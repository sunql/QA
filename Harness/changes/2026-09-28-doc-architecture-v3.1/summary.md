## 2. 设计评审

### 2.1 整体策略

| 决策点 | 选择 | 理由 |
|---|---|---|
| **合并策略** | v2 为主干 + 吸收 v1 框架 | v2 比 v1 完善 1.5×（12 元对象 vs 7 项 + 双编译器 + 8 产品中心） |
| **v3.1 校准对象** | v3（而非回到 v1/v2） | v3 已合并并标注现状，v3.1 是 v3 的修订而非重写 |
| **理想化处理** | 不删除能力，标注为 📦 v3.x 延后 + 显式激活条件 | 避免文档"假装能做"也避免"砍掉就不做了" |
| **文档分层** | 顶层蓝图（v3.1） / 对照基准（v3） / 历史稿（raw/v1,v2） | 三层让读者按需深入 |
| **是否动代码** | **不动** | 用户明确说"写一份"，不是"实现一份"；降级是认知校准而非功能降级 |

### 2.2 候选方案对比

#### 方案 A：在 v3 内降级（直接编辑 v3）

| 维度 | 评估 |
|---|---|
| 优点 | 文档数量少；只维护一个版本 |
| 缺点 | 失去"原始理想化版本"对照；后续若讨论"v3 当时为什么这样写"无 SSOT；变更可追溯性差 |
| 否决理由 | v3 已发布（含 ai-roadmap.md 引用），修改 v3 等于"抹掉历史决策记录" |

#### 方案 B：写独立 v3.1（选定）

| 维度 | 评估 |
|---|---|
| 优点 | v3 保留为对照基准，可看"v3 → v3.1 演化轨迹"；v3.1 是独立 SSOT |
| 缺点 | 文档多 1 份；维护成本微增 |
| **选定理由** | 架构修订属重大变更，必须保留原版做对照；多 1 份文档换完整决策可追溯，划算 |

#### 方案 C：写 v3.1 但彻底重写（不基于 v3）

| 维度 | 评估 |
|---|---|
| 优点 | 自由度高 |
| 缺点 | v3 中 50%+ 内容（现状对接 §22、12 元对象表、SQL Guard 章节等）仍有效，重写是浪费 |
| **否决理由** | 保留 v3 的可复用内容，只重写校准相关章节 |

### 2.3 降级决策：10 处校准一览

| # | 维度 | v3 | v3.1 | 触发校准的核心证据 |
|---|---|---|---|---|
| 1 | Agent 数量 | 9 个 | **3-4 个** | 9 次串行 LLM 调用 → 单任务 5-15 元、月度 6-18 万/100 用户，ROI 不可行 |
| 2 | LLM 调用/任务 | 9-30 | **2-5** | 同上 |
| 3 | DSL 数量 | 3 套 | **1 套** | 每套 DSL = 小型语言工程，3 套 = 6-9 个月 |
| 4 | Confidence | 4 维连乘 | **离散 4 级 + 触发条件** | 乘法模型假精确；冷启动无法工作；"历史准确率"无样本归零 |
| 5 | Authority | 完整模型 | **字段 + 治理流程建议** | Authority 是治理流程产物，不是技术能"建"出来的；没有治理委员会，模型形同虚设 |
| 6 | Evidence 类型 | 8 种 | **3 种 MVP** | 每种类型 1-2 周工程，8 种 = 2-3 个月 |
| 7 | Knowledge Compiler 产物 | 8 种 | **3 种 + 6 条运维约束** | v3 未定义更新/缓存/版本/回滚策略 = 不可用 |
| 8 | Planner 步数 | 10+ | **≤ 5 步** | 多步 LLM 调用是 token 黑洞 |
| 9 | Phase 3 自动报告 | 20-50 查询 + 自动结论 | **≤ 10 + 强制人审** | "自动钻取"无实现路径；"假设验证"是 LLM 幻觉重灾区 |
| 10 | Phase 1 目标 | "80% 准确率" | **Top 20 场景 ≥ 90%** | 拍脑袋目标不可承诺；"常见查询"无统一定义 |
| 11 | 三层 Memory | 严格分层 | **Phase A/B/C 渐进** | 完整实现需新 state store；Chat Context 当前已覆盖 80% |
| 12 | 8 产品中心 | 全部用户可见 | **区分用户页面 vs 内部模块** | 架构师视角 ≠ 用户视角 |
| 13 | Semantic Graph 三图合一 | 抽象 | **明确 P0 前置：统一 ID 体系** | 没说 ID 体系 = 没真做 |
| 14 | §22 现状对接 | 仅映射 | **映射 + 工时估算 + 优先级** | 让 roadmap 可排期 |

> 表中前 10 项是**功能性降级**，11-13 是**实现路径校准**，14 是**可执行性增强**。
