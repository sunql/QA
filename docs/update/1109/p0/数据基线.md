## 3. Neo4j

### 3.1 本体图

| 标签 | 数量 | 对照 PG |
|---|---|---|

关系：`HAS_PROPERTY` 6,854、`JOIN` 127。

### 3.2 业务实例图（**已回填，非空**）

| 标签 | 数量 |
|---|---|
| `BusinessEntity:ItemMaster` | **306,939** |
| `BusinessEntity:PurchaseOrder` | **200,562** |
| `BusinessEntity:Supplier` | 1,191 |

关系：`CONTAINS` **905,499**、`SUPPLIES` **343,678**、`PLACES` **200,562**、`REFERENCES` 3、`RELATED_TO` 3、`GENERATES` 2、`DERIVED_FROM` 2。

**结论**：
1. 业务图已全量回填，总量约 **145 万条关系**；
2. P3b 的「按发布重建/打标」必须**分批 + 限时**（建议按 label 分批，记录每批耗时），不能一次长事务；首次全量重建预计是分钟级到十分钟级，必须安排窗口；
3. 本体图与 PG 有 2–12 条差异（墓碑/指标收录口径），P1 编译器以 **PG 为准**，图谱一致性校验需允许「墓碑已删」的白名单。

## 4. Milvus（2.4.6，实测 5 个集合）

| 集合 | 行数 | 关键字段 | `enable_dynamic_field` |
|---|---|---|---|
| `ontology_class_embeddings` | 98 | ontology_id/type/name/alias/description/embedding(1024)/external_id | **false** |
| `ontology_property_embeddings` | 6,887 | 同上 | **false** |
| `ontology_metric_embeddings` | 5 | 同上 | **false** |
| `query_embeddings` | 86 | session_id/question/sql/datasource_id/embedding | **false** |
| `wiki_page_embeddings` | 4 | page_id/chunk_id/chunk_text/title/status/embedding | **false** |

**判读**：
1. 实际是**按类型拆分的 3 个本体集合**（代码中 `milvus_dual_write.py` 的双写/拆分形态），不是旧文档里的单一 `ontology_embeddings`；
2. `document_embeddings` 未创建——代码里是懒创建，且文档数为 0，符合现状，不是缺失；
3. **所有集合 `enable_dynamic_field=false`，且没有任何域/实体/有效期字段** ⇒ P3a 无法靠动态字段加过滤条件；
4. 体量很小（合计 < 7,100 行），**新建集合 + 全量回填的成本极低**，这是 P3a 的首选方案（比在 2.4.6 上试探 `add_collection_field` 更稳）。
5. 维度 1024，索引 HNSW，维持现状。

## 5. 数据源（外部系统）

| id | 名称 | 类型 | 地址 | 库/用户 | 默认 |

**判读**：

- `SEED_DS_KPI_CATALOG` 是种子/演示数据源，不参与生产业务判断；
- 结论：P5 的外部适配只能先做模拟器，真实写接口须业务方提供后再排期。

## 6. 对计划的修订

| 阶段 | 原假设 | 实测修正 |
|---|---|---|
| P1 | 当前本体规模未知 | 99 类 / 6,888 属性 / 191 JOIN ⇒ golden Manifest 与测试成本很低 |
| P2 | 影子比对可能较重 | 体量小，可全量逐条比对，不抽样 |
| P3a | 可能有动态字段 | **无动态字段、5 个拆分集合** ⇒ 采用「新建带过滤字段的集合 + 全量回填」（<7,100 行，分钟级） |
| P3b | 图谱回填状态未知 | 业务图已有 145 万关系 ⇒ 重建分批 + 窗口 + 每批耗时记录；本体图与 PG 的墓碑差异要白名单 |
| P4 | 文档 RAG | 文档为 0、`document_embeddings` 未创建 ⇒ 知识 Facade 首期以图谱/指标/SQL 为主，文档路按需启用 |
| P5 | 外部系统 | 写侧没有任何接口证据（THBI 是读库）⇒ 必须先确认 ERP/SRM 写接口，否则一律先用模拟器 |
| 全阶段 | 生产 drift 有告警 | 告警来自 8 天前的旧容器，非 DB 问题；下次发版后复核 |
