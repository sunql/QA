# 测试规范

## 强制要求（CRITICAL，不可违反）

后端测试**全面禁止** sqlite 内存库（含 `sqlite+aiosqlite:///:memory:` 和任何 sqlite 变体），不允许作为任何测试的 DB 后端。

必须同时满足：
1. **真实 PostgreSQL**：测试连独立测试库（如 `qa_metadata_test`），表结构由 Alembic 迁移（`upgrade head`）产生，使用真实的表/列/索引/唯一约束/默认值。
2. **完整 API 链路**：经 FastAPI 测试客户端（`AsyncClient` + `ASGITransport`）从 HTTP 入口发起，走路由 -> 中间件（参数校验/鉴权/限流）-> service -> repository -> 真实 PG。
3. **真实数据库对象**：准备数据与断言都落在真实 PG 行上（ORM 或 SQL），禁止用 mock 实体替代被测数据层。
4. **禁止降级**：未配置 `TEST_DATABASE_URL` 时 fail-fast，不允许静默降级到 sqlite。任何测试文件内的 `sqlite` 字符串都是 bug，review 时必须拦截。

## 为什么（本仓库实踩的坑）

sqlite 与 PG 行为有实质差异，sqlite 通过不代表 PG 正确：

- **迁移失真**：`Base.metadata.create_all` 不走 Alembic，模型变更（加列/加约束/建索引）在 sqlite 上照常通过，上线后 PG 迁移失败或行为漂移。
- **方言差异**：JSON/数组等类型、`autoflush` 语义、唯一约束、并发锁在 sqlite 上不成立。实际事故：生产 `database.py` 设 `autoflush=False`，未 flush 直接按旧值批量删除，真实 PG 上误删 43 条属性，sqlite 测试完全发现不了。
- **绕过 API 契约**：直接调用 service 跳过路由层校验（ValidationError -> 422）、鉴权、限流、错误封套，测试绿但真实请求 4xx/5xx。
- **假对象失真**：mock 实体无法覆盖 PG 约束/触发器/默认值，形成"测试绿、线上坏"。

## 例外（仅限无 IO 的纯逻辑）

- 纯函数/纯算法（不触 DB/网络）：可直接单测，无需真实库。
- 外部依赖（LLM、Milvus、Neo4j、外部 HTTP）：允许 test double（mock/stub），但 **PostgreSQL 数据层必须真实**，不得用假库代替。

## 落地方式

- 测试库约定：独立测试库（默认 `qa_metadata_test`，可用 `TEST_DATABASE_URL` 指定）；凭据走环境变量注入，禁止硬编码（见 [权限与安全规范](./权限与安全规范.md)）。
- 运行要求：真实 PG 测试需提供 `TEST_DATABASE_URL`（或 `DATABASE_URL` 指向真实 PostgreSQL），未配置时 **fail-fast**，不允许静默降级 sqlite。示例：
  `TEST_DATABASE_URL=postgresql+asyncpg://<user>:<pass>@localhost:5432/qa_metadata_test uv run pytest app/tests/integration/`
- 统一接管：`app/tests/integration/conftest.py` 覆盖根 conftest 的 sqlite `client`/`dbSession`，integration 目录内所有测试自动走真实 PG + 完整 API 链路，无需逐文件重复（模块级同名 fixture 可继续局部覆盖）。支撑见 `app/tests/_pg_support.py`。
- 迁移：测试 fixture 先对测试库执行 Alembic `upgrade head`（与生产同路径，见 `app/tests/_pg_support.py`），禁止 `create_all`。
- 隔离：每个测试 TRUNCATE 清库（RESTART IDENTITY CASCADE），互不依赖执行顺序；每个测试新建引擎并在结束 dispose（pytest-asyncio 每测试独立事件循环，跨测试共享 asyncpg 连接池会报 loop 错配）。
- 断言：以 API 响应（状态码、封套、错误映射）为准，并校验数据真实落库；LLM / Milvus / Neo4j / 外部 HTTP 允许注入桩替换该依赖，其余链路全真实。
- 覆盖门禁：`pytest --cov=app --cov-fail-under=80`（见 `unit-test-ci` 技能）。
