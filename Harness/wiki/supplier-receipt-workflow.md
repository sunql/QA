# 供应商收货流程（零库存 vs 非零库存）

> 本文件为 qa-system 的业务规则补充，配合 [[business-domain]] 的「供应商域」一节共同使用。
> 记录于 2026-08-20，由用户提供业务口径后整理。

## 1. 背景

Sage X3 中供应商主档 `BPSUPPLIER.YPTHFLGM_0`（收货模式）控制整条 SRM → WMS
收料链路的形态，「订单完成率」必须严格按此字段拆分为两组口径（零库存 /
非零库存）分别计算，混算会让两组数据互相干扰，得出既不合理也不可信的总数。

## 2. 字段与取值

| 字段 | 类型 | 取值 | 语义 |
|------|------|------|------|
| `BPSUPPLIER.YPTHFLGM_0` | INT | `1` | 非零库存供应商：通用物料 / 长周期供货，先建到货单、再走质检、最后建收货单入库 |
| `BPSUPPLIER.YPTHFLGM_0` | INT | `2` | 零库存供应商：JIT / 直送车间 / VMI 等无独立仓库库存，采购订单直接驱动收货单，生产领用时由系统自动入库出库 |

业务别名（写入本体 `business_aliases`）：「零库存标志」、「到货模式」、「收货管理方式」。

## 3. 非零库存供应商流程（YPTHFLGM_0 = 1）

```
PORDER / PORDERQ                  # 采购订单及明细
    │
    ▼ 创建到货单（草稿，供应商发货时填写）
YPRECEIPT / YPRECEIPTD            [草稿 draft]
    │   货物到达工厂 → 状态改为「到货」
    ▼
YPRECEIPT / YPRECEIPTD            [到货 arrived]
    │   推质检 QC
    ▼
YPRECEIPT / YPRECEIPTD            [质检中]
    │   质检完毕 → 输入合格数量 → 状态变为「质检完毕」
    ▼
YPRECEIPT / YPRECEIPTD            [质检完毕 qualified]
    │   以合格数量创建收货单
    ▼
PRECEIPT / PRECEIPTD              [收货 receipt]
    │   合格品入库，库存 +1
    ▼
    不合格品另走退货流程（不影响本路径）
```

关键约束：

- **收货数量 = 合格数量**：收货单 `PRECEIPTD.QTYUOM_0` 必须等于到货单录入的「合格数量」。
- **到货单与收货单一对多**：单张到货单可拆分为多张收货单（按批次 / 库位）。
- **状态机不可跳跃**：草稿 → 到货 → 质检完毕 → 收货完成；不允许从草稿直接跳到收货。

## 4. 零库存供应商流程（YPTHFLGM_0 = 2）

```
PORDER / PORDERQ                  # 采购订单及明细
    │   无独立到货 / 质检环节
    ▼ 订单直接驱动收货单
PRECEIPT / PRECEIPTD              [收货 receipt]
    │
    ▼ 发到生产车间
车间线边仓系统
    │   入库（虚拟入库到线边仓）→ 出库（领料至工单）
    ▼
    两步由生产领用系统自动执行，零人工干预
    ▼
车间消耗
```

关键约束：

- **没有 `YPRECEIPT`**：零库存供应商的采购链路不经过到货单实体，
  任何「到货及时率」类指标对此类供应商恒为空，必须剔除后再计算全厂均值。
- **入库 / 出库成对自动产生**：每次领料都伴随一次虚拟入库 + 一次实际出库，
  用于库存账实时一致（账面库存始终为 0，但交易流水完整）。
- **订单完成率**：以 `PRECEIPT` 是否创建为准，而非 `YPRECEIPT`。

## 5. 订单完成率口径

定义：按时收（入）库数量 / 订单数量。

- **零库存组**（`YPTHFLGM_0 = 2`）：分母用 `PORDERQ.QTYPUU_0`，分子用关联 `PRECEIPTD` 中由该订单生成且未退货的累计收货数量。
- **非零库存组**（`YPTHFLGM_0 = 1`）：分母同上，分子须再叠加一道「合格比例」——
  即 `sum(PRECEIPTD.QTYUOM_0) × 平均合格比例`，否则会把「质检不合格但仍挂单」的
  订单误算为已完成。

> ⚠️ 全厂总订单完成率不应直接对两组求和 / 加权平均，而应分别上报两组数值
> （业务方接受「零库存组」与「非零库存组」独立呈现）。

## 6. NL2SQL 引擎注意事项

- `BPSUPPLIER.YPTHFLGM_0` 已写入本体（PG id=1036、Neo4j 节点 pid=1036、Milvus 向量）。
- 用户问「订单完成率」时，`ontology_service` 的属性级文本匹配可命中该字段；NL2SQL
  Prompt 模板（`skills/nl2sql-prompt`）应自动注入 `Y/N 型分组要求` 提示，避免把
  `YPTHFLGM_0 = 2` 的订单也链到 `YPRECEIPT`（数据库中无对应行）。
- 涉及质检环节的提问（「合格数量 / 不合格数量 / 退货数量」）只对
  `YPTHFLGM_0 = 1` 有效，向「`YPTHFLGM_0 = 2`」用户回答时需显式说明「无该环节」。
