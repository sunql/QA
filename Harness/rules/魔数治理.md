# 魔数治理

> **目的**：把 pipeline 行为可调阈值集中到 `system_config` 表，admin 可在线改、新问句即生效；
> 同时把纯实现细节的常量保留在源码里，避免无意义的 DB 往返。
>
> **SSOT 出处**：`Harness/wiki/chat-service-assessment.md` §2.4 LOW 行 +
> `Harness/changes/chore-magic-number-governance/summary.md`
> **关联**：`Harness/rules/工程结构.md`、`Harness/rules/测试规范.md`、
> `Harness/rules/变更记录强制规范.md`

---

## 何时治理、何时不治理

### 三档决策

| 档 | 判据 | 处理 |
|---|---|---|
| **治理** | 编译期阈值，影响 pipeline 行为，admin 需可调（topK/char-limit/similarity/weight） | 迁 `system_config`，运行时现读 |
| **不改** | 纯实现细节（regex 模式、SQL 关键字集合、日志 reason 字符串） | 保留源码注释 |
| **判别不清** | 编译期数字但语义是「防御性兜底」而非「可调策略」 | 默认不改；如有 admin 反馈再迁 |

### 判定清单（新增魔数前必须答）

1. **运营/调试期是否需要调整？**（如召回 topK 太小想放宽 → 治理；fence 正则模式永远不会调 → 不改）
2. **调整频率？**（每次问都可能调 → 治理；调一次写死 → 不改）
3. **是否影响计费/性能边界？**（影响 prompt token 上限、查询行数限制 → 治理）
4. **是否每次请求都重新读取？**（与已有 system_config 读取模式一致 → 治理）

### 反例（绝对**不**治理）

```python
_SQL_FENCE_RE = re.compile(r"```(?:sql)?\s*(.*?)```")   # 解析语法，admin 改了反而挂
_JSON_FENCE_RE = re.compile(...)                          # 同上
_FORMULA_SQL_KEYWORDS: frozenset[str] = frozenset({...})  # SQL 关键字集合，运维无意义
REASON_PLAN_REPLY_EMPTY = "PLAN_REPLY_EMPTY"             # 日志契约，改名等于改监控
```

## 治理实施规范

### 1. 命名约定

- Python 常量 `_XXX_DEFAULT`（私有模块前缀）；system_config key `XXX`（去前缀，全大写下划线）
- 例：`_CLASS_FILTER_MAX_CLASSES_DEFAULT = 30` → key `CLASS_FILTER_MAX_CLASSES`

### 2. 读取模式（必须复用 SSOT）

**位置**：在调用方模块内部就近放置读取函数，**禁止**集中到一个统一 config 服务
（chat_service 已经按这个习惯处理：`_getClassFilterMaxClasses`/`_getAdsRecallWeight`/`_isL4AgentLoopEnabled`）。

```python
async def _getXxx(self, session: AsyncSession) -> int:
    """读 system_config.XXX；缺席/格式错/非正返 _DEFAULT。

    口径与 ``_getClassFilterMaxClasses`` 同：读失败不阻断主链路，返硬编码默认；
    admin 改值后立即对新问句生效（每次请求现读，无缓存）。
    非正值同样按非法处理：0/负数不是「截得更狠」而是闸门静默失效。
    """
    try:
        row = await session.execute(
            text("SELECT value FROM system_config WHERE key = 'XXX'")
        )
        raw = row.scalar_one_or_none()
        if raw is None or raw == "":
            return _XXX_DEFAULT
        value = int(raw)
        if value <= 0:
            logger.warning(
                "XXX 非正值 %r，返默认值 %d", raw, _XXX_DEFAULT,
            )
            return _XXX_DEFAULT
        return value
    except (TypeError, ValueError):
        logger.warning("XXX 值非法 %r，返默认值 %d", raw, _XXX_DEFAULT)
        return _XXX_DEFAULT
    except Exception:
        logger.warning("读取 XXX 失败，返默认值 %d", _XXX_DEFAULT, exc_info=True)
        return _XXX_DEFAULT
```

**关键不变量**（保证可恢复性）：

- **不缓存**：每次请求现读，admin 改值无需重启
- **失败不阻断**：DB 抖/格式错/非正 → 返 `_DEFAULT` + warning 日志
- **非正抛错**：与 `CLASS_FILTER_MAX_CLASSES` 同口径（闸门静默失效）
- **可读 SQL**：`text()` 直接写 key，不走 ORM（与既有实现保持一致）

### 3. 种子脚本（必须幂等）

**位置**：`backend/scripts/seed_system_config.py`

**模式**：`on_conflict_do_update`（不是 `do_nothing`），参考 memory `qa-system-seed-upsert-pattern`。

```python
async with session.begin():
    stmt = pg_insert(SystemConfig).values(
        key="XXX", value="30", description="…"
    ).on_conflict_do_update(
        index_elements=["key"], set_={"value": "30"},
    )
    await session.execute(stmt)
```

**运行方式**：`./scripts/run_local.sh python -m scripts.seed_system_config`

### 4. 测试要求

- **新增读取函数必须有 3 例**：
  1. key 缺席 → 返 `_DEFAULT`
  2. key 格式错 → 返 `_DEFAULT` + warning
  3. key 正常 → 返 DB 值
- **行为不变性**：用 51 字段快照 diff（参考 `chore-config-duplicate-fields` 思路）
  验证「默认值迁移后行为无变化」

## 反模式

| 反模式 | 后果 |
|---|---|
| 把阈值放进 `Settings` (Pydantic BaseSettings) | 改值需重启容器；违反「admin 即时生效」承诺 |
| 用 ORM `SystemConfig.getByKey(session, "XXX")` 缓存到内存 | 改值需重启；同样违背承诺 |
| 把多个 key 抽到统一 `config_service.getXXX` | 失去就近阅读性；调用点距定义千里 |
| 治理 `re.compile(...)` regex 模式 | admin 改了模式挂掉，反向压力 |
| 治理 `REASON_PLAN_REPLY_EMPTY = "..."` 日志字符串 | 改名等于改监控口径，不应让 admin 改 |
| 默认值改了但未走种子脚本 | dev/prod 配置漂移；与「运行期读 system_config」脱节 |
