# 项目编码规范

## 不可变性（CRITICAL）

- **始终创建新对象，禁止原地修改已有对象。**
- 领域逻辑、数据变换返回新副本。
- 例外：SQLAlchemy 会话托管的 ORM 实体为持久化需就地修改（显式 `setattr` + commit），但 service 返回前应保证对外不可变视图。
- Pydantic DTO 默认不可变（`frozen` 风格），不修改响应对象。

## 核心原则

- **KISS**：选最简单可行的方案，避免过度设计。
- **DRY**：重复逻辑抽公共函数/工具，避免复制粘贴漂移。
- **YAGNI**：不为想象中的需求提前抽象。

## 错误处理

- 每层显式处理错误，禁止静默吞异常。
- 服务层捕获底层异常并转换为 `app/domain/exceptions.py` 中的领域异常。
- UI 层给用户友好提示；服务端记录详细上下文（logger）。
- 输入边界校验：所有外部输入（API 请求、文件、外部响应）先校验再处理，fail fast。

## 命名约定

| 类型 | 规范 | 示例 |
|------|------|------|
| 函数/变量 | camelCase | `selectModel`、`sessionCost` |
| 布尔 | is/has/should/can 前缀 | `isActive`、`hasPermission` |
| 类型/组件 | PascalCase | `ModelRouterService`、`ChatPanel` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRIES`、`FALLBACK_ENCODING` |
| 自定义 hooks | use 前缀 | `useChat` |
| ORM 列 / Pydantic 字段 | snake_case | `model_name`、`session_id` |

## 代码异味

- 深嵌套：用早返回替代。
- 魔法数：用命名常量。
- 长函数：拆分单一职责的小函数。

## 国际化（i18n）

所有用户面向文案必须走 i18n 框架，不得硬编码。详见 `Harness/rules/国际化与多语言规范.md`。
