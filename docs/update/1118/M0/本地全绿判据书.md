## 0 · 这本册子是什么 / 不是什么

**是什么**：一份**可执行、可归档、可复现**的判据集合。它回答两个问题：
1. 「本地测试没问题」这句话，**由哪些可核对的证据支撑**？
2. 每个里程碑**到哪一步才算做完**？

**不是什么**：
- 不是「测试覆盖率越高越好」这类目标描述——判据必须是**二值可判**的；
- 不是对既有红基线的豁免清单——**既有红基线允许存在，但必须逐条同名同因**；
- 不是发版 runbook（runbook 在 M7 产出）。

> **为什么现在写**：当前 **6** 个 `ENABLE_*` 开关**从未在本地打开过**（且 backend / worker 两侧不对称，见判据 3）。在此之前，「功能都完成、等本地测没问题再统一部署」这句话**没有事实基础**——没有可核对的全绿判据，「测过了」就只是一句感觉。本册子就是把这个感觉换成证据。

## 1 · 总则

### 1.1 「绿」的三个必要条件

一条判据记为**绿**，当且仅当同时满足：

| # | 条件 | 反例（假绿） |
|---|---|---|
| G1 | **可复现**：任何人在同一 commit、同一环境下重跑，结论一致 | 只跑了一次，凭记忆记「上次是绿的」 |
| G2 | **有归档证据**：证据文件落在约定目录（§3），不是只在终端里 | 「我截图了」但没进仓 |
| G3 | **双向断言**：既要断言「该成的成了」，也要断言「该不成的不成」 | 只断言 HTTP 200 |

> **G3 的分量**：仓内已多次出现「只看状态码 = 假绿」——4xx 响应体同样是 JSON，`resp.json()` 会正常 resolve，于是「抛错」被当成「返回了数据」。**每个断言必须成对写。**

### 1.2 证据的三种形态（都可归档）

| 形态 | 位置 | 例子 |
|---|---|---|
| 命令输出 | `docs/update/1118/M{n}/evidence/*.log` | `alembic check` 输出、pytest 摘要 |
| 脚本断言 | `scripts/acceptance/*.sh`（**必须同时断言 HTTP 与落库状态**） | `scripts/acceptance/p5_smoke.sh` |
| 报告 | `docs/update/1118/M{n}/report/*.md` | 覆盖率报告、性能报告、对差报告 |

> **`scripts/acceptance/p5_smoke.sh` 是仓内已有的正面样板**：它在文件头注释里写明了「每一件都同时断言 HTTP 结果 **和** 落库状态，避免『只看状态码』的假绿」，并且覆盖了全链路 / 幂等 / 取消 / 四眼四类断言。**新切片沿用这个写法。**

### 1.3 纪律（继承仓内既有规范，不可放宽）

| 纪律 | 说明 |
|---|---|
| **真实 DB** | 后端测试必须用**真实 PostgreSQL + 完整 API 链路 + 真实 DB 对象**；**禁 sqlite 内存库、禁直接调 service**。本地固定用 `5434 / qa_metadata_test`（CI 同款）；`5433` 是旧端口，**不要用** |
| **禁裸 pytest** | 裸 `pytest` 会删**线上 Milvus/Neo4j** 数据。Milvus / Neo4j 相关**只跑定向测试** |
| **全量 unit 不可作门禁** | 后端全量 unit 单文件可能 27 分钟且含既有红基线；**跑定向**（`test_refine_shortcuts.py` 是既有红基点） |
| **先 `ps` 再信「回归」** | 跑回归前先 `ps aux \| grep pytest` 抓**僵尸 pytest**，否则僵尸进程会锁库/串扰，让「回归」结论失真 |
| **覆盖率只在绿跑时产出** | 套件红时覆盖率数字不可用（分母/采集不完整）——**先修绿，再看覆盖率** |
| **入库只走 `jsonSafe`** | 落库的 JSON 一律用 `app/utils/json_safe.py` 的 `jsonSafe`（Decimal 会被 `json.dumps` 炸） |

### 判据 1 · 迁移（Migration）

**定义**：数据库结构在「代码声明 / 迁移链 / 真实库」三者间一致，且升降级可往返。

| 量化口径 | 判定 |
|---|---|
| 本地库 `alembic_version` == `main` 的 head | 必须相等 |
| `alembic check` 绿 | 无新迁移需要生成 |
| `upgrade head` → `downgrade -1` → `upgrade head` 往返 | 全程无错 |
| **ORM metadata / migration / 真实库三方一致** | `backend/scripts/check_schema_drift.py` 绿 |

**标准命令**

> ⚠️ **`alembic check` 必须在**干净 probe 库**上跑**（见陷阱 3）：

```bash
cd backend
uv sync --frozen --extra dev

# 建一次性 probe 库（不碰共享测试库）
docker exec qa-pg-a1 psql -U qa_user -d postgres \
  -c "DROP DATABASE IF EXISTS qa_metadata_test_probe" \
  -c "CREATE DATABASE qa_metadata_test_probe"
export DATABASE_URL='postgresql+asyncpg://qa_user:<pwd>@localhost:5434/qa_metadata_test_probe'

uv run alembic upgrade head
uv run alembic current                     # 期望 0153 (head)
uv run alembic check                        # 期望 "No new upgrade operations detected."
uv run alembic downgrade -1 && uv run alembic upgrade head   # 往返
uv run python scripts/check_schema_drift.py --database-url "$DATABASE_URL"  # 期望无 drift
```

**证据**：`docs/update/1118/M{n}/evidence/alembic-*.log`

**⚠️ 本判据的三个已知陷阱**

1. **drift 全绿 ≠ `alembic check` 绿**。`alembic` 1.19.1 **不比谓词**（CHECK 表达式、索引表达式），只比名。drift 检查报「DB 多余」时，根因常常是 **ORM 漏声明**（该补 ORM，不是 DROP DB）。
2. **CHECK 约束只在 ORM 侧钉住才算数**。只补约束名 = 假绿；表达式比对要靠 **PG 渲染**（`pg_get_constraintdef`）+ 硬断言。
3. **共享测试库会被测试期创建的 sandbox 表污染** ⇒ `alembic check` 报 `remove_table` ⇒ **判据 1 假红**（例：测试期建的 `po_lines_sandbox` 表，ORM metadata 里没有它）。⇒ **判据 1 只在干净 probe 库上判定**；共享测试库的 schema 判定交给 `check_schema_drift.py`（它有「DB 多余」的白名单机制）。

**责任切片**：新增/修改迁移的每个切片。

### 判据 2 · 回归（Regression）

**定义**：本次改动**没有引入新的失败**。

| 量化口径 | 判定 |
|---|---|
| 与**基线 HEAD** 做**失败集合对差** | **净新增失败 = 0**（不要求全绿） |
| 既有失败必须**同名同因** | 逐条核对，不能"名字差不多就算" |
| 对差结果 | exit 0；exit 5 = 净丢失（须证伪）；exit 6 = 需要 owner 仲裁 |

**标准命令**

```bash
# 单元：按分片跑（禁全量；全量 27 分钟且含既有红基线）
cd backend
uv run python -m app.utils.ci_shard --root app/tests/unit --shards 4 --shard 0 --nul > /tmp/s0
mapfile -d '' -t t < /tmp/s0 && uv run pytest "${t[@]}" -q -p no:randomly
# 其余 shard 同理；分片清单为空时**必须硬失败**（空数组 = pytest 回落 testpaths = 收全树 = 假绿）

# 集成：定向（禁裸 pytest）
uv run pytest app/tests/integration/<本切片相关文件> -q -p no:randomly
```

**失败集合对差**（CI 侧已实现，本地可复用同一工具）：

```bash
uv run python -m app.utils.ci_failure_set \
  --repo <org/repo> --base-run <基线 run id> --pr-run <本次 run id>
```

**证据**：`docs/update/1118/M{n}/evidence/regression-diff.md`（含基线 run id、两个失败集合、净新增列表）

**⚠️ 本判据的四个已知假绿**

| 陷阱 | 机制 | 反制 |
|---|---|---|
| **基线过期** | 基线那次 CI 被取消 ⇒ 基线退到更早的 main ⇒ 对差结论无意义（表现为 exit 5） | 推新 commit 重新派发 CI，**不要直接 bypass** |
| **`cancelled` / `UNUSABLE_JOBS`** | 被取消的 job **失败集合是空的** ⇒ 对差得出「净新增 0」的假结论 | 整轮复跑；空失败集合的 job **不参与对差** |
| **分片归属轮转** | 用「排序下标 mod N」分片时，增删一个文件会让其后所有文件轮转一位 ⇒ 大量文件「换片」⇒ 假 net-new | 只用 `ci_shard.py`（路径稳定哈希） |
| **僵尸 pytest** | 上一次跑测的进程没退，锁库/串扰 | 回归前先 `ps aux \| grep pytest` |

**责任切片**：全部切片（这条是**闸门级**，每个切片都要过）。

### 判据 3 · 开关（Switch）

**定义**：**6** 个灰开关**全部被打开并跑通**，且每个都有「开 / 关两态行为」用例。

**当前 6 个开关**（默认全关）：

| 开关 | 控制什么 |
|---|---|
| `ENABLE_SEMANTIC_RELEASE` | 语义发布面 |
| `ENABLE_SEMANTIC_REGISTRY_NL2SQL` | Registry → NL2SQL 链路 |
| `ENABLE_SEMANTIC_REGISTRY_RAG` | Registry → RAG 链路 |
| `ENABLE_KNOWLEDGE_FACADE` | 知识四路 Facade |
| `ENABLE_WORKFLOW` | 工作流域 |
| **`ENABLE_AGENT_ORCHESTRATION`** | **通用多工具 Agent 编排（M3 用它）** |

> ⚠️ **实测（2026-11-18）**：这是**两侧不对称**的开关。
> `qa-backend` 容器**一个 `ENABLE_*` env 都没有** ⇒ 6 个全默认关；
> `qa-workflow-worker` 容器**已有 `ENABLE_WORKFLOW=true`** ⇒ **"worker 开" ≠ "backend 开"**。
> ⇒ 本判据必须**两个容器分别验**，不能只看 worker。
> ⇒ 第 6 个 `ENABLE_AGENT_ORCHESTRATION` 正是 M3（只读采购 Agent）要用的，**漏验它 = M3 假装通过**。

| 量化口径 | 判定 |
|---|---|
| **6** 个开关都有**开态**用例 | 每个 ≥1 条 |
| **6** 个开关都有**关态**用例（关掉后行为明确回退，**不是 500**） | 每个 ≥1 条 |
| **至少一个能力在开态下被真实业务问题跑通** | ≥1 条端到端 |
| **backend 与 workflow-worker 两侧的开关态一致** | 各开关在两侧的值必须一致 |

**标准动作**

```bash
# ① 开关是 **backend/worker 容器的 env**（compose 的 env_file: docker/.env），不是脚本入参。
#    本地 .env：6 个 ENABLE_*=true + AUTH_MODE=real + ALLOW_STUB_WHEN_REAL=false
#    ⇒ 改 .env 后必须重建容器，再核 env：
docker exec qa-backend env | grep -E '^ENABLE_' | sort

# ② 两态用例（单元 / 行为 / HTTP 404 / 误配告警）
./scripts/run_local_tests.sh \
  app/tests/unit/test_feature_flags_two_state.py \
  app/tests/unit/test_semantic_schema_gate.py \
  app/tests/unit/test_semantic_registry_rag_gate.py \
  app/tests/unit/test_workflow_list_api.py \
  app/tests/unit/test_workflow_definition_admin_api.py \
  app/tests/integration/test_agent_orchestration_config_api.py \
  app/tests/unit/test_semantic_release_config.py \
  app/tests/unit/test_knowledge_facade_auth_config.py \
  app/tests/unit/test_semantic_registry_rag_config.py \
  app/tests/unit/test_production_auth_guard.py

# ③ 开态端到端
ADMIN_PASSWORD=… SUBMITTER_USER=wf_submitter SUBMITTER_PASSWORD=… \
  ./scripts/acceptance/p5_smoke.sh
```

> A2 实测（2026-11-18）：两态批 **122 passed**，冒烟 **30/30**，两侧 env 一致
> ⇒ 完整矩阵与用例 ID 见 [evidence/switch-matrix.md](./evidence/switch-matrix.md)。

**证据**：`docs/update/1118/M{n}/evidence/switch-matrix.md`（6×2 用例表 + **两侧 env 实际值**列：开关 / backend 值 / worker 值 / 开态断言 / 关态断言 / 用例 ID）

**⚠️ 关态用例不能只是「关掉不报错」**：必须断言**行为回退到预期形态**（例如 Facade 关掉时该端点返回 404 而非 500；Registry 关掉时 NL2SQL 回落到旧链路）。

**责任切片**：引入/改动开关的切片，以及 **M0 本身**（本判据是 M0 的核心交付物之一）。

### 判据 4 · 端到端（End-to-End）

**定义**：真实业务问题在**完整链路**上跑通，产出可归档证据。

| 量化口径 | 判定 |
|---|---|
| 附录 B **Q01–Q07** 全部有可归档证据 | 逐问一份 |
| pilot **P-01…P-14** 全部有可归档证据 | 逐条一份 |
| **Q06/Q07 必须在 M5/M6 之后才计入** | 未到里程碑的不计入本里程碑判据 |
| 每问的答案**结构化 + 带 evidence** | Q01–Q05：≥4 条 evidence，每条带 `evidenceId` + `security` + 可回溯 ref |
| **零条 LLM 估算数值** | 答案里的数字必须来自查询结果，不是模型估的 |

**每问的证据模板**（`docs/update/1118/M{n}/q/<编号>.md`）

```markdown
# Q01 哪些供应商可以供应指定物料？
- 问题原文：
- 环境：commit=<sha> / 开关全开 / 数据源=<...>
- 期望答案（业务方给的）：见 问卷D D2.2
- 实际答案：
- Evidence 列表：evidenceId / 来源（表或文档 ref）/ security / 时间戳
- 数值来源：<SQL 或工具返回的原始片段>   ← 必须能贴出原始片段
- 判定：✅ 一致 / ❌ 不一致（原因）
```

**证据**：`docs/update/1118/M{n}/q/*.md` + `docs/update/1118/M{n}/report/e2e-summary.md`

**⚠️ 三个必须双向断言的点**

1. **正确的问题** → 断言答案**对**；
2. **越界的问题**（如问一个未接入的数据域）→ 断言系统**明确说"未接入"**，**不是编一个数**；
3. **权限外的问题** → 断言**被过滤**（不是拒答，也不是照答）。

**责任切片**：M2（Q01–Q05）、M5（Q06）、M6（Q07）、M7（全部 + pilot）。

### 判据 5 · 覆盖（Coverage）

| 量化口径 | 判定 |
|---|---|
| **新增 / 改动代码行**覆盖率 ≥ **80%** | CLAUDE.md 硬约束 |
| 前端：`npm run test:coverage` 的**覆盖率 gate** 通过 | 基线会漂移，须以 **HEAD 实测**为准 |
| 后端：改动模块的 coverage 报告 | — |

**标准命令**

```bash
# 前端
cd frontend && npm exec -- tsc -b && npm run test:coverage

# 后端（定向到本切片）
cd backend && uv run pytest <本切片测试文件> -q -p no:randomly --cov=<本模块> --cov-report=term-missing
```

**证据**：`docs/update/1118/M{n}/evidence/coverage-*.txt` + `report/coverage-summary.md`

**⚠️ 三个陷阱**

1. **覆盖率 gate 只在绿跑时产出**——套件红时数字不可用，**先修绿再看数**；
2. **前端覆盖率基线会漂移**——任何"上次是 83%"的说法都必须以 **HEAD 实测**复核后再写进报告；
3. **覆盖率达标 ≠ 行为正确**。覆盖率高只说明代码被执行过，**不说明断言有效**——所以判据 4 的双向断言不可省。

**责任切片**：全部切片。

### 判据 6 · 性能（Performance）

| 量化口径 | 目标 |
|---|---|
| 实体查询 P95 | **< 1s** |
| 图谱查询 P95 | **< 2s** |
| RAG 召回 P95 | **< 3s** |
| 数据 | **必须用真实数据，不造数** |
| 容量核对 | 记录单次查询的行数、返回体积 |

**标准动作**

```bash
# 连续 ≥20 次真实查询，统计 P95；结果落 evidence/performance-<能力>.md
```

**证据**：`docs/update/1118/M{n}/report/performance.md`（含样本量、原始时延列表、P95、真实数据规模说明）

**⚠️ 造数不算数**：压测必须打在**真实数据**上。造出来的量级不能代表生产的响应特征。

**责任切片**：M2（知识四路）、M3（Agent 工具）、M7（整体）。

---

### 判据 7 · 回滚（Rollback）

**定义**：**每个切片**的回滚动作**当场演练过一次**，整体发版回滚路径**演练一次**。

| 量化口径 | 判定 |
|---|---|
| 每个切片有**回滚动作的书面描述** | 在切片的变更记录里 |
| 每个切片的回滚**演练过** | 有演练记录（不是"应该能退"） |
| 整体发版回滚路径演练 | 一次完整演练 |
| 回滚后**数据状态正确** | 回滚不是只回代码，**数据也要能退**（迁移的 downgrade 已由判据 1 覆盖） |
| 回滚**不需要**改 `SECRET_KEY` | Fernet 主密钥不可变；旧 token 会全部失效 |

**⚠️ 三个已知雷**

1. **`SECRET_KEY` 必须复用**：改它 ⇒ 所有旧 token 失效 ⇒ 回滚变成"重登一切"。回滚方案里**禁止**包含改密钥。
2. **compose 是 v1**（`docker-compose 1.29.2`，**无 v2 插件**）：回滚脚本里**禁用** `docker compose` 子命令、**禁用** `--remove-orphans`、**禁用** `!override` / `profiles`；生产入口是**单文件** `/opt/qa-system/docker/docker-compose.centos7.yml`。
3. **v1 合并列表是"相加"的**：想"去掉"某项必须**重写整个文件**，不能靠"注释掉一行"（会静默漂移）。

**证据**：`docs/update/1118/M{n}/evidence/rollback-<切片>.md`（含：动作 / 执行记录 / 回滚后状态断言）

**责任切片**：每个切片 + M7（整体）。

## 3 · 验收包目录约定

每个里程碑**自带验收包**（落地计划准则 E：自带验收包 + 标准库可复现）。

```
docs/update/1118/M{n}/
├── README.md                  # 本里程碑范围、判据勾选、结论
├── evidence/                  # 原始输出（命令日志、脚本断言）
│   ├── alembic-*.log
│   ├── regression-diff.md
│   ├── switch-matrix.md
│   ├── coverage-*.txt
│   └── rollback-*.md
├── report/
│   ├── e2e-summary.md         # Q01–Q07 / P-01…P-14 汇总
│   ├── performance.md
│   └── coverage-summary.md
└── q/                         # 逐问证据（判据 4）
    ├── Q01.md … Q07.md
    └── P-01.md … P-14.md
```

**规则**

1. **证据可删、结论不可删**：原始日志可裁剪，但 `README.md` 的**判据勾选表必须完整**。
2. **验收包在合并前入仓**——它是"本地全绿"这句话的载体。
3. 脚本化的断言放进 `scripts/acceptance/`，**每次执行都同时断言 HTTP 结果与落库状态**。
