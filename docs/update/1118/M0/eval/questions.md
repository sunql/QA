## 实体占位值说明（v1 新增）

v0 保持附录 B 原文（「指定物料」「这些供应商」），实跑证明这会让题目**不可执行**。
v1 固定为 `A0001` / `S0001`–`S0003`：

- 这些编码是**占位值**，不保证在业务库存在；
- 评估工具**不执行**生成的 SQL ⇒ 编码是否存在不影响两态对照；
- 评的是「开关是否改变了回答」，**不是答案对错**（后者归 M2 / M7）。

## v1 的已知覆盖缺口（**必须写进报告，不得省略**）

1. **最低集，不是全集**：附录 B 只有 7 题；M0.4 §4.6 要求「5 类每类 ≥2 题」⇒ 需 D 问卷回收后升 v2。
2. **边界题只有 1 道（Q03）**：采购域本体无质量/合规事实表，两态都会产出「无法回答」类查询
   ⇒ 可验证「开关没把数据缺口变成有答案」，但不足以覆盖「越权数据」负例（D2.4 回收后补）。
3. **3 题不参与**：Q04（RAG+Rule）、Q06/Q07（Workflow）不经过语义发布开关的 NL2SQL 路径，
   开关两态对它们**本就无影响**；把它们算进通过率只会稀释信号。
4. **不含答案对错**：两态评估只回答「开关是否改变了回答」，不回答「回答是否正确」——后者归 M2 / M7。
5. **Q02 的时间窗口由模型合成**：SQL 里的日期字面量取决于生成时刻，若同态两遍不一致，
   按规则判 J > 0 ⇒ 退出码 6（不可归因），**不得**人工放宽。

## 变更纪律

- **改任何一题 ⇒ 升 `version` 并重算 `sha256`**；脚本对摘要不符直接退出码 4（前置条件），不进入评估。
