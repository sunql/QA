      │
      ▼
编排层 _SqlOutcome.semanticReleaseId
      │
      ▼
运行记录 session_query_state.semantic_release_id  ──► 下一轮 _planAndGenerateSql 取它当 pinnedReleaseId

## 3. 重放一致性的判据（为什么这条断言不是假绿）

「同一请求重放读取同一发布」若只断言「返回的 id 相同」，那只是**断言了一个字段**。
真正的判据是**渲染结果逐字节相同**。本批的测试做法
（`test_重放读同一发布则文本逐字节相同`）：

1. 造两份快照：**A** = 与当前本体**事实一致**的快照（此刻它是 ACTIVE）；
   **B** = 与当前本体**事实不一致**的快照（多一个 SUPPLIER 属性 ⇒ 走未钉住路径会被 D15 守卫拒绝）；
2. **基准**：`first` = A 为 ACTIVE 时渲染出的文本；
3. **实验组**：B 上位后**钉住 A** ⇒ `replay.text == first.text`（**逐字节相同**）
   ⇒ 证明钉住真的取到了 A，且没有偷偷回退到 ACTIVE；
4. **对照组**：B 上位后**不钉住**（走 ACTIVE=B）⇒ 守卫拒绝 B ⇒ 降级直读
   ⇒ `withB.text != first.text`（**发散**）且 `withB.semanticReleaseId is None`
   ⇒ 若「重放一致」这条断言恒真，它必然是假绿。

即：**控制组必须发散、实验组必须收敛**，两者同时成立才有意义。

> 真实 dev 库上的探针（§4.5）用的是**另一套基准**：单测用「两份事实等价、列序不同的快照」
> 造发散/收敛；探针在真实库里没法造第二份快照 ⇒ 改用「**同一版两次渲染逐字节相同**」
> +「**钉住 == ACTIVE**（仅当 ACTIVE 路径确实用了快照）」两层，详见 §4.5 的说明。

> 必然不等 ⇒ 拿它当唯一基准会把「**ACTIVE 陈旧**」误报成「**钉住重放不一致**」，结论指错方向。
> ⇒ 基准拆成两层：**① 同一版两次钉住渲染逐字节相同**（任何时候都成立，这才是「重放」本体：
> 渲染只由「发布 id」决定）；**② 钉住渲染 == ACTIVE 渲染**（**仅当 ACTIVE 路径确实用了快照**时才成立；
> ACTIVE 降级时跳过该比对并明确报出「基准不可用」，**不误判成失败**）。

## 6. 开关 / 降级契约（D17 演练要照着读）

| 场景 | 钉住？ | 行为 | 日志 |
|---|---|---|---|
| 开关关（默认） | — | 连库都不碰，**逐字节等于今天** | — |
| 开关开 + 无 ACTIVE 快照 | 否 | 直读治理表 | INFO「当前没有 ACTIVE 语义发布快照…」 |
| 开关开 + 钉住的那一版**已被删除** | 是 | 降级直读、**不回报 id**、**钉住失效 ⇒ 运行记录里的钉住被清空**（DD-2 三态的第三态） | WARNING「钉住的语义发布已不存在（releaseId=…），本次降级为直读治理表」 |
| 开关开 + 钉住的那一版**完整性校验失败**（manifest_hash 对不上 / 体量超限） | 是 | 降级直读、**不回报 id**、**清空钉住** | ERROR「钉住的语义发布完整性校验失败…」 |
| 开关开 + 快照与当前本体**事实不一致** | **否**（未钉住 / ACTIVE 路径） | 拒绝用快照、降级直读、**不回报 id**（D15 语义不变） | ERROR（D15 守卫，事实缺口语义） |
| 开关开 + 快照与当前本体**事实不一致** | **是**（已钉住路径） | **仍用该版渲染**、**不降级**、**回报该 id**（偏差 ⑭ 的分叉：钉住的意义就是「明知与当前本体有差异，仍按那一版作答」） | WARNING（记差异，**不降级**） |
| 开关开 + 快照**新鲜** | 是 | 用快照渲染，**回报该发布 id** ⇒ 下一轮钉住 | — |

> **写侧三态（DD-2）**：`semanticReleaseId` 给了 ⇒ **覆盖**；`None` ⇒ **保留**既有钉住；
> `pinInvalidated=True` ⇒ **清空**。⇒ 死钉（钉住的那一版已被删除）**自愈**，
> 不再需要人工清理；也不存在「把列清空 ⇒ 悄悄丢掉上一轮的钉住」。

> ⚠️ **偏差 ⑪ 未决**：D15 的「报错而非静默降级」实现为「降级 + ERROR 日志」（P0 裁决一），
> **仍需负责人拍板**，D17 前必须确认。
> （偏差 ⑭ 的分叉只影响**未钉住分支**的告警强度，不影响 D16 交付。）
