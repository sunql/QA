# M0 · report/ —— 汇总报告

> 依据：[《本地全绿判据书》§3 验收包目录约定](../本地全绿判据书.md#3--验收包目录约定)
> 状态：骨架（2026-11-18 A3）

本目录放**汇总级**报告：把分散在 `evidence/` 的原始输出收敛成一句可判的结论。
原始日志不进这里（进 `evidence/`），逐问证据也不进这里（进 `q/`）。

## 应有什么

| 文件 | 对应判据 | 内容 | 生成方式 |
|---|---|---|---|
| `e2e-summary.md` | 判据 4 | Q01–Q07 / P-01…P-14 逐条通过情况 + 链接到 `q/*.md` | 人工汇总（每问结论必须二值） |
| `coverage-summary.md` | 判据 5 | 覆盖率数字 + **绿跑**的 commit/时间戳 + 未覆盖热点 | 只在整套件绿跑后产出 |
| `performance.md` | 判据 6 | P95 实测值 vs 阈值 + 测量条件（数据量 / 并发 / 机器） | 基准脚本 + 环境记录 |

## 纪律

1. **报告里的每个数字都要能追到 `evidence/` 的原始输出**；追不到的数字不写。
2. **套件红时不写覆盖率**（判据书 §1.3）——分母不完整，数字不可用。
3. 报告是**结论载体**，允许随证据刷新而更新；但已归档版本的结论不得被静默覆盖，
   改结论要在文末追加「修订记录」（日期 / 原结论 / 新结论 / 原因）。
