## 一、整体定位

QA System 是一个**企业 AI-Ready 数据底座**，面向数据分析场景提供两类核心能力：

1. **对话式 NL2SQL**：用户用自然语言提问，系统自动解析意图 → 生成 SQL → 查询业务库 → 渲染图表
2. **AI Agent 平台**：结构化业务工具（供应商 360°、风险评估、图推理）的注册、鉴权与调度

当前版本为 **Phase 7**（Phase 1-5 + Phase 6 + Phase 7 缺口全部完成）。

## 三、模块说明

### 3.1 对话引擎（Chat）

| 端点 | 说明 |
|------|------|
| `POST /chat` | 主对话入口，SSE 流式响应（Markdown + 图表卡片） |
| `POST /chat/suggest` | 相似历史问法建议（向量检索） |
| `GET /sessions` | 会话列表 |
| `GET /sessions/{id}/history` | 历史消息 |

**对话路由链**：
1. 意图解析（`IntentService`）→ 识别 NL2SQL / Graph / Agent / DomainCommand
2. 数据源解析（`DataSourceService`）
3. 执行（`Nl2SqlService` / `GraphTraversalService` / `AgentRuntimeService`）
4. 渲染（`ChartService` / `Supplier360Service`）
5. SSE 流式输出

### 3.2 AI Agent 平台（Phase 6.4 + Phase 7）

| 端点 | 说明 |
|------|------|
| `POST /agents` | 创建 Agent 定义 |
| `GET /agents` | 列表（按 status/dataDomain 过滤） |
| `GET /agents/{code}` | 详情 |
| `POST /agents/{code}/run` | 触发一次 Agent 执行 |
| `GET /agents/{code}/policies` | 访问策略 |
| `POST /agents/{code}/schedules` | 创建定时调度（Phase 7 G5） |
| `GET /agents/{code}/schedules` | 调度列表 |
| `GET /agents/{code}/schedules/logs` | 运行历史 |

**内置 Agent 工具**：

| Agent | 工具 | 数据层 | 说明 |
|-------|------|--------|------|
| `SUPPLIER_360_AGENT` | `supplier_360` | DIM + FEATURE | 供应商综合信息 |
| `SUPPLIER_RISK_AGENT` | `supplier_risk` | DIM + FEATURE | 供应商风险评估 |
| `GRAPH_REASONING_AGENT` | `graph_traverse` | DIM + DWD | 业务图多跳推理 |

**定时调度**：croniter 解析 cron 表达式 → PG `agent_schedule` 表 → 独立 worker 进程轮询 → `AgentRuntimeService.run` → `agent_run_log` 落库

### 3.3 本体管理（Ontology）

| 端点 | 说明 |
|------|------|
| `GET/POST /ontology/classes` | 类 CRUD |
| `GET/POST /ontology/properties` | 属性 CRUD |
| `GET/POST /ontology/metrics` | 指标 CRUD |
| `GET /ontology/classes/{name}/versions` | 版本历史（Phase 6） |
| `POST /ontology/search` | 向量语义检索 |

### 3.4 数据质量（KPI Catalog + DQ Rules）

| 端点 | 说明 |
|------|------|
| `GET/POST /kpi-catalog` | KPI 目录 CRUD |
| `POST /kpi-catalog/{id}/evaluate` | 执行评分 |
| `GET/POST /data-quality/rules` | DQ 规则 CRUD |
| `POST /data-quality/scores` | 质量评分写入 |

### 3.5 知识管理（Phase 5.2）

| 端点 | 说明 |
|------|------|
| `POST /documents/upload` | 上传文档（分块 + embedding） |
| `GET /documents` | 文档列表 |
| `GET /documents/search` | 语义检索 |

## 五、与设计文档的偏差

| 设计项 | 现状 | 偏差原因 |
|--------|------|----------|
| 多租户 tenant_id | 未实现 | MVP 阶段不需要，架构预留字段 |
| Redis 缓存本体 | 未实现 | 当前规模下性能可接受，优先级低 |
| SL(Segment Routing) 多模型路由 | 部分实现 | 只做了加权随机 + 成本阈值，未做 Segment Routing |
| 完整 Data Lineage | 部分实现（边） | 字段级血缘未实现，只有表级血缘 |
| SL(Segment Routing) 多租户隔离 | 未实现 | MVP 阶段不需要 |
| APScheduler 调度 | 改为 croniter + 独立 worker | APScheduler 绑定进程生命周期，croniter 更轻量独立 |

## 六、Known Limitations

- **NL2SQL**：仅支持 SELECT，禁止 DDL/DML；不支持多表 JOIN 以外的复杂 SQL
- **图推理**：固定 2-hop（`graph_traverse` 工具），Chat 路径支持口语跳数指定（1-5 hop）
- **Token 计量**：prompt/completion 拆分已完成，但累计成本展示仍在用量看板中
- **Agent 调度**：Worker 进程需手动启动（`python -m app.workers.agent_scheduler_worker`），暂无 systemd/supervisor 脚本
- **文档 RAG**：分块策略固定（512 tokens），无自定义分块规则

## 七、快速参考

### 启动后端
```bash
cd backend
cp .env.example .env  # 填写 DATABASE_URL / OPENAI_API_KEY 等
uv run python -m uvicorn app.main:app --reload --port 8000
```

### 启动 worker（Agent 调度）
```bash
uv run python -m app.workers.agent_scheduler_worker
```

### 跑测试
```bash
# 单元测试
uv run pytest app/tests/unit/ -q

# 集成测试（需真实 PG 5433）
TEST_DATABASE_URL=postgresql+asyncpg://qa_user:qa_pg_dev_2026@localhost:5433/qa_metadata_test \
  uv run pytest app/tests/integration/ -q

# 覆盖率
TEST_DATABASE_URL=... uv run pytest app/tests/ --cov=app --cov-fail-under=80
```
