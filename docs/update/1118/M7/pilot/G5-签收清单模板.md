# G5 采购域试点：业务签收清单（模板）

> 本文件是**模板**，不含真实业务数据。真实签收物料由脚本生成在仓库外：
> `backend/scripts/discovery_pilot_supplier_material.py`
> 默认输出 `/tmp/discovery-pilot-<时间戳>/`（`summary.md` / `candidates.csv` / `findings.csv`）。

## 一、试点范围（首期）

| 对象 | 表 | 说明 |
|---|---|---|
| 供应商 | `DIM_SUPPLIER` | 主数据；业务键候选 `BPSNUM_0` |
| 物料 | `DIM_IMATERIAL` | 主数据；业务键候选 `ITMREF_0` |

## 二、生成签收物料

```bash
cd backend
QUERY_TIMEOUT_SECONDS=120 python -m scripts.discovery_pilot_supplier_material \
  --datasource 1 \
  --tables DIM_SUPPLIER,DIM_IMATERIAL \
  --dataset-version pilot-2026-11 \
  --out-dir /tmp/discovery-pilot-g5
```

输出：
- `summary.md`：候选数 / 问题数 / 证据完整率 / verdict（**不含真实值**，可归档进仓库）；
- `candidates.csv`：逐条候选 + 证据摘要 + **空白判定列**（utf-8-sig，Excel 直接打开）；
- `findings.csv`：逐条主数据问题 + **空白判定列**。

> ⚠️ CSV 含真实业务值（如供应商名称、日期边界）⇒ **不要提交进仓库**；归档时只提交 `summary.md`。

## 三、业务签收表（逐条填写）

### candidates.csv 判定列

| 列 | 允许值 | 含义 |
|---|---|---|
| `businessVerdict` | `采纳` / `驳回` / `待证` | 该候选是否进入下一轮提案 |
| `businessNote` | 自由文本 | 驳回理由 / 需补充的证据 / 口径确认 |

判定口径建议：
- **采纳**：语义与证据一致，且符合业务口径（例：`BPSNUM_0` distinct=3500=行数 ⇒ 业务键）；
- **待证**：方向对但证据不足（需补采样/对账/与源系统文档核对）；
- **驳回**：语义不符（例：把「付款条件列」误判成「供应商编码」）。

### findings.csv 判定列

| 列 | 允许值 | 含义 |
|---|---|---|
| `businessVerdict` | `确认` / `不成立` / `待核` | 该主数据问题是否成立 |
| `businessNote` | 自由文本 | 处理建议 / 负责人 / 是否另行立项 |

## 四、误合并复核（硬性红线）

本流程**不做自动合并**：候选只有被人工采纳、并进入提案 → 四眼审核 → 发布后才可能生效。
⇒ 误合并率**结构性为 0**；但请业务在 `businessNote` 里注明任何「两个不同实体被当成一个」的候选。

## 五、评测指标与上报

| 指标 | 来源 | 阈值 |
|---|---|---|
| 候选准确率 | `businessVerdict=采纳` ÷ 已判定条数 | 试点基线后签署 |
| 候选召回率 | 业务标注集（CSV 之外的已知清单） | 试点基线后签署 |
| 证据完整率 | 脚本自动算（应恒为 100%） | **100%**（硬性） |
| 人工耗时 | 签收人记录（分钟） | 试点基线后签署 |
| 误合并率 | 见 §四 | **0**（硬性） |

签收完成后，由管理员上报：

```bash
curl -X POST http://127.0.0.1:8010/api/v1/ontology-discovery/runs/<runId>/evaluate \
  -H 'Content-Type: application/json' -H 'X-User-Id: admin' -H 'X-User-Roles: admin' \
  -d '{"datasetVersion":"pilot-2026-11","note":"业务签收：准确率 x%、召回 y%、人工 z 分钟"}'
```

或直接用 `recordEvaluation` 服务上报带准确率/召回的指标（需业务先给出标注集）。
