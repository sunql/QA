认证是 X-User-Id 头桩映射
目前是认证是 X-User-Id 头桩映射，要调整为用户名，密码认证，但是要临时保留认证是 X-User-Id 头桩映射的能力，通过一个开关做管理，等正式上线等时候在切换。
下面是一套升级方案，核心思路是：**引入真正的账号密码登录 → 签发 token → 认证过滤器优先走 token，开关打开时才回退到 `X-User-Id` 桩**。上线时把开关关掉即可。

---

## 一、整体架构

```
客户端 --(账号密码)--> /auth/login --> 校验密码 --> 签发 JWT
客户端 --(Bearer JWT)--> 业务接口 --> 认证过滤器 --> 解析出 userId --> UserContext
                                          |
                                          └-- 若开关开启且无 token --> 回退读 X-User-Id
```

关键点：**两种认证方式收敛到同一个 `UserContext`**，业务代码完全不用改。

---

## 二、数据库：用户表

```sql
CREATE TABLE sys_user (
    id            BIGINT PRIMARY KEY AUTO_INCREMENT,
    username      VARCHAR(64)  NOT NULL UNIQUE,
    password_hash VARCHAR(100) NOT NULL,   -- BCrypt 结果
    nickname      VARCHAR(64),
    status        TINYINT DEFAULT 1,       -- 1 启用 0 禁用
    created_at    DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

密码**绝不能明文存**，用 BCrypt：

```java
String hash = new BCryptPasswordEncoder().encode(rawPassword);
boolean ok = new BCryptPasswordEncoder().matches(rawPassword, hash);
```

## 三、登录接口，签发 JWT

```java
@PostMapping("/auth/login")
public LoginResp login(@RequestBody LoginReq req) {
    SysUser user = userMapper.findByUsername(req.getUsername());
    if (user == null || !encoder.matches(req.getPassword(), user.getPasswordHash())) {
        throw new BizException("用户名或密码错误");
    }
    if (user.getStatus() != 1) {
        throw new BizException("账号已禁用");
    }
    String token = jwtUtil.sign(user.getId(), user.getUsername());
    return new LoginResp(token);
}
```

JWT 里放 `userId`、`username`、过期时间，用密钥签名。示例（jjwt）：

```java
public String sign(Long userId, String username) {
    return Jwts.builder()
        .setSubject(String.valueOf(userId))
        .claim("username", username)
        .setExpiration(new Date(System.currentTimeMillis() + expireMs))
        .signWith(Keys.hmacShaKeyFor(secret.getBytes()), SignatureAlgorithm.HS256)
        .compact();
}
```

## 四、认证过滤器（核心：开关在这里）

```java
@Component
public class AuthFilter implements Filter {

    @Value("${auth.stub-x-user-id-enabled:false}")
    private boolean stubEnabled;   // 桩开关

    private final JwtUtil jwtUtil;

    @Override
    public void doFilter(ServletRequest req, ServletResponse resp, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest request = (HttpServletRequest) req;

        Long userId = null;

        // 1. 优先走真正的 token 认证
        String auth = request.getHeader("Authorization");
        if (auth != null && auth.startsWith("Bearer ")) {
            try {
                userId = jwtUtil.parseUserId(auth.substring(7));
            } catch (Exception e) {
                // token 非法/过期
                writeUnauthorized(resp, "token 无效或已过期");
                return;
            }
        }

        // 2. token 没解析出来时，才考虑桩
        if (userId == null && stubEnabled) {
            String stub = request.getHeader("X-User-Id");
            if (stub != null && !stub.isBlank()) {
                userId = Long.valueOf(stub);
                log.warn("[STUB] 使用 X-User-Id 桩认证, userId={}, uri={}",
                         userId, request.getRequestURI());
            }
        }

        // 3. 仍无身份 → 拒绝
        if (userId == null) {
            writeUnauthorized(resp, "未登录");
            return;
        }

        // 4. 写入上下文，业务代码统一从这里取
        try {
            UserContext.set(userId);
            chain.doFilter(req, resp);
        } finally {
            UserContext.clear();   // 防止线程池串号
        }
    }
}
```

`UserContext` 用 ThreadLocal：

```java
public class UserContext {
    private static final ThreadLocal<Long> HOLDER = new ThreadLocal<>();
    public static void set(Long id) { HOLDER.set(id); }
    public static Long get() { return HOLDER.get(); }
    public static void clear() { HOLDER.remove(); }
}
```

业务代码统一写 `UserContext.get()`，这样**从桩切到真登录，业务层零改动**。

## 五、配置开关

`application.yml`：

```yaml
auth:
  stub-x-user-id-enabled: true   # 开发/测试：true；生产：false
```

或按环境隔离：

```yaml
# application-dev.yml
auth:
  stub-x-user-id-enabled: true

# application-prod.yml
auth:
  stub-x-user-id-enabled: false
```

**上线时只需把 prod 的值改成 false，重新发布即可，不用动代码。**

如果不想重新发布，也可以把开关做成配置中心（Nacos/Apollo）的动态配置，运行时直接关掉。

## 六、上线前必须做的安全加固

1. **生产环境 `stub-x-user-id-enabled` 必须为 false**
   否则任何人伪造 `X-User-Id: 1` 就能冒充管理员。

2. **网关层剥掉外部传入的 `X-User-Id`**
   即便服务端开关关了，也建议在网关把客户端自带的 `X-User-Id`、`X-Real-User` 之类的头全部删掉，只允许网关注入。

3. **密码策略**
   BCrypt/Argon2 加盐，禁止明文、禁止 MD5。

4. **JWT 密钥**
   放环境变量或密钥管理服务，别写死在代码/仓库里；设置合理过期时间，必要时加刷新 token。

5. **登录防爆破**
   失败次数限制、验证码、IP 限流。

6. **HTTPS**
   密码和 token 必须走 TLS。

## 七、平滑迁移步骤

1. 加用户表 + 登录接口 + JWT 签发。
2. 加认证过滤器，**先让桩开关为 true**，此时新旧逻辑共存。
3. 前端/调用方逐步接入登录，改用 `Authorization: Bearer xxx`。
4. 观察日志里 `[STUB]` 出现频率，降到 0 说明没人再用桩了。
5. 生产配置把 `stub-x-user-id-enabled` 设为 false。
6. 观察一段时间无异常后，删掉过滤器里的桩分支和相关配置。

---

## 八、可选增强

- **网关统一认证**：把 JWT 校验放网关，网关解析后把 `X-User-Id` 注入给下游。这样下游服务天然只信任网关注入的头，桩逻辑可以直接演进成正式方案。
- **权限模型**：在 `UserContext` 里再挂角色/权限，加 `@PreAuthorize` 注解做接口级鉴权。
- **审计日志**：记录登录、失败、桩使用情况，方便排查和合规。

---

一句话总结：**认证方式收敛到 `UserContext`，过滤器里“先 token 后桩”，桩由配置开关控制，生产关掉开关即可完成切换。**
