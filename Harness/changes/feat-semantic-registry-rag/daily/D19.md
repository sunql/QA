## 三、降级口径矩阵（安全关键，逐条单测钉死）

| 场景 | 读什么 | 结果 | `degradedReason` |
|---|---|---|---|
| 开关关（无过滤器） | v1 | 与今天一致 | `None` |
| 开关关（**带**过滤器） | v1（不过滤） | 与今天一致 + **口径失真告警** | `switch_off_with_filter` |
| 开关开，无过滤器，v2 正常 | v2 | 正常 | `None` |

| 开关开，**有作用域**，v2 缺失/异常 | — | **fail-closed：空结果** | `v2_missing` / `v2_error` |
| 开关开，有作用域，表达式构造失败 | — | **fail-closed：空结果** | `filter_invalid` |

> **为什么有作用域时绝不回落 v1**：回落 = 拿「不过滤的答案」冒充「按维度过滤的答案」
> = 把越权行放进来 = 泄漏。宁可召回为空（上层有 fallback 路径）。

## 四、维度映射的 fail-closed 语义（已实测）

| 维度 | 表达式 | 未归域行 |
|---|---|---|
| 域 | `array_contains(domain_codes, "X") or …` | 空数组不命中 ⇒ 被排除 |
| 组织 | `array_contains(org_codes, "X") or …` | 同上 |
| 实体 | `entity_type == "X"` | `""` 不命中 ⇒ 被排除 |
| 有效期 | `valid_from <= now and (valid_to == 0 or valid_to >= now)` | `valid_to=0` = 长期有效（fail-open，业务语义） |
| 发布 | `release_id == N` | `0` 不命中 ⇒ 被排除 |

维度间 `and` 组合；**从不用 `not array_contains`**（D18 实测：它会命中空数组行）。

「未归域行被排除」是**可解释的收窄**（该行本来就没有域），不是泄漏：
过滤只决定「召回候选集」，不放行任何行。

## 六、本日裁决

| # | 裁决 | 理由 |
|---|---|---|
| D19-① | **一个开关管读 + 写**（`ENABLE_SEMANTIC_REGISTRY_RAG`） | 两个开关会产生「读 v2 但从没写 v2」的错配态 ⇒ 必然空召回，且难以归因 |
| D19-② | **有作用域 ⇒ fail-closed**，绝不回落无过滤的 v1 | 回落即泄漏；宁可空结果 |
| D19-③ | 维度从 **PG 治理表**推导，**查不到就写空维度**（显式「未归域」），不猜 | 猜出来的维度 = 假治理事实；空维度 fail-closed 的行为可解释 |
| D19-④ | v2 写入**先删后插**（幂等覆盖），失败只告警不抛 | 幂等；影子副本挂了不该拖垮 CRUD，读路径闸门兜底 |
| D19-⑤ | v2 写侧**不原地改调用方的 record**（返回新记录） | 全局不可变约定；调用方常复用同一批 record 再写 v1 |
| D19-⑥ | 维度解析在 **commit 之后**做（CRUD 路径传 `session=`，后台任务自开短会话） | 未提交的行短会话看不到 ⇒ 维度会错记为空 |
| D19-⑦ | 闸门调 v1 检索走**模块属性** `milvus.searchEmbeddingsByTypeRouted` | 既有测试的 monkeypatch 点是 `milvus_client.searchEmbeddingsByTypeRouted`；
直接 `from … import` 会让老替身失效 ⇒ 回归假红 |

### 6.1 与 D18 裁决的一处**偏差**（须记账）

D18-⑦ 拟定的命名是 `insertEmbeddingsToVersions`（新双写另起名）。
本卡实际落名：

| 实际函数 | 位置 | 说明 |
|---|---|---|
| `insertRegistryV2` | `milvus_registry_v2.py` | 纯 Milvus 侧写入（无治理解析） |
| `syncRegistryV2Embeddings` | `registry_v2_write.py` | 业务侧双写（解析维度 + 写 v2） |
| `deleteRegistryV2Embedding` | `registry_v2_write.py` | v2 删除（开关保护） |

偏差理由：D18-⑦ 的**意图**是「避免与 `insertEmbeddingsDual` 的遗留命名混淆」。
`RegistryV2` 前缀同样满足该意图，且更准 —— 它表达的是「**注册表 v2 集合**」
（与 `Registry`（语义注册表发布）同源），而不是「版本」。
`insertEmbeddingsToVersions` 反而会与语义发布（release/version）概念撞名
—— 本仓 `release_id` 正是语义发布版本 ⇒ 保留 D18-⑦ 的意图、改掉字面名。
