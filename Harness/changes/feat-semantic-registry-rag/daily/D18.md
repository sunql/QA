## 实测依据（2026-11-15，本地 Milvus 2.4.6，库 `qa_test`）

探针脚本自建 `probe_array_v1` / `probe_array_v2` 两个集合，跑完 `drop_collection` 清理。

### 1. 表达能力

| 写法 | 实测输出 |
|---|---|
| ARRAY\<VARCHAR\> 建集合 + 插入（含空数组） | `insert with empty arrays OK, entities: 3` |
| `array_contains(domain_codes, "SUP")` | `OK → [('SUPPLIER', ['SUP','PROC'])]` |
| `domain_codes in ["SUP"]` | `FAIL MilvusException: value '"SUP"' in list cannot be casted to Array` |
| `domain_codes like "SUP"` | `FAIL MilvusException: can not comparisons array fields directly` |
| `entity_type == "SUPPLIER"` | `OK` |
| `valid_from <= 150 and (valid_to == 0 or valid_to >= 150)` | `OK`（2 行，含 `valid_to=0` 长期有效行） |
| `not array_contains(domain_codes, "SUP")` | `OK → [([], []), (['MAT'],…)]` ⇒ **空数组行被命中** |
| `query(expr=…, output_fields=[ARRAY])` | `OK → {'domain_codes': ['SUP'], …} / {'domain_codes': [], …}` |

### 2. 由实测锁死的三条设计约束

1. 多值维度**只能** `array_contains(...) or ...`；`in` / `like` 在 ARRAY 上直接 query plan 解析失败
   （⇒ 不能用 `like "SUP"` 糊弄——既跑不通、语义也会误命中 `SUPX`）。
2. `not array_contains` **命中空数组行** ⇒ 「排除某域」必须显式枚举允许域，
   不能用否定式。
3. 空数组是**合法值**（未归域用 `[]` 表达）——`enable_dynamic_field=false` 下
   缺字段写不进去。

### 3. 数据摸底（本地 dev PG `qa_metadata`）

| 项 | 值 | 推论 |
|---|---|---|
| ontology_class | 55（`valid_to` 非空 18） | 有效期维度有真实数据 |
| business_object | 6（`primary_domain_id` 全有值） | — |
| data_domain / business_object_domain | 4 / **0** | 无附域 ⇒ ARRAY 当前只有 1 元素 |
| organizations | 6 | 组织维度有真实数据 |
| **有域的类** | **6 / 55 ≈ 11%** | **域过滤一旦生效会显著收窄召回** |

⇒ 由此产生 D20 的硬要求：影子比对报告必须给「**归因缺口**」计数，
否则无法区分「过滤错了」与「本体没归域」。

## 本日裁决

| # | 裁决 | 理由 |
|---|---|---|
| D18-① | **新建 v2 集合 + 全量回填**，不改 v1 | 沿用 `p0/数据基线.md` §4 裁决 #4（2.4.6 的 `add_collection_field` 不可靠；总量 < 7,100 行 ⇒ 重建成本极低） |
| D18-② | **回填复用 v1 现有 embedding，绝不重算** | 否则影子差异里会混入「向量漂移」，差异不可解释 |
| D18-③ | **回填只增不删** | Milvus 无自动备份 ⇒ drop 不可逆；本仓有前科（2026-09-30 裸 pytest 删空线上向量） |
| D18-④ | **域/组织/实体/发布四维 fail-closed，有效期 fail-open** | 未归域的行在域过滤下被排除 ⇒ 是**可解释**的收窄而非泄漏；有效期 `valid_to=0` 视为长期有效（业务语义） |
| D18-⑤ | **本批只交付过滤机制，不发明授权策略** | 本仓现有 ACL 只有 `assertCanModify`（admin 级），**没有**「用户 → 可见域/组织」策略源；策略接线属受控变更，另立 |
| D18-⑥ | **维度用 epoch 毫秒 INT64，不用日期字符串** | INT64 范围比较实测 OK；字符串日期比较在 2.4.6 未实测 ⇒ 不冒险 |
| D18-⑦ | **新双写另起名 `insertEmbeddingsToVersions`** | 既有 `insertEmbeddingsDual` 的 "dual write" 是「单集合→按类型拆三集合」的遗留命名，不是 v1/v2 双写 ⇒ 避免后人误读 |
