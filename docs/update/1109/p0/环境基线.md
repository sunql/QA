## 3. 关键结论

### C1（重要）：生产部署不走仓库的 centos overlay

生产实际入口（见 `Harness/changes/feat-data-domain-layer/deploy-prod-1025.md`）：

```bash
docker-compose -p qa-system \
  --env-file /opt/qa-system/docker/.env \
  -f /opt/qa-system/docker/docker-compose.centos7.yml "$@"
```

- 生产 compose 文件是 **`/opt/qa-system/docker/docker-compose.centos7.yml`**，且为 **Compose v1 兼容写法**；
- 仓库里的 `docker/docker-compose.centos.yml` 使用 `!override`（≥2.24）与 `profiles`（v2），**在生产上不可用**，不要拿它当部署依据；
- 生产还包含仓库里没有的 `qa-ollama-https`（nginx TLS 代理）；后端/前端用离线镜像手工 `docker load` + `docker tag` 发布。

⇒ **P5 新增 Worker/服务必须遵守离线发布 runbook，并写 v1 兼容的 compose 片段；不得依赖 `!override` / `profiles` / `docker compose` 子命令。**
