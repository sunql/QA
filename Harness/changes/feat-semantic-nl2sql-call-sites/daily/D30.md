# D30 每日证据（2026-11-16）—— chat_recall 整链切换 + 调用点清单

> 分支：`feat/semantic-nl2sql-call-sites`；**零 DDL、不部署**。

## 〇、需求

召回链（`classifyAndRecall`）直读治理表：全量类 `listClasses`、DIM 补拉
`_fetchAllDimClasses`、join 目录 `listJoins`。会话钉住了发布时仍是活本体
⇒ 召回选出的类与 schema 渲染（P2 已钉）可能不同版本。

## 一、关键裁决：**整链切换，不是只切 DIM**

混合口径（DIM 从快照、其它从活表）会静默破坏「按发布读」的合同——
同一个问句里两半用了两个版本的本体。⇒ D30 把召回链的**三个本体读**
（全量类 / DIM / join 目录）一次全部接到同一版快照上。

## 二、实现

| 文件 | 职责 |
|---|---|
| `app/services/semantic_recall_gate.py` | **召回闸门**（137 行）：`loadRecallOntology(session, pinnedReleaseId)` ⇒ `RecallOntology`（全量类 + 全量 join，同一版快照）；降级语义与工具闸门一致 |
| `app/services/chat_recall.py` | `classifyAndRecall`：state 里取钉住 id ⇒ 视图；`allClasses` / DIM 补拉 / join 扩边三个读全部走视图（没钉住 ⇒ 原直读路径）；`_rankByLayer` / `_fallbackRecall` / `_selectRelevantClasses` 穿参 |

**为什么视图必须可变**（`RecallClass` 非 frozen）：召回管线会往类对象上写
`cls._recall_score = ...`（扩边后回填诊断分）——P2 的 `SnapshotClass` 是 frozen
⇒ 召回侧用**可变**视图（字段名与 ORM 逐字对齐 ⇒ 层判定/ODS 过滤/排序一视同仁）。

**降级即回落**：那一版被删 / 完整性失败 / 畸形 / 意外异常 ⇒ `None` + 留痕 ⇒
召回照旧直读治理表（问答不因语义面失败，G4「随时可回落」）。
