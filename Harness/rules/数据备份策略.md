# 数据备份策略

> **SSOT**：本文件是项目数据备份的**唯一权威**。所有 backup 脚本、根目录结构、保留策略、恢复命令必须与本文一致。
> **生效日期**：2026-09-19
> **关联**：`Harness/rules/数据存储防护.md`（防丢）、`Harness/rules/数据库环境使用规范.md`（Alembic）、`scripts/backup_*.sh`

## 一、强制要求（CRITICAL）

- **备份统一在项目根目录 `backups/`**：**禁止** 在 `backend/backups/` 或其它子目录新建。`backend/` 只放代码；所有运行时产物快照放根 `backups/`。
- **必须覆盖 5 类数据**：PostgreSQL（业务元数据）、Neo4j（本体图）、MinIO qa-objects（知识源文件）、Minvus minio bucket（向量索引）、Milvus etcd（元数据）。少任何一项都是不完整备份。
- **保留窗口 ≥ 14 天**：脚本默认 `--keep 14`，过旧自动清理；不可手工改成 < 7 天。
- **恢复演练 ≥ 季度一次**：从 dump 实际跑一次 `pg_restore` 到临时库 + `neo4j-admin database load`，确认链路通。
- **生产环境备份双写异地**：除本机 `backups/` 外，**额外** rsync 到独立存储（NAS / S3 / OSS）。本机磁盘单点故障不可作为唯一恢复源。
- **PreToolUse hook 守护销毁**：删除 `backups/` 子目录时（`rm -rf backups/...`）必须经 `QA_SYSTEM_VOLUME_GUARD_BYPASS=1` 二次确认（见 `Harness/rules/数据存储防护.md`）。
- **备份含 SECRETS**：Fernet 密文、Fernet key（`docker/.env` 的 `SECRET_KEY`）必须随业务数据一起备份；缺密钥 = 密文永久不可解。

## 二、根目录结构（SSOT）

```
backups/                                      ← 项目根目录 /Users/sunql/.../qa-system/backups/
├── pg/                                       ← PostgreSQL 元数据 + 业务数据
│   ├── qa_metadata_YYYY-MM-DD_HHMM.dump     ← 标准 cron 输出（backup_pg.sh）
│   ├── qa_metadata_pre-sync_*.dump          ← 一次性预迁移快照（人工）
│   ├── entity_mapping_*.dump                ← 单表导出（追溯同步前/后差异）
│   ├── document_catalog_*.sql               ← 单表 SQL 格式（git diff 友好）
│   ├── knowledge_relation_*.dump
│   ├── owner_*.sql
│   └── backup.log                           ← PG 备份脚本运行日志
│
├── neo4j/                                   ← Neo4j 本体图（5.23-community）
│   └── neo4j_YYYY-MM-DD_HHMM.dump           ← neo4j-admin database dump 输出
│
├── objects/                                 ← MinIO 知识源文件（qa-knowledge-sources 桶）
│   ├── objects_data_YYYY-MM-DD_HHMM.tar.gz  ← backup_objects.sh 标准输出
│   └── minio_qa-objects_YYYY-MM-DD_HHMM/    ← mc mirror 备选（人工）
│
├── milvus/                                  ← Milvus 全部三个卷 + 嵌入导出
│   ├── milvus_minio_YYYY-MM-DD_HHMM.tar.gz  ← backup_milvus.sh 标准输出
│   ├── milvus_data_YYYY-MM-DD_HHMM.tar.gz
│   ├── milvus_etcd_YYYY-MM-DD_HHMM.tar.gz
│   ├── document_embeddings_YYYY-MM-DD_HHMM.json.gz  ← 嵌入向量 JSON（可独立读）
│   └── minio_milvus_YYYY-MM-DD_HHMM/        ← mc mirror 备选（人工）
│
├── container/YYYYMMDD_HHMMSS/               ← 后端代码快照（alembic/app/scripts）
│   ├── alembic/
│   ├── app/
│   └── scripts/
│
├── file-edit/                               ← 历史：单文件编辑留底（保留仅供审计）
│
└── menu_config_*.sql                        ← 一次性菜单配置导出
```

**命名约定**（强制）：

| 类别 | 模式 | 示例 |
|---|---|---|
| 时间戳 | `YYYY-MM-DD_HHMM` 或 `YYYY-MM-DD_HHMMSS` | `qa_metadata_2026-09-19_1130.dump` |
| 容器快照目录 | `YYYYMMDD_HHMMSS`（无分隔符） | `container/20260912_100929/` |
| 文件后缀 | `.dump`（pg_dump -Fc）/ `.tar.gz`（卷 tar）/ `.sql`（文本）/ `.json.gz`（嵌入） | — |

## 三、备份脚本（SSOT）

所有备份走项目自带脚本，**禁止** 内联 `docker exec pg_dump` 等命令临时备份：

| 脚本 | 输出 | 何时跑 | 备注 |
|---|---|---|---|
| `scripts/backup_pg.sh` | `backups/pg/qa_metadata_*.dump` | 每日 cron | 默认 `--keep 14`；写日志到 `backups/pg/backup.log` |
| `scripts/backup_neo4j.sh` | `backups/neo4j/neo4j_*.dump` | 手动 | 2026-09-19 新增；停服 ~6s + temp 容器跑 `neo4j-admin database dump`；写日志到 `backups/neo4j/backup.log` |
| `scripts/backup_objects.sh` | `backups/objects/objects_data_*.tar.gz` | 手动 | ⚠️ **手动**——本机 cron 静默失效（launchd 契约断裂） |
| `scripts/backup_milvus.sh` | `backups/milvus/milvus_{minio,data,etcd}_*.tar.gz` | 手动 | ⚠️ **手动**——同上 |
| `scripts/install_pg_backup_cron.sh` | 注册 PG cron | 首次部署 / 重建后 | 一次性；其它三类**不**注册 cron |

**手动备份命令**（当前推荐）：

```bash
# PG（自动化）
./scripts/backup_pg.sh --keep 14

# Neo4j（**已补** backup_neo4j.sh）
./scripts/backup_neo4j.sh --keep 14

# MinIO 知识源文件
./scripts/backup_objects.sh

# Milvus 三卷
./scripts/backup_milvus.sh
```

## 四、保留策略

| 类别 | 保留窗口 | 清理机制 |
|---|---|---|
| PG dump | 14 天 | `backup_pg.sh` 内置 `find ... -mtime +14 -delete` |
| Neo4j dump | 14 天 | **待补**：`backup_neo4j.sh` 应含同款清理 |
| Objects tar | 14 天 | `backup_objects.sh` 内置 |
| Milvus tar | 14 天 | `backup_milvus.sh` 内置 |
| 容器快照 | 30 天 | **手动**清理（极少用，每月审一次） |
| 一次性 pre-sync / owner_*.sql | 不清理 | 历史里程碑，永不删 |

**生产环境保留窗口 90 天**，本机仅作 hot tier；异地冷存储保留 1 年。

## 五、恢复手册

### 5.1 PostgreSQL

```bash
# 1. 停服避免新写入
docker compose -f docker/docker-compose.yml stop backend frontend

# 2. 删库重建
docker exec qa-postgres dropdb -U qa_user qa_metadata --if-exists
docker exec qa-postgres createdb -U qa_user qa_metadata

# 3. 还原
docker exec -i qa-postgres pg_restore -U qa_user -d qa_metadata --no-owner --no-acl \
  < backups/pg/qa_metadata_2026-09-19_1130.dump

# 4. 启动 + 健康检查
docker compose -f docker/docker-compose.yml up -d backend frontend
curl http://localhost:8000/api/v1/health
```

### 5.2 Neo4j

```bash
docker stop qa-neo4j
docker run --rm \
  -v qa-system_neo4j_data:/data \
  -v $(pwd)/backups/neo4j:/backup \
  neo4j:5.23-community \
  neo4j-admin database load neo4j --from-path=/backup --overwrite-destination=true
docker start qa-neo4j
```

### 5.3 MinIO 知识源文件

```bash
# 删除现有卷内容（慎！）
docker run --rm -v qa-system_objects_data:/data alpine:3.20 sh -c 'rm -rf /data/*'

# 还原 tarball
docker run --rm \
  -v qa-system_objects_data:/data \
  -v $(pwd)/backups/objects:/backup:ro \
  alpine:3.20 \
  tar xzf /backup/objects_data_2026-09-19_1130.tar.gz -C /data
```

### 5.4 Milvus 三卷

```bash
# 停服
docker compose -f docker/docker-compose.yml stop milvus-standalone milvus-minio milvus-etcd

# 删卷
docker volume rm qa-system_milvus_minio qa-system_milvus_data qa-system_milvus_etcd

# 重建卷
docker compose -f docker/docker-compose.yml up -d milvus-minio milvus-etcd
# 等待健康
sleep 30

# 还原
for vol in milvus_minio milvus_data milvus_etcd; do
  docker run --rm \
    -v qa-system_${vol}:/data \
    -v $(pwd)/backups/milvus:/backup:ro \
    alpine:3.20 \
    tar xzf /backup/${vol}_2026-09-19_1130.tar.gz -C /data
done

docker compose -f docker/docker-compose.yml up -d milvus-standalone
```

### 5.5 SECRETS（必须一起恢复）

```bash
# docker/.env 必须与备份时间点同步——否则 Fernet 解密全部失败
cp backups/secrets/docker.env.2026-09-19_1130 docker/.env
docker compose -f docker/docker-compose.yml restart backend
```

## 六、验证 checklist

每次备份后跑一次：

```bash
# PG：dump 完整可读
pg_restore -l backups/pg/qa_metadata_2026-09-19_1130.dump | tail -5

# Neo4j：dump 文件 > 0 字节
[ -s backups/neo4j/neo4j_2026-09-19_1130.dump ] && echo "OK"

# MinIO：tar 可解压
tar tzf backups/objects/objects_data_*.tar.gz | head -5
tar tzf backups/milvus/milvus_minio_*.tar.gz | head -5

# 日志无 ERROR
tail -20 backups/pg/backup.log | grep -i "error\|fail" || echo "no errors"
```

## 七、CI / 自动化

- **CI 必查项**（`Harness/rules/开发流程规范.md` 的 PR 流水线）：
  - 改了 `app/domain/models.py` 表结构 → PR 必须附 alembic 迁移 + 提醒「备份后再合并」
  - 改了 `docker/.env` 模板 → PR 必须提醒「生产需要先备份 SECRET_KEY」
  - 改了 `scripts/backup_*.sh` → PR 必须保留输出到 `backups/<类别>/` 的命名约定
- **季度审计**（owner 责任）：跑一次完整恢复演练到临时库；不通过的备份**不算备份**。
