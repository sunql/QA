## 二、独立维度交叉核对（补上「真值自指」的缺口）

评审指出：D20 影子比对的「真值」是从 **v2 行自己带的维度字段**读出来的 ⇒
**自指** ⇒ 若回填把维度写错了，过滤与真值会**一起错**，「泄漏 0」照样成立 ⇒ **假绿**。

处置：新增 `scripts/verify_registry_v2_dimensions.py` —— 用**另一条代码路径**
（直接 SQL，见脚本 `_EXPECTED_DIMENSIONS_SQL`）从 PG 治理表重新推导期望维度，
再与 v2 行**实际存的值**逐行比对（纯逻辑有单测覆盖）。

实测（本地隔离实验库 `qa_registry_v2` + dev PG `qa_metadata`@5433，**只读**）：

| 项 | 值 |
|---|---|
| v2 行数 | **3,791** |
| 比对行数 | **3,791** |
| **不一致行** | **0** |
| 孤儿行（v2 有、治理表已无） | **0** |
| PG 有实体但无向量行 | 18（正常：不是每个实体都有向量） |

⇒ D20 的「泄漏 0」**不是自指的**：v2 里存的维度与 PG 治理事实**逐行一致**。

## 四、裁决

| # | 裁决 | 理由 |
|---|---|---|
| D21R-① | 评审意见按「**越权/静默失效**」与「**遗留增强**」两档分流 | 前者会真的让过滤失效（必须修）；后者是范围外的能力增强（登记即可，别在收尾轮悄悄扩大范围） |
| D21R-② | 「有作用域」一律 **fail-closed**（含开关关、空作用域、表达式非法、v2 缺失/异常） | 四种情形同源：**这条路径没有能力施加调用方声明的收窄** ⇒ 用「更宽的答案」冒充 = 泄漏 |
| D21R-③ | `releaseId <= 0` 判**非法输入**（抛错）而不是「当作不过滤」 | `release_id == 0` 是哨兵值；放行会让条件退化成另一个语义（召回所有无发布行） |
| D21R-④ | 影子/核对脚本**不得**自建表达式，必须委托生产构造器 | 自建的那份不认识转义与哨兵 ⇒ 验证的不是线上路径 ⇒ 证据失效 |
| D21R-⑤ | 死代码连**其测试**一起删 | 只删代码留测试 = 测试失去被测对象；只留测试 = 假信心 |
| D21R-⑥ | 「真值自指」用**独立代码路径**交叉核对来补，不改 D20 的判据 | D20 判据本身没错；缺的是「v2 存量 == 治理事实」这层外部锚点 |
