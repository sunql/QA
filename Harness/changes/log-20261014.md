## 一、根因

`alembic_version.version_num` 停在 `0117`,但库内实际 schema 已是 head `0121`：

- `0117` 的 DDL（`audit_log.entity_id_str` ADD COLUMN + `entity_id` DROP NOT NULL）已生效
- `b1ea6cb32588_run_state` 的 `CREATE TABLE research_run_state` + 2 索引已生效
- `0118/0119/0120/0121` 的 4 张研究平台表 + 全部索引已生效

容器每次启动都从 `0117` 开始 → alembic 重放整条 lineage → 在 `0117:25 op.add_column` 撞 `DuplicateColumnError` → crash loop（25s 间隔）。

最可能的漂移来源：**手工 DDL（`psql -c "ALTER ..."` / `docker cp` 覆盖代码后又跑了 schema 变更 / 分支切换 / 合版撞号）跑过表结构但未 `alembic stamp`**。本次未追溯到具体时间点（`pg_stat_user_tables` 已被覆盖），但形态与 memory `qa-system-alembic-merge-number-collision.md` 同款。

### 核心规则（精炼版）

1. **任何手工 DDL 跑过表结构后，必须立刻 `alembic stamp <revision>`**（承认事实）。
2. **禁止** DDL 没跑就用 `UPDATE alembic_version` 强行改版本号（只改声明不追事实 → 假 error）。
3. **stamp 前必须逐条对账 lineage**：grep 每个 revision 的 `op.*` + 库内 `\d` / `pg_indexes` 全部对齐。
4. **stamp 命令必须显式覆盖 `DATABASE_URL`**（即便走 docker compose env_file 注入，留痕）。

### stamp vs UPDATE 判定表

| 场景 | 元数据相对事实 | 推荐动作 | 严禁 |
|------|----------------|----------|------|
| DDL 已跑、版本号落后（库内对象齐全） | 落后 | **`alembic stamp head`** | `UPDATE alembic_version` 直改声明 |
| DDL 没跑、想跳过迁移 | 超前 | 补跑 DDL 再 stamp | `UPDATE alembic_version` 追上 |
| 部分 DDL 已跑 | 部分落后 | 补齐缺失 DDL 再 stamp head | stamp 到 head（schema 缺对象） |

## 三、本次修复执行（已落地，可复演）

```bash
# 停 backend
docker compose stop backend

# 摸现状
docker exec qa-postgres psql -U qa_user -d qa_metadata -c "SELECT version_num FROM alembic_version;"
# version_num = 0117

# 对账 lineage（0117 → b1ea → 0118 → 0119 → 0120 → 0121）：
# 逐条 \d research_* + SELECT indexname FROM pg_indexes ... → 全部齐
# 包括 audit_log.entity_id_str / entity_id nullable、research_session.active_run_id + FK

# Stamp head（一次到顶，因为 lineage 完整）
docker compose run --rm \
  -e DATABASE_URL='postgresql+asyncpg://qa_user:qa_pg_dev_2026@postgres:5432/qa_metadata' \
  backend alembic stamp head
# version_num: 0117 → 0121

# 验证 + 重启
docker compose up -d backend
sleep 8
docker ps --format 'table {{.Names}}\t{{.Status}}' | grep backend
# qa-backend  Up X seconds

curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/openapi.json
# 200
docker logs qa-backend --tail=20 | grep -E "Application startup|Uvicorn running"
# Application startup complete. / Uvicorn running on http://0.0.0.0:8000
```
