# D23 每日证据（2026-11-15）—— 图谱镜像的**物化 Job**（幂等 / dry-run / 分批 / 断点续跑）

> 分支：`feat/semantic-release-graph-mirror`（worktree `/private/tmp/qa-graph-mirror`）
> base = `origin/main` `b6af98a1`
> **零 DDL、不部署生产**；镜像写路径默认只准**测试实例**（7688），生产要显式 `--allow-prod-write`。
> 收口 D22 的遗留项 **L-5**（物化无状态标记 / 无原子性）与 **L-7**（已物化快照可被覆盖）。

## 〇、需求

D22 把「镜像怎么写」做出来了（纯计划构建 + 库函数），但**没有编排**：没有 dry-run、
没有分批、没有台账、没有断点续跑、没有「已物化就别再写」的闸门。
运维要重跑一次物化，只能手写一段 Python 调库函数 ⇒ 既没有退出码可判、也没有失败可续。

**验收标准（用户视角、可测量）**

| # | 标准 | 判据 |
|---|---|---|
| 1 | **不写图也能看到会怎么跑** | 默认（不加 `--apply`）只出计划；报告里每个批次有「打算写多少条」；**图上一个字节都不变** |
| 2 | **重复执行结果一致** | 跑两次，节点/边计数逐类相等；第二次能跳过已完好批次（不白写） |
| 3 | **失败可续跑** | 中途失败后再跑 ⇒ 已成功的批次跳过、坏的批次重跑 ⇒ 计数回到正确值 |
| 4 | **已物化的快照不会被悄悄改写** | 已 materialized 的发布默认**拒写**（退出码 2）；要重建必须显式 `--force-rebuild` |
| 5 | **破坏性操作有双保险** | 裁剪必须 `--prune --expect-delete N`；实际将删数 ≠ N ⇒ 拒绝执行 |
| 6 | **失败可判** | 退出码 4 档互斥：`0` 成功 / `1` 运行失败 / `2` 前置阻断 / `3` 物化完成但有未解析 |

## 二、方案对比（≥ 2 个候选，含取舍）

### 2.1 台账放哪：PG 表 vs Neo4j 节点

| 维度 | **A PG 新表**（`semantic_graph_job_state`） | **B Neo4j 节点**（采纳） |
|---|---|---|
| 迁移成本 | 新表 + Alembic 迁移 + **部署生产** | **零 DDL**（本批约束） |
| 与被描述对象的关系 | 台账在 PG、镜像是图 ⇒ 跨库一致性问题（PG 说成功、图被清空） | **同库** ⇒ 图没了台账也没了（自洽） |
| 写保护 | PG 表不受图库闸门保护 | **自动受**同一道写目标闸门保护（C-15） |
| 对账干扰 | 无 | 台账用**独立 label** ⇒ 对账计数不受污染（C-16） |
| 查询便利 | SQL 友好 | CQL（但只是「读几个状态」⇒ 够用） |
| 结论 | ❌ 破坏「零 DDL、不部署」 | ✅ **采纳** |

### 2.2 续跑「跳过」的依据：台账状态 vs 图上计数

| 维度 | **A 只信台账**（批次状态 = succeeded 就跳过） | **B 只信图**（每批都重写） | **C 台账 + 图计数双条件**（采纳） |
|---|---|---|---|
| 续跑速度 | 最快 | 慢（全量重写） | 只重跑「坏的」 |
| 台账说成功、图上被人工删了 | ❌ **跳过 ⇒ 永远修不好**（D23 真实踩到，见第七节） | ✅ 修好 | ✅ 修好 |
| 图被清空、台账还在 | ❌ 跳过 ⇒ 镜像永远缺失 | ✅ 修好 | ✅ 修好（图计数 0 ≠ 计划 ⇒ 重跑） |
| 结论 | ❌ **台账是「意图」，图才是「事实」** | 能修但慢 | ✅ **采纳**：跳过条件 = 台账 succeeded **且** 图上计数 == 计划计数 |

### 2.3 裁剪的确认方式

| 维度 | **A 只给 `--prune`** | **B `--prune --expect-delete N`（采纳）** |
|---|---|---|
| 误删风险 | 高（一个开关就能删掉整版镜像） | 低（数量对不上就拒绝） |
| 可用性 | 简单 | 运维要先看 dry-run 里的「将删 N 个」再照抄 N |
| 结论 | ❌ Neo4j 无备份（C-12）⇒ 不可逆 | ✅ **采纳**（实测不符 ⇒ 退出码 2，不删） |

### 2.4 dry-run 是否受「已物化」闸门约束

| 维度 | **A 一律拒绝**（初版实现） | **B 只挡写、不挡看**（采纳） |
|---|---|---|
| 运维想看「会怎么分批」 | ❌ 退出码 2，一个字节信息都拿不到 | ✅ 出计划（批次号 / 条数），图上零写入 |
| 保护了谁 | 保护「写」（但 dry-run **不写**） | 保护「写」，不挡「看」 |
| 结论 | ❌ 拒绝只该保护不可逆的写 | ✅ **采纳**（本批修的一个真 bug，见第七节） |

## 三、数据形态（裁决的具体化）

### 3.1 批次表（B1–B6）

| 批次 | 内容 | 规模（实测） | 备注 |
|---|---|---|---|
| B1 | `ReleaseClass` 节点 | 37 | 单批 |
| B2 | `ReleaseProperty` 节点 | 3267 | 最重的一批（属性数量级） |
| B3 | `ReleaseMetric` 节点 | 12 | |
| B4 | `ReleaseKpiCatalog` 节点 | 12 | |
| B5:`<relType>` | 6 种边，**每种一批**（`HAS_PROPERTY` / `SUBCLASS_OF` / `JOIN` / `DERIVED_FROM` / `MEASURED_BY` / `REFERENCES`） | 合计 3293 | 按 relType 分开 ⇒ 失败能定位到具体边型，也能单边型重跑 |
| B6 | prune（清理本次计划外的残留镜像节点**与边**） | 计划外才有 | **必须显式 opt-in**（`--prune --expect-delete N`） |

> 相比 D22 §五的粗版（B3 = 指标+KPI 合一、B4 = 全部边），实现**拆细**成
> B3/B4 各一类节点、边按 relType 一批 ⇒ 每批都有独立条数与耗时，失败定位粒度更细。

### 3.2 状态机

- 作业级：`materializing` → `materialized`（成功）| `failed`（中途失败）
- 批次级：`running` → `succeeded` | `failed` | `skipped`（已完好，跳过） | `planned`（dry-run 预览态，**不落库**）

台账节点 MERGE 键：作业 = `release_id`；批次 = (`release_id`, `batch_no`)
⇒ 同一次物化反复写只更新同一行（幂等）。

### 3.3 依赖失效规则

**本轮真重跑了节点批次 ⇒ 边批次与裁剪批次不许跳过。**
理由：节点属性变了，端点集合就可能变了 ⇒ 旧边集合不再等于新计划（少写或多写）。
「节点跳过、边重跑」是安全的（端点没变）；反过来不安全。

## 四、边界声明（本批**不做**的事，写明理由）

| 不做的事 | 理由 |
|---|---|
| **HTTP API 触发物化** | 发布（PG 事务）与物化（图库写入）**跨系统**⇒ 同步触发会拉长事务、部分失败 ⇒ 保持「独立 Job + 显式执行」；触发 API 另立卡（D25 或后续） |
| **一次性对账脚本** | 是 D24 的产出；D23 只做「收尾核对」（写入后回读计数 vs 计划） |
| **读侧切换** | D25 |
| **业务图镜像** | 沿用 D22 §四（体量与语义都不在本批） |
| **语义关系边** | 沿用 D22 §四（manifest 无 relations 分区 ⇒ 无法自包含重建） |
| **物化失败后回滚** | Neo4j 无跨批事务；用「幂等 + 可续跑」代替回滚（D22 L-5 的处置方向） |

## 五、风险与守卫

| 风险 | 守卫 |
|---|---|
| 误写生产图库（无备份 ⇒ 不可逆） | **库层写目标闸门**（C-15）+ 脚本层 `--allow-prod-write` 显式开关（双保险，非替代） |
| 已物化的快照被覆盖（L-7） | 作业状态 = `materialized` ⇒ **默认拒写**（退出码 2）；哈希不一致（台账 vs 快照）也拒写；重建必须 `--force-rebuild` |
| 裁剪删多了 / 删少了 | `--prune --expect-delete N`；**实际将删数 ≠ N ⇒ 拒绝执行**（不「按 N 删一部分」） |
| 半份镜像被当成已发布 | 收尾核对：写入后回读节点/边计数 vs 计划；不一致 ⇒ 作业状态 `failed`、退出码 1 |
| 解析不全 ⇒ 镜像缺实体 | fail-closed：**未解析非空 ⇒ 默认拒绝物化**（退出码 2）；`--allow-partial` 才放行，且退出码 3（不报干净成功） |
| 端点缺失导致静默少写 | 镜像边端点用 MATCH；命中数 < 请求数 ⇒ 抛错（沿用 D22） |
| CQL 注入 | label 走固定映射表、relType 走白名单（沿用 D22） |
| 台账被当成「备份」 | 台账与镜像同库（图没了台账也没了）⇒ 文档明写「台账 = 现场记录，不是备份」 |
| dry-run 意外写图 | 默认 `--apply` 关闭；dry-run 分支在**任何写函数之前**返回；单测断言「写端口零调用」 |

## 六、TDD 与实现要点

### 6.1 模块切分（文件规模与职责）

| 文件 | 行数 | 职责 |
|---|---|---|
| `app/services/semantic_graph_mirror_job.py` | **723** | **编排层（IO-free）**：端口协议 + 状态机 + 批次执行 + 跳过决策 + 收尾核对 |
| `app/services/semantic_graph_mirror_ledger.py` | **87** | 台账行 ↔ 状态对象的**转换**（4 个函数，单向依赖，无环） |
| `scripts/semantic_graph_sync.py` | **405** | **唯一装配点**：把端口接到真实 PG / Neo4j；退出码契约 |
| `app/domain/semantic_graph_mirror_spec.py` | 115 | 新增 `MIRROR_JOB_BATCH_STATUS_PLANNED`（dry-run 预览态） |

> 编排层**不做 IO**：所有读写都走注入的 `MirrorJobPorts` ⇒ 单测用替身端口即可，
> 不连数据库、不连图库（与 D22 的「纯逻辑可单测」保持一致）。
> 抽出 ledger 模块的原因：job 服务一度到 **792 行**（上限 800）⇒ 转换函数单独成文件。

### 6.2 关键算法

1. **跳过决策**（`_canSkip`）：`台账 succeeded` **且** `图上计数 == 计划计数` **且**
   `manifestHash` 一致 **且** 不是 `--force-rebuild` ⇒ 才跳过；
2. **输出完好性**（`_OutputIntact`）：开工前一次性统计「图上各类节点/边数」与
   「计划各类节点/边数」⇒ 每个批次按自己的实体类型 / relType 比对；
3. **依赖失效**：本轮有节点批次真跑过 ⇒ 边批次一律不许跳过；
4. **裁剪对账**：先数「计划外的镜像节点数」⇒ 与 `--expect-delete` 不等 ⇒ 拒执行；
5. **收尾核对**：写完回读计数 vs 计划计数 ⇒ 不等 ⇒ 作业 `failed` + 退出码 1。

### 7.5 ⚠️ 真实踩坑：**台账说成功、图上东西没了 ⇒ 永远修不好**（本批最重要的发现）

**现象**：开发中手工删掉 1 个镜像属性节点（`DETACH DELETE` ⇒ 它的 `HAS_PROPERTY` 边一并消失），
台账里 `B5:HAS_PROPERTY` 仍是 `succeeded` ⇒ 续跑时**全部批次被跳过** ⇒ 图上永远是 3266/3266，
**永远修不好**（除非人知道要加 `--force-rebuild`）。这就是「台账当事实」的经典死锁。

**根因**：台账记的是「上次打算做到哪」，不是「现在图上是什么」；
两者会因人工干预 / 图被清空 / 半批失败而**不一致**。

**处置（两层）**

1. **依赖失效**：本轮真重跑了节点批次 ⇒ 边批次/裁剪批次不许跳过（端点变了边必须跟着重写）；
2. **计数为准**（根因修复）：跳过条件加一条 —— **图上该类型的计数 == 计划计数**
   （`_OutputIntact`）⇒ 台账说成功但图上缺东西 ⇒ 该批**必须重跑**。
   ⇒ 原则：**台账 = 意图，图 = 事实**。

**实证（自愈）**

```
① 手工删 1 个 ReleaseProperty 节点：
   节点 class 37 / property 3267→3266， 边 HAS_PROPERTY 3267→3266
```

### 7.6 ⚠️ 本批修的第二个真 bug：**dry-run 被「已物化」闸门挡住**

初版把「已物化 ⇒ 拒写」放在 dry-run 分支**之前** ⇒ 已物化的发布连**预览**都拿不到
（退出码 2，零信息）⇒ 运维想看「这次会怎么分批」时完全无从下手。

**根因**：闸门要保护的是**不可逆的写**，不是「看」。
**处置**：闸门移到 dry-run 分支**之后** ⇒ 只挡写、不挡看。
**实证**：已物化发布上再跑 dry-run ⇒ 退出码 0，出完整计划（3328 / 3293），图上零写入；
同一发布 `--apply`（不加 `--force-rebuild`）⇒ 仍然退出码 2。

### 7.7 幂等
