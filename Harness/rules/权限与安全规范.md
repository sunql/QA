# 权限与安全规范

## 认证（MVP 阶段）

- 当前为 Stub：`app/dependencies.py::getCurrentUser` 从 `X-User-Id` / `X-Tenant-Id` 头解析。
- 后续替换为 JWT 或 API Key 中间件，接口不变（依赖注入替换实现）。
- 所有路由默认 `Depends(getCurrentUser)`。

## 治理写入口（admin 门禁）

以下写入的是**全公司共享的治理数据**（会进入每个用户每次 NL2SQL 的 prompt / 取数口径），
因此写路由一律 `Depends(requireAdmin)`，读路由保持所有登录用户可用：

| 路由 | 守卫 |
|---|---|
| `POST/DELETE /api/v1/term-dictionary` | `requireAdmin` |
| `POST/PUT/DELETE /api/v1/ontology/metrics` | `requireAdmin` |

**chat 斜杠命令是同一批写入口**：`/metric` `/define` `/map` 在 `POST /api/v1/chat`
（只要求登录）里直调本体写服务，路由层门禁**够不着**。因此
`chat_domain._handleDomainCommand` 在分发处按 `requireAdmin` 同口径再判一次角色；
新增任何会写治理数据的 chat 意图命令，必须接入该门禁并补集成用例
（`test_chat_domain_write_gate.py`）。

新增同类写入口时，必须同步登记到 `backend/app/tests/integration/test_governance_write_route_auth.py`
的 `_WRITE_ROUTES` —— 该守卫直接构建**生产 app**（`app.main.createApp()`）检查依赖声明，
因为 API 集成测试走的是手工装配的测试 app，生产装配漏门禁时集成套件看不出来。

## 密钥管理

- **禁止硬编码** API Key、密码、Token。
- API Key 通过 `POST /api/v1/models` 提交明文，服务端用 Fernet 加密存储（`infrastructure/security/crypto.py`）。
- Fernet 密钥来自环境变量 `SECRET_KEY`，必须为合法 Fernet key（生成命令见 `docker/.env.example`）。
- 所有密钥（OPENAI_API_KEY、数据库密码等）仅通过环境变量注入，不进代码库。
- `.env` 已在 `.gitignore`，仅提交 `.env.example`。

## SQL 安全（Phase 3 核心）

业务数据源查询必须经 `app/infrastructure/security/sql_guard.py`：

- 仅允许 `SELECT`。
- 黑名单：`INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/TRUNCATE/EXEC/UNION`。
- 拒绝多语句（含 `;`）。
- 自动追加 `LIMIT`（默认 5000）。
- 连接级 `statement_timeout`。
- 拒绝 `file://` 连接 URL。
- 可选 `DATASOURCE_HOST_ALLOWLIST` 限制可连主机。
- 每次执行记录审计日志（session、datasource、SQL、耗时）。

## 数据源凭据

- `data_source` 表的连接密码用 Fernet 加密存储。
- 默认 `is_read_only=True`，禁止写回。

## 安全审查触发

涉及以下变更必须用 `security-reviewer` 审查：
- 认证/授权代码
- 用户输入处理
- 数据库查询
- 文件系统操作
- 外部 API 调用
- 加密操作
- SQL Guard 修改
