## 设计要点

- **裁决一（自包含）**：`manifest_json` JSONB NOT NULL + `manifest_hash` VARCHAR(64) NOT NULL；
  不依赖 `ontology_class.version/valid_*`（Phase 6 已移除版本管理，那些列只是兼容残留）。
- **裁决四（作用域）**：`domain_code` 可空；非空时 FK → `data_domain.code` **ON DELETE RESTRICT**。
- 三条索引各有目的：
  - `uq_semantic_release_global_version`：部分唯一（`domain_code IS NULL`），PG 唯一约束对 NULL 互不相等，必须部分索引。
  - `uq_semantic_release_one_active`：唯一表达式索引 `COALESCE(domain_code,'')`，`WHERE status='ACTIVE'`，同域最多一条 ACTIVE。
  - `ix_semantic_release_status`：按状态列举。
- `schema_version` 与发布 `version` 解耦（Schema 演进时旧快照仍可回放）。

## 评审修复（code-reviewer + security-reviewer 双审）

| 来源 | 问题 | 处置 |
|---|---|---|
| code-review MEDIUM + security LOW-6 | 「同域最多一条 ACTIVE」用例只断言 unique/where，**没钉 `COALESCE(domain_code,'')` 表达式** —— 改成裸 `domain_code` 后用例仍绿，全局作用域静默失去兜底 | 用例增加 `assert "COALESCE" in str(ix.expressions[0]).upper()` |
| security MEDIUM-1 | `status` 是无约束 VARCHAR：部分唯一索引谓词是字面量 `status='ACTIVE'`，写入 `'active'`/`'ACTIVE '` 会绕过兜底 | 迁移与 ORM 同时加 `CHECK (status IN (...))`，命名 `ck_semantic_release_status`（仓库既有约定）；新增用例钉住 |
| security MEDIUM-2 | ORM 注释称「同一作用域内唯一」，实际只保证全局（NULL）作用域 | 更正注释，写明首期仅全局；按域发布上线时再补同域版唯一索引 |
| security LOW-1 | `deleteDomain` 预检只查三处引用，新 FK 会让删除落到 IntegrityError → 裸 500 | 预检增加 `semantic_release.domain_code` 计数；新增集成用例（先 RED：实际抛 `ForeignKeyViolationError` → 500，后 GREEN：409 且文案含 `semantic_release`） |
| code-review LOW | `status` 的 ORM `server_default` 无断言（drift 只比列名不比默认值） | 用例同时断言 `col.default` 与 `col.server_default` |
| code-review LOW | `ix_semantic_release_status` 无任何用例覆盖 | 新增 `test_status_index_declared` |
| code-review LOW | `test_banned_name_is_not_exported` 属命名戏法（只能防命名偏好，防不了功能回归），docstring 还误引「裁决四」 | 删除；命名约定改由模块 docstring 记录 |
| security LOW-4/L-2/L-3/L-5 | `domain_code` 无独立索引致 FK 校验全表扫；`data_domain.code` 无非空 CHECK；FK 不管 `enabled`；`manifest_hash` 无格式 CHECK、快照无大小上限 | 记入待办，本期不处理（快照量级小、写入路径尚未存在；L-3 属 D9/D10 服务层职责） |
