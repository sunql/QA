# 部署与访问规范

> SSOT：前端发布后的访问地址适配（127.0.0.1 / localhost / 局域网 IP / 域名）。
> 2026-09-21 制定。背景：Windows 迁移部署中发现前端 bundle 烤死 `localhost:8000`，
> 换地址访问即全挂；本规范把「同源部署」定为强制架构决策。

## 一、强制：前端 API 走同源相对路径（CRITICAL）

**禁止把绝对 API 地址编译进前端 bundle。** Vite 的 `VITE_API_BASE_URL` 是
**编译期**注入，烤进 JS 后任何部署地址变化都会让浏览器连向错误的机器。

- `frontend/src/config.ts`：留空时回落到相对路径 `/api/v1`——**这是唯一认可的默认行为**
  （浏览器按「打开页面的那个地址」发请求，天然适配所有入口）。
- `docker/Dockerfile.frontend`：`ARG VITE_API_BASE_URL` 默认值**必须为空**；
  确有特殊部署要绝对地址时，显式 `--build-arg VITE_API_BASE_URL=...` 覆盖，
  并在变更记录里说明理由。
- `docker/docker-compose.yml`：frontend 服务**不得**设置运行时的
  `VITE_API_BASE_URL` 环境变量——静态构建产物读不到它，只会误导后来者。
- API 反向代理 SSOT：`docker/nginx.conf` 的 `location /api/` → `backend:8000`
  （含 `resolver 127.0.0.11` + 变量写法，防后端容器重建后 502）。修改代理路径
  必须同步 `config.ts` 的回落值。

## 二、禁止「动态探测 IP 注入配置」类方案

不得以启动脚本枚举本机 IP 再回写 nginx/CORS/前端配置：

- IP 会变（DHCP）、多网卡多 IP、内外网地址不可预知——枚举永远覆盖不全；
- 相对路径天然免疫上述全部问题，是 Web 部署标准做法；
- 唯一允许的「动态」动作：**打印**访问入口（见 §四），不写任何配置。

## 三、端口绑定与 CORS

- Docker `ports:` 默认绑 `0.0.0.0`（全网卡），即同时覆盖 127.0.0.1 /
  localhost / 局域网 IP——**这是默认且认可的行为**；仅安全加固场景才显式
  收紧绑定地址，收紧属变更，需记录。
- CORS 白名单（`backend/app/config.py` `CORS_ORIGINS`）只影响**绕过 nginx
  直连 8000** 的跨源请求；同源反代（§一）生效后前端链路不依赖它。
  为直连场景扩白名单时按 origin 精确列举，禁止 `*` + credentials 组合。

## 四、发布入口枚举（推荐）

发布/重启后应向操作者列出全部可用入口，避免「找不到对应地址」：

```bash
# scripts/show_access_urls.sh（WSL2 / macOS / Linux 通用）
echo "qa-system 访问入口："
for ip in 127.0.0.1 localhost $(hostname -I 2>/dev/null); do
  echo "  http://$ip:5173"
done
```

- `scripts/run_local.sh` 启动成功段应调用/内联该枚举。
- 正式部署验收：必须用**局域网 IP 入口**实际访问一次（不只验 localhost），
  重点确认登录 + 菜单 + 一次 API 调用成功。
