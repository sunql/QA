## 设计要点

1. **只读边界（裁决一）**：`getActive()` 只 `SELECT semantic_release`，不回查治理表、不重新编译。
   单测用源码静态守卫钉住（禁止出现 `OntologyClass` / `semantic_compiler` / `compileManifest` 等 10 个标识符），
   集成测用「编译 → 激活 → 改治理表 → 重读 → 清缓存再读」证明快照不漂移。
2. **空结果也缓存**：未发布是常态，若不缓存 `None`，每个问答都会打一次库。
3. **缓存键 = 域作用域**（`None` = 全局），与部分唯一索引 `COALESCE(domain_code,'')` 的语义对齐；
   全局快照与按域快照互不遮蔽。
4. **写时失效**：`invalidate()` 由写路径在**事务提交后**调用（D9/D10 落点）。
5. **TTL 兜底 60s**：进程内缓存感知不到其他副本 / 手工 SQL 的变更；正常路径仍是写时失效，
   TTL 只是跨进程收敛上限（`docs/deployment/06-distributed.md` 的 3 副本部署）。
6. **代数（generation）防回填竞态**：`getActive` 在 await 前记代数，回填前比对；
   期间发生过 `invalidate()` 就放弃回填 —— 否则「失效前开始的读」会把旧快照永久钉进缓存。
7. **manifest 每次访问解析私有副本**：缓存正文存规范化 JSON 字符串，`snapshot.manifest`
   每次 `json.loads` 出新 dict；不共享 ORM 实体上的可变 dict（D7b `dimensionDefaults` 同类 HIGH）。
8. **加载时校验 `manifest_hash`**：不匹配抛 `SemanticReleaseIntegrityError`（RuntimeError ⇒ 500），
   不把绕过发布路径的坏数据当语义使用。
9. **列表列白名单**：`_SUMMARY_COLUMNS` 不含 `manifest_json`（快照约 1MB，50 条就是 50MB 无效传输）。
10. **输入守卫**：`limit` 1~200、`offset` 0~1e6、`releaseId ≥ 1`、`status` 必须是
    `SemanticReleaseStatus` 枚举值、`domainCode` 长度 1~20（列宽）；缓存条目上限 16（安全阀）。

## 评审处置

两轮评审（code-reviewer / security-reviewer）结论：CRITICAL 0 / HIGH 2 / MEDIUM 若干 / LOW 若干。

| 级别 | 问题 | 处置 |
|---|---|---|
| HIGH | `manifest` 按引用共享：消费方原地改 dict 会污染进程缓存与 ORM 实体 | 缓存改存规范化 JSON 字符串，`manifest` 属性每次解析副本；单测 + 集成测各一条 |
| HIGH | 失效/并发读竞态：await 后无条件回填，可把失效前的旧行永久缓存 | 引入 `_generation`，回填前比对；原「互相覆盖无副作用」的错误说法已删除 |
| MEDIUM | 多副本部署下进程内缓存不收敛 | 加 60s TTL 兜底（写时失效仍是主路径）；跨进程广播列为后续演进 |
| MEDIUM | `listReleases` 的域筛选三态无覆盖（未覆盖行 139） | 补真实 PG 三态用例（不传 / `None` / 字符串） |
| MEDIUM | 任意 `domainCode` 可撑大缓存 | 长度校验 1~20 + 条目上限 16 安全阀 |
| MEDIUM | D9 必须对 getById/listReleases 做 admin 门禁（草稿/归档 + `created_by`/`note`） | 记入 D9 任务要求，本日不实现 API |
| LOW | getById 快照体量、status 非枚举校验、id/offset 无上界 | 后三条本日已补；体量与响应上限随 D9 一起处理 |
| LOW | 汇总列用例没钉住查询列 | 补 `_SUMMARY_COLUMN_NAMES` 断言（不含 `manifest_json`） |
| LOW | 分页文案内联、未进 `messages_zh` | 已移入 `messages_zh`（6 条） |
| LOW | 集成 conftest 未重置进程级单例 | 已在 `warmAgentCaches` 前后各加 `invalidate()` |
