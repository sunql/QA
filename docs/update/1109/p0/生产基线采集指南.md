# P0 生产基线采集指南（D1–D3，全部只读）

> 目的：在生产机上一小时内采齐日级排程 D1–D3 需要的环境与数据事实。
> **所有命令只读**：只执行 `docker ps/inspect`、`SELECT`、`MATCH`、Milvus 读接口、`alembic current`。
> **禁止**：`alembic upgrade`、任何 `INSERT/UPDATE/DELETE/DROP`、`git pull`、跑 pytest。

---

## 0. 执行前须知

1. 在生产**宿主机**（CentOS 7）执行，容器名以 `docker ps` 实际输出为准（本文按 compose 默认名：`qa-postgres` / `qa-neo4j` / `qa-milvus` / `qa-backend` / `qa-objects` / `qa-mysql-demo` / `qa-frontend`）。
2. **不要贴 `docker/.env`**。本文脚本只输出变量**名称**，不输出值；`data_source` 查询**不选密码列**。
3. 若生产机不允许执行自定义脚本，可按下文「逐项手工命令」一条条执行，结果等价。
4. 所有输出默认写到 `/tmp/qa-p0-baseline-<时间戳>/`，最后打包成一个压缩包回传。

---

## 1. 一页式采集脚本（推荐）

在宿主机执行：

```bash
vim /tmp/p0_baseline.sh    # 粘贴下面整段内容
bash /tmp/p0_baseline.sh
```

脚本内容：

```bash
#!/usr/bin/env bash
# QA P0 生产基线采集（只读）
set -u
TS=$(date +%Y%m%d-%H%M%S)
OUT="/tmp/qa-p0-baseline-$TS"
mkdir -p "$OUT" || exit 1

echo "[1/7] 主机与 Docker 版本"
{
  echo "## OS"
  cat /etc/redhat-release 2>/dev/null || cat /etc/os-release 2>/dev/null
  echo; echo "## uname"; uname -a
  echo; echo "## docker"
  docker version --format 'Client={{.Client.Version}} Server={{.Server.Version}}' 2>&1
  echo; echo "## compose"
  docker compose version 2>&1 || docker-compose version 2>&1
} > "$OUT/01-host.txt"

echo "[2/7] 容器与镜像 digest"
{
  docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
  echo
  echo "## 容器 -> 镜像 -> digest"
  for c in $(docker ps --format '{{.Names}}'); do
    img=$(docker inspect -f '{{.Config.Image}}' "$c" 2>/dev/null)
    dig=$(docker image inspect -f '{{index .RepoDigests 0}}' "$img" 2>/dev/null || true)
    printf '%-30s %-55s %s\n' "$c" "$img" "${dig:-<本地构建，无 digest>}"
  done
} > "$OUT/02-containers.txt"

echo "[3/7] PostgreSQL / Alembic / 表规模"
{
  echo "## server version"
  docker exec qa-postgres psql -U qa_user -d qa_metadata -At -c "select version();"
  echo; echo "## alembic current"
  docker exec qa-backend alembic current 2>&1
  echo; echo "## alembic heads"
  docker exec qa-backend alembic heads 2>&1
  echo; echo "## schema drift（只读，不加 --strict）"
  docker exec qa-backend python -m app.infrastructure.schema_drift 2>&1 | tail -60
  echo; echo "## 表行数估算（reltuples，前 50）"
  docker exec qa-postgres psql -U qa_user -d qa_metadata -P pager=off -c \
    "select relname, n_live_tup from pg_stat_user_tables order by n_live_tup desc limit 50;"
  echo; echo "## 关键表精确行数（60s 超时）"
  docker exec qa-postgres psql -U qa_user -d qa_metadata -P pager=off -c \
    "set statement_timeout='60s';
     select 'ontology_class' t, count(*) c from ontology_class union all
     select 'ontology_property', count(*) from ontology_property union all
     select 'ontology_relation', count(*) from ontology_relation union all
     select 'ontology_join', count(*) from ontology_join union all
     select 'ontology_metric', count(*) from ontology_metric union all
     select 'business_object', count(*) from business_object union all
     select 'data_domain', count(*) from data_domain union all
     select 'entity_mapping', count(*) from entity_mapping union all
     select 'kpi_catalog', count(*) from kpi_catalog union all
     select 'feature_definition', count(*) from feature_definition union all
     select 'document_catalog', count(*) from document_catalog union all
     select 'wiki_page', count(*) from wiki_page;"
} > "$OUT/03-postgres.txt" 2>&1

echo "[4/7] Neo4j"
{
  docker exec qa-neo4j sh -c 'PASS="${NEO4J_AUTH#*/}"; cypher-shell -u neo4j -p "$PASS" --format plain "CALL dbms.components() YIELD name, versions, edition RETURN name, versions, edition;"' 2>&1
  echo; echo "## 节点标签计数"
  docker exec qa-neo4j sh -c 'PASS="${NEO4J_AUTH#*/}"; cypher-shell -u neo4j -p "$PASS" --format plain "MATCH (n) RETURN labels(n) AS labels, count(*) AS c ORDER BY c DESC LIMIT 50;"' 2>&1
  echo; echo "## 关系类型计数"
  docker exec qa-neo4j sh -c 'PASS="${NEO4J_AUTH#*/}"; cypher-shell -u neo4j -p "$PASS" --format plain "MATCH ()-[r]->() RETURN type(r) AS rel, count(*) AS c ORDER BY c DESC LIMIT 50;"' 2>&1
  echo; echo "## APOC 可用性"
  docker exec qa-neo4j sh -c 'PASS="${NEO4J_AUTH#*/}"; cypher-shell -u neo4j -p "$PASS" --format plain "RETURN apoc.version() AS apoc;"' 2>&1
} > "$OUT/04-neo4j.txt" 2>&1

echo "[5/7] Milvus（读集合列表/数量/schema）"
docker exec -i qa-backend python - <<'PY' > "$OUT/05-milvus.txt" 2>&1
import os
from pymilvus import connections, utility, Collection

uri = os.environ.get("MILVUS_URI", "http://milvus-standalone:19530")
print("uri:", uri)
connections.connect(alias="p0", uri=uri)
names = utility.list_collections(using="p0")
print("collections:", names)
for name in names:
    c = Collection(name, using="p0")
    print("\n===", name, "===")
    print("num_entities:", c.num_entities)
    print("schema:", c.schema)
    for idx in c.indexes:
        print("index:", idx.params)
connections.disconnect("p0")
PY

echo "[6/7] 数据源清单（不含密码列）"
{
  docker exec qa-postgres psql -U qa_user -d qa_metadata -P pager=off -c \
    "select id, name, type, host, port, database_name, username, is_active, is_default, oracle_version from data_source order by id;"
} > "$OUT/06-datasources.txt" 2>&1

echo "[7/7] 外部系统连通性（按 data_source 的 host:port 逐个探测）"
{
  echo "## 连通性探测（超时 5s，仅 TCP）"
  docker exec qa-postgres psql -U qa_user -d qa_metadata -At -F' ' -c \
    "select host, port from data_source where is_active order by id" > /tmp/p0-ds-endpoints.txt
  while read -r host port; do
    [ -z "${host:-}" ] && continue
    docker exec -i qa-backend python - "$host" "$port" <<'PY'
import socket, sys
h, p = sys.argv[1], int(sys.argv[2])
try:
    s = socket.create_connection((h, p), timeout=5)
    s.close()
    print(f"{h}:{p} OK")
except Exception as e:
    print(f"{h}:{p} FAIL {type(e).__name__}: {e}")
PY
  done < /tmp/p0-ds-endpoints.txt
  echo; echo "## 后端环境变量名称（仅名称，不含值）"
  docker exec qa-backend sh -c 'env | cut -d= -f1 | sort'
} > "$OUT/07-connectivity.txt" 2>&1

tar -czf "$OUT.tar.gz" -C /tmp "$(basename "$OUT")"
echo
echo "完成。输出目录: $OUT"
echo "回传文件: $OUT.tar.gz"
```

> 说明：`docker exec` 跑 Python heredoc 必须带 `-i`，否则 stdin 不喂进去（本仓库踩过这个坑）。

## 2. 逐项手工命令（无法跑脚本时）

### 2.1 Docker / Compose 版本（D1）

```bash
docker version --format 'Client={{.Client.Version}} Server={{.Server.Version}}'
docker compose version || docker-compose version
```

**判读**：

| 输出 | 结论 |
|---|---|
| Compose ≥ 2.24（v2 插件） | 现有 `docker-compose.centos.yml`（`!override` + `profiles`）可直接用 |
| Compose 1.29.x（v1 二进制） | **现场实测即此分支**：生产用 `/opt/qa-system/docker/docker-compose.centos7.yml`（v1 兼容）+ 离线镜像；仓库 overlay 不可用 |

### 2.2 镜像与 digest（D1）

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
docker inspect -f '{{.Config.Image}}' qa-backend
docker image inspect -f '{{index .RepoDigests 0}}' postgres:16-alpine
```

本地构建的 `qa-system-backend` / `qa-system-frontend` / worker 没有 RepoDigest 属正常，记录镜像 ID 即可：

```bash
docker inspect -f '{{.Image}}' qa-backend
```

### 2.3 Alembic 状态（D2）

```bash
docker exec qa-backend alembic current
docker exec qa-backend alembic heads
```

**判读**：两者一致即无待执行迁移。合并 0141 之前，生产预期停在 `0140`。若 `current` 落后 `heads`，记录差距即可，**不要在生产执行 upgrade**（0141 需单独评审）。

### 2.4 Schema 漂移（D2，只读）

```bash
docker exec qa-backend python -m app.infrastructure.schema_drift | tail -60
```

**判读**：记录 `[db:*]` / `[orm:*]` 条数。不加 `--strict`，不会改变任何状态。

### 2.5 表规模（D2）

```bash
docker exec qa-postgres psql -U qa_user -d qa_metadata -P pager=off -c \
  "select relname, n_live_tup from pg_stat_user_tables order by n_live_tup desc limit 50;"
```

精确行数（大表先看估算，避免长事务）：

```bash
docker exec qa-postgres psql -U qa_user -d qa_metadata -P pager=off -c \
  "set statement_timeout='60s';
   select 'ontology_class' t, count(*) c from ontology_class union all
   select 'business_object', count(*) from business_object union all
   select 'entity_mapping', count(*) from entity_mapping union all
   select 'document_catalog', count(*) from document_catalog;"
```

> 若某表 `n_live_tup` 超过千万级，精确 `count(*)` 可能超时——脚本里的 `statement_timeout='60s'` 会中断而不是拖死库。

### 2.6 Neo4j 现状（D2）

```bash
# 版本
docker exec qa-neo4j sh -c 'PASS="${NEO4J_AUTH#*/}"; cypher-shell -u neo4j -p "$PASS" "CALL dbms.components() YIELD name, versions RETURN name, versions;"'

# 标签计数
docker exec qa-neo4j sh -c 'PASS="${NEO4J_AUTH#*/}"; cypher-shell -u neo4j -p "$PASS" "MATCH (n) RETURN labels(n) AS labels, count(*) AS c ORDER BY c DESC LIMIT 50;"'

# 关系计数
docker exec qa-neo4j sh -c 'PASS="${NEO4J_AUTH#*/}"; cypher-shell -u neo4j -p "$PASS" "MATCH ()-[r]->() RETURN type(r) AS rel, count(*) AS c ORDER BY c DESC LIMIT 50;"'
```

**判读**：`Class/Property/Metric` 是本体图；业务图标签（`BUSINESS_ENTITY_LABELS` 集合）若计数为 0，说明业务图未回填（历史上出现过「子图为空导致 404」）。APOC 已随 compose 启用（`NEO4J_PLUGINS=["apoc"]`），但 **GDS 未安装**，不要设计依赖 GDS 的算法。

### 2.7 Milvus 现状（D2）

```bash
docker exec -i qa-backend python - <<'PY'
import os
from pymilvus import connections, utility, Collection
connections.connect(alias="p0", uri=os.environ.get("MILVUS_URI", "http://milvus-standalone:19530"))
for name in utility.list_collections(using="p0"):
    c = Collection(name, using="p0")
    print(name, "num_entities=", c.num_entities)
    print("  schema:", c.schema)
    for idx in c.indexes:
        print("  index:", idx.params)
connections.disconnect("p0")
PY
```

**判读**（2026-11-09 实测）：实际是 **5 个按类型拆分的集合**——`ontology_class_embeddings`(98) / `ontology_property_embeddings`(6,887) / `ontology_metric_embeddings`(5) / `query_embeddings`(86) / `wiki_page_embeddings`(4)；`document_embeddings` 未创建（懒创建，文档数为 0）。**全部 `enable_dynamic_field=false`、无域/实体/有效期字段** ⇒ P3a 采用「新集合 + 全量回填」，不再试探改字段。
**注意**：生产 19530 是线上库，只读列表/计数；**不要在生产跑任何测试或写操作**。

### 2.8 数据源与外部系统（D2）

```bash
docker exec qa-postgres psql -U qa_user -d qa_metadata -P pager=off -c \
  "select id, name, type, host, port, database_name, username, is_active, is_default, oracle_version from data_source order by id;"
```

不选 `password_encrypted`，不会泄漏凭据。**判读**：`type` 区分 Oracle/MySQL/PostgreSQL 等；ERP/SRM/OA/合同系统若是数据库直连，会出现在这里；若是 HTTP 接口，需要业务方提供 URL。

HTTP 接口探测模板（替换为实际地址）：

```bash
docker exec qa-backend sh -c 'curl -k -s -o /dev/null -w "%{http_code} %{time_total}s\n" -m 5 https://<erp-host>/<health-path>'
```

### 2.9 环境变量名称（D2，仅名称）

```bash
docker exec qa-backend sh -c 'env | cut -d= -f1 | sort'
```

用于确认 `DATABASE_URL` / `NEO4J_URI` / `MILVUS_URI` / 开关名是否按 `.env.example` 注入；**不要输出值**。
