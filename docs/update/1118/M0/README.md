## 5 · M0 的 DoD（引自落地计划）

1. 本地 **6** 个开关全开，冒烟全过；**任一开关关闭时，对应能力的行为差异有明确用例**（双向断言）。
2. G3 从「3 过 1 不过」变 **4/4 过**（分层判据见 M0.4 §4.5）。
3. 12 条 KPI 归因清单产出：**0 条「口径未定义」**。
4. 4 份问卷发出且回收 **≥3 份**；回收内容落 `M0/业务问卷/E-回收登记.md`。
5. `alembic check` 绿；upgrade→downgrade→upgrade 往返绿。

> **回收率不足 3 份 ⇒ M5 / M6 不启动**（准则 C 修正版，2026-11-18）。**M1 / M2 / M2′ / M3 / M4 照常推进**（只需"部分答案 + 降级"）；仅当回收 **≤1 份** 才触发整体重排。
> ⇒ 配套的**并行轨**（回收窗口期间做什么）见 [`../智能采购平台_V0.3落地实施计划_并行轨与汇合点_1118.md`](../智能采购平台_V0.3落地实施计划_并行轨与汇合点_1118.md)。

## 7 · 回收窗口不是等待期（并行轨）

**问卷发出后、回收回来之前，工程轨不停。**
⇒ 详细计划见 [`../智能采购平台_V0.3落地实施计划_并行轨与汇合点_1118.md`](../智能采购平台_V0.3落地实施计划_并行轨与汇合点_1118.md)。

摘要：

| | 内容 |
|---|---|
| **轨 A（工程）** | A1 本地栈同构 / A2 开关落地 / A3 判据书定稿 / A4 渲染顺序统一 / A5 答案级评估器 / A6 KPI 归因 / A7 口径**槽位**模板 / A8 源绑定**候选** |
| **轨 B（问卷）** | 发出顺序 **A → C → D → B**（按"卡的工作包最大 & 最早"排，不按好答程度排） |
| **汇合点 G1** | 逐题登记 → 答案填槽 → 候选确认 → 口径注入 → 未答降级 → 按实际回收质量重排 |
| **三条硬纪律** | ① 口径**不写死**（只做槽位）② **候选 ≠ 结论**（不进生产）③ **禁伪并行**（没有验收包不算进行中） |

> **产能对照**：回收窗口 1 周 ≈ 12–15 人日 ≈ 轨 A 的 A1–A7（10.5–16.5 人日）⇒ **M0 恰好在回收回来之前做完**，两条线在窗口末尾汇合。
