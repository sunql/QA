## API 契约

| 端点 | 行为 |
|---|---|
| `POST /api/v1/semantic/releases` | 从当前治理表编译 DRAFT。`version` 必填 1~32 字符；可选 `domainCode`（须存在）/ `note`。**允许带阻断项落库**，响应 `blockers` 即预览 |
| `POST /{releaseId}/validate` | DRAFT → VALIDATED。完整性 → Schema → 闸门全部通过才放行；阻断项非空 ⇒ 409 |
| `POST /{releaseId}/activate` | VALIDATED → ACTIVE。同作用域原 ACTIVE 在同一事务里归档；并发撞唯一索引 ⇒ 409 |
| `POST /{releaseId}/archive` | ACTIVE → ARCHIVED。终态；回滚 = 重新激活历史快照的副本 |

写操作统一返回 `{release, blockers, warnings}`；`blockers` 只在 createDraft 可能非空（DRAFT 预览）。

## 设计要点

1. **状态机双保险**：服务层 `_ALLOWED_TRANSITIONS` 把非法迁移变成 409 领域错误；库侧
   `ck_semantic_release_status` 与 `uq_semantic_release_one_active` 兜底。ARCHIVED 是终态 ——
   把它改回 ACTIVE 会让审计里的历史状态失去意义，回滚语义是「激活一份历史快照的副本」。
2. **闸门分级（D07）**：`sources` 为空 → 告警（治理债要显式暴露）；`status=PUBLISHED` 的
   RATIO/DIFFERENCE 缺分子/分母落点 → 阻断；DRAFT 指标同型问题 → 仅告警。当前治理库 12 条指标
   全是 DRAFT，首个快照不会被卡住，但评审预览必须列出无源/无落点清单。报告封顶 20 条。
3. **激活是「顶替」不是「并存」**：`_lockActivesInScope` 先 `SELECT … FOR UPDATE` 锁住同作用域
   其他 ACTIVE，逐条归档后再把目标置 ACTIVE，全部同一事务。全局（`domain_code IS NULL`）与
   按域互不影响；部分唯一索引是并发下的最后一道闸，撞上翻译成 409 而不是 500。
   **归档与激活之间必须显式 `flush()`**：SQLAlchemy 的 unit of work 按主键排序发送 UPDATE，
   当目标是更小 id（回滚到历史版本）时会先发 `目标→ACTIVE` 再发 `旧版→ARCHIVED`，
   瞬时两条 ACTIVE 撞 `uq_semantic_release_one_active`，合法回滚被误报成并发冲突。
   这由 `test_activation_can_roll_back_to_an_older_release` 钉住（变异 D 取证）。
4. **状态迁移串行化**：`_lockRelease` 用 `SELECT … FOR UPDATE`，两个请求不会同时看到 DRAFT。
5. **审计同事务**：每次迁移 `AuditService().record(...)`（CREATE 只带 after，UPDATE 带 before+after，
   payload = status/version/domainCode）。审计写失败则整体回滚 —— 治理动作必须留痕。
6. **写时失效顺序**：`semanticRegistry.invalidate()` 只在 `commit()` 成功之后调用；提交前失效会被
   并发读把旧行重新回填缓存（D8 代数守卫的反面）。validate 不失效：VALIDATED 不被读路径服务。
7. **体量在写路径更早拒绝**：`compileManifest` → `validateManifest` → 规范化 JSON 字节数 >
   `MAX_MANIFEST_BYTES`（4MB）⇒ 422，异常快照根本不落库（读路径的上限只是兜底）。
8. **撞库翻译**：`IntegrityError` 的 sqlstate `23503` → 422（域不存在），其余 `23505` → 409
   （版本冲突），任何情况下都不漏成未分类 500。
9. **本日修正的自身缺陷（评审前自测抓出）**：`evaluatePublishGate` 最初不区分指标类型，
   把 `MEASURE` 也按「缺落点」硬拒绝；且对 MEASURE 报「分母缺落点」是纯噪音。
   已改为分母只对 RATIO/DIFFERENCE 检查，硬拒绝只对 `PUBLISHED` + RATIO/DIFFERENCE 生效。
10. **身份字段先于编译校验**：`actor` 1~64、`actor_departments` 拼接后 ≤500（审计列宽）。
    超宽若交给 asyncpg 会变成 `DataError` 500，且发生在一次 ~1MB 编译之后；改为入口即 422。
11. **版本冲突提前判**：`createDraft` 在编译前先查一次同版（全局）存在性 → 409；
    库侧 `uq_semantic_release_global_version` 仍是并发下的最终裁决（`IntegrityError` 翻译兜底）。
12. **日志不留注入面**：版本号按 `%r` 输出（外部可控字符串不拼进格式化模板）。

## 风险与遗留

- 生产仍在 alembic **0140**；`0141/0142` 未部署。本日**不部署**。
- **按域版本唯一性没有库侧约束**：`uq_semantic_release_global_version` 只覆盖
  `domain_code IS NULL`（迁移 0142 的既定设计，模型注释已预告「按域发布上线时再补同域版唯一索引」）。
  服务层不做非原子的应用级去重 —— 非全局域目前只是预留能力。补索引须随迁移单独评审。
- 每次 createDraft 都要 `compileManifest`（~1MB）；已由 admin 门禁 + rate limit 约束，暂不缓存编译产物。
- 读路径未审计（沿用 D9 遗留）。
- `note` 长度由 Pydantic 限制 2000，库列是 TEXT —— 故意比库更严，防止公告式长文进治理表。
- **鉴权 fail-soft（评审 #3，未改）**：非生产环境下 stub 用户可带 admin 角色。与 D9 同口径；
  收紧属跨特性策略变更，需连同全部 stub 夹具一起改，另行立项。
- **完整性异常保持 500（评审 #5，未改）**：篡改快照 fail-closed；服务端记详日志，不伪装 4xx。
- **路由探测器版本差异（评审 #4，已修）**：FastAPI ≥0.141（`uv.lock` 锁 0.141.1）把
  `include_router(dependencies=…)` 放进 `include_context`，不并入 `route.dependant`；
  0.136.x 会并入。本守卫两条路径都覆盖，并已分别实测 6 passed。**本地 venv 仍是 0.136.1，
  与 `uv.lock` 不一致** —— 这是环境债，但不构成升级理由（升级属被禁事项），
  只要求：涉及路由装配的改动必须按锁版本隔离复测。
- 集成用例依赖 `qa_metadata_test_semantic` 的治理表种子；`createDraft` 每次真编译（~1MB），
  用例总量增加后套件耗时上升（当前 4 文件 ~61s，全语义面 ~146s）。
