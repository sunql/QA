#### 4.1 A8 Q6 的口径更新：**收货 / 请购的 ODS 入口类不必补**

A8 §7 曾建议「M1-1.4 补类」：`ODS_PRECEIPT` / `ODS_PRECEIPTD` / `ODS_PREQUISO` /
`ODS_PREQUISD` / `ODS_PQUOTATD`（收货 / 请购的 ODS 层，本体完全没建）。
**本批不补**，理由三条：

1. **该建议写于 M0，当时还没有绑定表** ⇒ 现在的 **D2 两张表设计**（`procurement_source_binding`）
   里 `source_table` 的注释就是「**物理表名（可 ≠ class_name）**」⇒
   收货 / 请购的类**可以直接绑到 ODS 物理表**，**不需要**为每张 ODS 表造一个同名类；
2. **41 类绑定范围（34 + 复活 7）里不含这 5 个类**（它们只出现在 A8 证据 §E 的「未建模表」清单里）
   ⇒ **没有消费方** ⇒ 建出来是**孤儿类**（活跃本体里多 5 个无人引用的类）；
3. V0.3 §3.2 的 10 个对象里，收货 / 请购**已经各有 DWD 级类**（`DWD_GOODS_RECEIPT_DTL` /
   `DWD_PURCHASE_REQUISITION_LINE`）⇒ 对象覆盖度**不缺**。

⇒ **A8 Q6 的默认处置在此更新为「不补类」**；若将来业务要求「收货 / 请购必须从 ODS 层取数」，
则走 **M1-b 绑定**（在绑定表里把收货类的 `source_table` 指到 `ODS_PRECEIPT`），
**不改本体**。

## 5. 为什么必须「复活墓碑类」（**这是本批的技术核心**）

`ontology_metric_source` 用 **class_id** 引用本体类；编译器遇到**墓碑类**的源引用
会**整条丢弃**（`semantic_compiler_sections.groupMetricSources`）⇒ 后果有两条：

1. **静默口径漂移**：指标只剩一半口径
   （OTD 只剩分母、三单匹配只剩 FILTER）⇒ 指标算出来**看着有值、其实是残缺的**；
2. **采购域切片里一个采购 KPI 都到不了**：指标按类锚定
   （`targetClassName` / `sources[].className`），类没了 ⇒ 指标归不了属 ⇒ 被 fail-closed 排除。

**实测（开发库 5433，补齐前）**：`ontology_metric_source` 共 **18 行**，
编译后**只保留 3 行** ⇒ **被丢弃 15 条**；**9 个采购指标**里有 **9 个** `sources` 为空
⇒ 采购域切片只剩 **1 个指标 / 1 个 KPI**（`KPI_SUPPLIER_MAINTENANCE_RATIO`，
锚点是活跃类 `DIM_SUPPLIER`）。

**复活必须「原地」做**（清 `valid_to`）：若改成新建 v2 行，`class_id` 会变，
指标源仍指向旧 id ⇒ 照样被丢弃（**换汤不换药**）。

| **D-12** | **CONTRACT 明确不建**，替代承载面 = 文档目录 | 源缺口（表不存在 + 业务确认「没有」）⇒ V0.3 明写「不虚构源表」；建一个无源的类会让「有类 = 有数据」的错觉成立 ⇒ 比不建更坏 |
| **D-13** | **墓碑类原地复活**（清 `valid_to`），不新建 v2 行 | 指标源按 `class_id` 引用 ⇒ 换行 = 换 id = 口径照样丢；原地复活保持 `class_id` 不变 |
| **D-14** | **补 4 个 BO**（PR / QUOT / POL / PAY），BO 码取 `docs/data-knowledge/采购域.md` 目录 | 域归属**只**由 `business_object.primary_domain_id` 承担 ⇒ 缺 BO ⇒ 域切片拿不到该对象；BO 码沿用既有目录，避免两套命名 |
| **D-15** | **BO `INVOICE` 改指** `DWD_AP_INVOICE_DTL` → `DWD_PURCHASE_INVOICE` | 现头类是 46 行的文件抽取旁表（`FILE_*` 属性、两个月时间跨度）⇒ 与 V0.3「发票金额、税额、订单/收货匹配关系」完全对不上 |
| **D-16** | **补 `POL`（采购订单行）BO**，而不是把 `PO` 改指到订单行 | `uq_business_object_header_class` 决定「一个类只能挂一个 BO」⇒ 补 POL 与改指 PO **只能取一**；取补 POL（与 `采购域.md` 目录一致），`PO` 仍指宽表 `DWD_PURCHASE_ORDER_DTL` |
