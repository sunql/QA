## 1. 需求

P1a/P1b 已交付「语义发布 = 语义的自包含快照」，但**没有任何生产消费方**。P2 让它第一次真正作用于问答：

1. **影子接入**：NL2SQL 的 schema 文本改由**已发布快照**渲染（D12 适配器 / D13 影子比对 / D14 零差异判据）；
2. **接线闸门**：schema 文本走**唯一出口**，开关默认关、关态逐字节等于今天，快照缺事实必须「响」且不许炸问答（D15）；
3. **发布钉住**：运行记录记住「这一轮用哪一版渲染」，下一轮钉住它 ⇒ 同一会话的重放读同一版（D16）；
4. **切换演练**：两态回放同一批问题，量化「开闸会不会改变回答」，并给出生产开闸的前置条件（D17）。

验收（G3，1109 排程原文）：**影子差异 0；切换前后回放结果一致；SQL Guard 链原样；开关可秒级回落**。

**关键设计**（细节在各日证据）：

- **闸门是唯一权威**：`SchemaRenderResult(text, semanticReleaseId, pinInvalidated)`。id 为 `None` = 本轮没走快照 ⇒ **不许记账**；
  `pinInvalidated=True` = 尝试过钉住但没用上 ⇒ 运行记录**清空**钉住（死钉自愈）。
- **写侧三态**：给了 id ⇒ 覆盖；`None` ⇒ 保留；`pinInvalidated` ⇒ 清空。
- **事实守卫按钉住分叉**（偏差 ⑭）：未钉住路径 = 「不一致 ⇒ ERROR + 降级直读」；已钉住路径 = 「只做自完整性校验，差异记 WARNING、不降级」（钉住的语义就是「明知与当前本体有差异，仍按那一版作答」）。
- **降级不抛异常**（偏差 ⑪，已结案）：坏快照不许炸问答，但绝不静默。

## 4. G3 判定（3 过 1 不过）

| # | 判据 | 实测 | 判定 |
|---|---|---|---|
| 1 | 影子差异 0 | 两态 602 / 602 行，按块行多重集 **差异块 0** | ✅ |
| 2 | 切换前后回放结果一致 | 同态重复逐字相同 ⇒ 抖动为 0；跨态**实质性不同**（OFF 带 `ENAFLG_0 = 2` / `TCLCOD_0 IN (...)`；ON 丢了 `DIM_IMATERIAL` 的 JOIN 与这两条口径） | **❌** |
| 3 | SQL Guard 链原样 | 8 条真实 SQL 全过；`DELETE` 两态均被拒 | ✅ |
| 4 | 开关可秒级回落 | 进程内 **0.8 ms**；生产 = 改 env + 重启（秒级），无镜像重建、无 DDL 回滚 | ✅ |

**根因**（[D17 §4](./daily/D17.md)）：编译器对 manifest 显式排序（属性按 `propertyName`、JOIN 按 `joinKey`，
为字节确定性），直读走 ORM 物理行序 ⇒ 两侧内容相等、顺序必然不同 ⇒ prompt 不同 ⇒ 模型对行序敏感 ⇒ **计划与 SQL 都变**。

**为什么不能「把快照侧改成直读顺序」**：`Test顺序确定性` 钉死了相反原则 —— 快照顺序必须由 manifest 决定，
否则同一版发布在不同机器/时间渲染不同 ⇒ **D16 的钉住重放塌掉**。而直读侧顺序本身不是契约（关系无 `ORDER BY`）。

**负责人裁决（2026-11-15）**：不改代码，**如实登记 G3 第 2 条 ❌**。
⇒ **生产打开开关前置条件**：
1. **答案级影子评估**（同一批业务问题 OFF/ON 对照，评估结果集与口径变化）；
2. 就「是否让两侧统一渲染顺序」**再拍板一次**（那会是独立一次发版，会改变今天关态的 prompt 与回答）。

> **本演练否证了一条推论**：「schema 内容等价 ⇒ 开闸无影响」。后续评审不得再据此判定开闸安全。
> **局限**：演练模型是本地 27B（Qwen3.8-27B-4bit），非生产 DeepSeek ⇒ 证的是机制，不能定量预测生产漂移幅度。
