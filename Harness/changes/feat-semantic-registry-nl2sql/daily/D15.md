## 1. 做了什么

### 1.1 新增：闸门模块 `app/services/semantic_schema_gate.py`

唯一职责：**把「要不要用快照」这件事收敛到一个出口**，并在该出口上做完整性守卫。

```
renderSchemaText(classes, joins, *, session, **renderParams) -> str
```

| 分支 | 行为 | 与今天的关系 |
|---|---|---|
| 开关 **关** | 直接 `buildSchemaText(classes, joins=joins, **renderParams)` | **逐字节一致**（同一函数、同一入参、同一顺序） |
| 开关开 + **会话缺席** | 同上，**且不查快照**（见 §2.1） | 逐字节一致 |
| 开关开 + **无 ACTIVE 快照** | 同上（适配器原样返回治理表对象） | 逐字节一致 |
| 开关开 + 快照**新鲜** | 渲染**快照侧**文本 | 事实等价，**顺序**按快照（D14 已知差异：类内列序 / JOIN 条目序） |
| 开关开 + 快照**缺/多/改事实** | **拒绝用快照**：ERROR 日志 + 降级直读 | 逐字节等于今天的直读文本（**不喂错事实给模型**） |
| 开关开 + 取快照**抛异常 / 快照畸形** | 降级直读（**不抛**） | 逐字节等于今天 |

**为什么守卫用「渲染后按块比行多重集」，而不是逐字段比**：
D14 已把「零差异」定稿成**内容等价 = 0**（逐类块比行多重集）。守卫直接复用**同一判据**
⇒ 影子比对与运行时守卫**同一把尺子**，不会出现「比对说等价、运行时说有缺口」的双口径。
它同时能抓到**值层面的漂移**（描述改了、类型改了、JOIN 边没了），而逐字段比会漏。

**为什么这个判据不会误报（顺序无关）**：
- 渲染器对类块按 `(class_name, id)` 拓扑排序 ⇒ 两侧块序一致；
- 关键列摘要按 `(class_name, property_name)` 排序 ⇒ 块内摘要顺序无关；
- 孤岛表 / JOIN 图都是集合语义 ⇒ 顺序无关。
⇒ 只有「事实本身不同」才会被判成缺口。实测（§4.2）差异 **0**。

## 6. ⚠️ 偏差 ⑪：任务卡的「报错」被实现成「降级 + ERROR 日志」

| 项 | 内容 |
|---|---|
| 任务卡原文 | 反向守卫：开关开但快照缺字段 ⇒ **报错**而非静默降级 |
| 本实现 | **降级为直读治理表 + `logger.error` + 显式告警**，**不抛异常** |
| 为什么 | ① **P0 裁决一「坏快照不许炸问答」**：抛异常会让「快照陈旧」这种**发布节奏的常态**直接打断线上问答（快照落后于治理表是常态，不是事故）；② 本仓最忌讳的失败模式是**静默降级**——本实现**不静默**（ERROR 级 + 降级方向明确）；③ 降级方向是**保守**的：用**更完整**的直读事实，而不是用缺字段的快照 |
| 风险 | 事实缺口**不会**中断问答 ⇒ 现场可能长时间不知情（依赖 ERROR 日志/告警被看到） |
| 需要的决策 | 是否要「抛异常 / 上报指标 / 页面提示」作为**第二档**（如：缺口连续出现 N 次 ⇒ 告警升级） |

> 本条**登记为偏差 ⑪**，随 D17 一并提交负责人拍板。P2 不部署生产 ⇒ 现阶段无生产影响面。
