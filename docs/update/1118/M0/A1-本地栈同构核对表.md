## 1 · 为什么需要这张表

「本地全绿」判据书里，**判据 2（回归）** 用「失败集合对差，净新增 = 0」作判据。
这条判据的**前提**是「本地与 CI 跑的是同一套栈」——不同构 ⇒ 两侧 verdict 不可比 ⇒
「本地全绿」这个结论本身不成立。

2026-11-18 A1 实测到 **3 处不同构**，每一处都能单独制造假绿/假红：

| # | 不同构 | 后果（实测） |
|---|---|---|
| **D1** | **测试库落错**：不设 `TEST_DATABASE_URL` 时，`resolveTestDatabaseUrl()` 只改 `DATABASE_URL` 的**库名**、**端口原样保留** ⇒ 本地落到 `5433/qa_metadata_test`（实测停在 **0139**，schema 缺列） | `_ensureSchema()` 里的 `alembic upgrade head` 抛 `DuplicateColumnError` ⇒ **整套测试跑不起来**（连纯 unit 都 ERROR，因为 unit 的 conftest 也会建引擎） |
| **D2** | **测试代码读开发库**：读 `settings.databaseUrl` 的测试，本地 = 开发库 `5433/qa_metadata`、CI = 测试库 `5434/qa_metadata_test` | 同一份代码在两处给**两个不同 verdict**（本地绿 / CI 红，或反之）—— 2026-11-18 实测有 **5 处**自建引擎的测试全落在这条缝里 |
| **D3** | **本体类物理表绑定分叉**：迁移 `0039`/`0040` 与 `seed_ontology.CLASSES` 对同一 `class_name` 写不同 `source_table`（DWD_* 词表 vs ERP 词表） | ① NL2SQL 指向**不存在的表**；② 干净库上 `seed_ontology.seed()` **直接崩**（`uq_ontology_class_name_version` 违例）；③ 测试夹具种子分叉 ⇒ verdict 取决于夹具顺序 |

## 4 · 判据 1（迁移）的执行库与命令

**⚠️ 必须在**干净 probe 库**上跑 `alembic check`** —— 共享测试库会被测试期创建的
sandbox 表污染（例如 `po_lines_sandbox`），ORM metadata 里没有它 ⇒ `alembic check`
报 `remove_table` ⇒ **判据 1 假红**。

```bash
cd backend

# 1) 建一次性 probe 库（只碰这个库，不碰 qa_metadata_test）
docker exec qa-pg-a1 psql -U qa_user -d postgres \
  -c "DROP DATABASE IF EXISTS qa_metadata_test_probe" \
  -c "CREATE DATABASE qa_metadata_test_probe"

# 2) 迁移链全量跑到底（alembic/env.py 只读 DATABASE_URL）
export DATABASE_URL='postgresql+asyncpg://qa_user:<pwd>@localhost:5434/qa_metadata_test_probe'
uv run alembic upgrade head
uv run alembic current          # 期望 0153 (head)
uv run alembic check             # 期望 "No new upgrade operations detected."
uv run alembic downgrade -1 && uv run alembic upgrade head   # 往返
uv run python scripts/check_schema_drift.py --database-url "$DATABASE_URL"
```

**2026-11-18 实测结果（判据 1 全绿）**：

| 检查 | 结果 |
|---|---|
| `alembic upgrade head` | `0152 -> 0153` ✅ |
| `alembic current` | `0153 (head)` ✅ |
| `alembic check` | `No new upgrade operations detected.`（exit 0）✅ |
| `downgrade -1` → `upgrade head` 往返 | `0153 -> 0152 -> 0153 (head)` ✅ |
| `check_schema_drift.py` | `Schema drift 检查通过：ORM 与 DB 一致（表 / 列 / 索引）。`（exit 0）✅ |

## 5 · 重建测试库的正确命令

> ⚠️ **不要**用 `docker compose ... down -v` 或删 `qa-pg-a1` 容器来「重置测试库」——
> 那会连带干掉同容器上的 42 个库（含别的特性线还在用的 scratch 库）。

```bash
# 1) 只重建 SSOT 测试库（名字必须匹配白名单 ^qa_metadata_test($|_)）
docker exec qa-pg-a1 psql -U qa_user -d postgres \
  -c "DROP DATABASE IF EXISTS qa_metadata_test" \
  -c "CREATE DATABASE qa_metadata_test"

# 2) 迁移链拉满
cd backend
export DATABASE_URL='postgresql+asyncpg://qa_user:<pwd>@localhost:5434/qa_metadata_test'
uv run alembic upgrade head

# 3) 跑测试（会自动补 schema：_ensureSchema() 幂等 upgrade head）
./scripts/run_local_tests.sh
```

## 6 · 同构处置与防回退守卫

| 不同构 | 处置 | 防回退 |
|---|---|---|
| **D1 测试库落错** | 新增 **`scripts/run_local_tests.sh`** —— 本地跑后端测试的**唯一入口**，一次性接线三个测试依赖（PG 5434 / Neo4j 7688 / Milvus `qa_test`）+ 端口可达性前置检查 | 脚本自身即入口；文档与本表指向它 |
| **D2 测试代码读开发库** | ① `backend/app/tests/conftest.py`：显式给了 `TEST_DATABASE_URL` 就让 `DATABASE_URL` 跟它对齐；② 5 个自建引擎的测试改走 `app.tests._pg_support._newEngine()`（含 `assertTestDatabase()` 白名单 + `_ensureSchema()`） | **`backend/app/tests/unit/test_test_db_url_guard.py`** —— 源码级 AST 守卫 R1–R4（见 §6.1） |
| **D3 本体类绑定分叉** | ① 新增**数据迁移 `0153`**（无 DDL ⇒ `alembic check`/drift 不受影响）把 5 个采购域类的 `source_table` 校准到 ERP 词表；② `seed_ontology._seedClasses` 复用路径补齐 `class_alias`/`description` 回写 | **`backend/scripts/procurement_class_source_table_realdata.py`** —— 干净库门禁（建临时库 → 真跑迁移链 → 断言 5 个绑定 + 反向断言无 `DWD_*` 残留 → 跑 `_seedClasses` 断言复用不崩 → 删库） |

### 6.1 守卫 R1–R4（`test_test_db_url_guard.py`）

| 规则 | 内容 | 抓什么 |
|---|---|---|
| **R1** | `create_async_engine(...)` 的实参（位置**或** `url=` 关键字）不得是字符串字面量 | 直接内联 DSN |
| **R2** | 模块内**任意作用域**若定义「值含 postgres DSN」的常量，则该模块不得调用 `create_async_engine` | R1 抓不到的「常量 + 变量传参」形态（含函数内常量） |
| **R3** | 测试代码不得出现 `.databaseUrl` 属性访问 | 读 `settings.databaseUrl` ⇒ 本地/CI verdict 分叉 |
| **R4** | 字符串字面量不得同时含 `5433` 与 `qa_metadata_test` | 已退役的「旧端口 + 测试库名」组合 |

全部 **AST 判定**（不用正则：正则会被自己写的注释/docstring 命中 ⇒ 假红），
且**每条规则都有正向样本**（空集假绿防护）+ 反向样本（不误伤样本 DSN 字符串）。
扫描集另有**空集硬保护**：`_testSources()` 要求「≥100 个 .py」且 `conftest.py` 在集内
（目录被挪 / 路径拼错时 `rglob` 返回空且不报错 ⇒ 「0 违规」会恒通过）。

### 6.2 测试库双白名单（`assertTestDatabase()`）

只校验**库名**是不够的：夹具每用例 `TRUNCATE ... CASCADE`、`_ensureSchema()` 还要跑
alembic DDL ⇒ 远端/共享 PG 上若恰好有同名 `qa_metadata_test*` 库，只凭库名会放行。
故闸门有两条：

1. **库名** `^qa_metadata_test($|_)`（含 `_probe`/`_purcclass` 等派生库）；
2. **主机必须是回环地址**（`""` / `localhost` / `127.0.0.1` / `::1`）；
   确需连远端测试实例须**显式** `QA_TEST_DB_ALLOW_REMOTE=1`。

`resolveTestDatabaseUrl()` 的「只改写库名」分支**改写后再过一次**双白名单
（否则「生产主机 + 测试库名」这种组合会漏过去）。
