
# QA 系统代码审查

审查版本：`fabd487ded3b7721f645a8c48250936dd18ff638`。

范围：FastAPI 身份认证、模型配置、数据源管理、文档上传与检索、模型客户端缓存、限流，以及 React 登录和错误处理。没有修改仓库源码、依赖声明或锁文件。

验证方式：使用单独的 PostgreSQL 16 容器和 `qa_metadata_test`，通过 Alembic 迁移到 0104；使用真实 `app.main.createApp()` 的 HTTP 路由和真实数据库复现认证/配置问题。该复现不运行应用 lifespan，不验证整套服务启动。模型 SDK 仅使用合成测试值构造客户端，没有发送模型请求或使用真实凭据。另运行已有 19 个后端集成测试和 2 个临时前端拦截器复现检查。

以下“已复现”表示观察到了当前错误行为，临时检查通过不表示相关功能没有缺陷。“代码证据”表示尚未做对应完整服务验证。

## 1. 高：普通用户可以管理全局模型配置，并存在凭据外发风险

- 位置：[model_config.py](/workspace/QA/backend/app/api/v1/model_config.py:21)、[model_config_service.py](/workspace/QA/backend/app/services/model_config_service.py:69)、[factory.py](/workspace/QA/backend/app/infrastructure/llm/factory.py:104)、[openai_client.py](/workspace/QA/backend/app/infrastructure/llm/openai_client.py:103)。
- 已复现：`AUTH_MODE=real` 下，一个没有任何角色的真实登录用户访问用户管理返回 403，却能创建模型配置（201）和修改配置（200）。模型路由只要求登录，service 也没有管理权限检查。
- 影响：普通用户能停用全局模型、改费用参数或调用端点。修改 `api_endpoint` 时不提交 key 会保留原密文；后续新建客户端会解密原 key 并将其用于新端点。若该端点可从部署环境访问，可能把模型密钥和问答内容发送给非授权接收方。没有使用真实密钥验证外发；现有客户端缓存会延迟端点变化，不构成安全保护。
- 建议：写入接口统一要求模型管理权限；限制端点目的地及协议；端点变化时重新核验凭据绑定；补充无角色用户的拒绝测试。数据源管理接口也只有登录检查，应一并核对运维权限边界。

## 2. 高：生产环境鉴权误配置只告警，不阻止服务启动

- 位置：[config.py](/workspace/QA/backend/app/config.py:76)、[dependencies.py](/workspace/QA/backend/app/dependencies.py:28)、[main.py](/workspace/QA/backend/app/main.py:171)。
- 代码证据：默认 `AUTH_MODE=stub`、`AUTH_STUB_ENABLED=true`；stub 的匿名默认角色包含 admin。即使 `APP_ENV=production`，启动检查也只输出日志。JWT 开发默认密钥检查同样只输出 warning。
- 触发条件：生产漏设认证开关，或启用了允许 stub 的配置。正确配置的 real 模式不会仅因存在默认字段就开放匿名访问。
- 影响：部署配置失误可能使匿名请求获得管理能力。已知弱 JWT 密钥也不应获准用于生产，但 session 表校验意味着不能仅凭默认密钥就断言可任意伪造有效登录。
- 建议：生产启动时强制 real 模式、禁止 stub，并校验 JWT/Fernet 密钥；不满足要求则终止启动。

## 3. 高：“必须改密”没有服务端执行限制

- 位置：[dependencies.py](/workspace/QA/backend/app/dependencies.py:202)、[auth_service.py](/workspace/QA/backend/app/services/auth_service.py:222)、[RequireAuth.tsx](/workspace/QA/frontend/src/components/common/RequireAuth.tsx:5)。
- 已复现：`must_change_password=true` 的用户登录后直接调用模型创建接口，得到 201。Bearer 验证只检查用户启用状态，没有检查强制改密状态。
- 影响：初始密码或管理员重置密码可以持续用于业务操作；前端登录后的改密跳转可以通过直接 API 请求或改地址绕过。
- 建议：服务端限制该状态的用户只能访问个人认证信息、改密和登出；前端路由同步限制访问，作为体验补充。

## 4. 中：登录失效返回 403，前端保留无效 token

- 位置：[dependencies.py](/workspace/QA/backend/app/dependencies.py:194)、[exceptions.py](/workspace/QA/backend/app/domain/exceptions.py:254)、[client.ts](/workspace/QA/frontend/src/api/client.ts:83)。
- 已复现：登出吊销 JWT 后继续访问 `/auth/me` 返回 403；前端拦截器在收到该 403 后保留 token。过期 JWT 的异常走同一 PermissionDeniedError 分类。
- 影响：凭据到期、改密或管理员重置后，前端仍认为用户已登录，停留在受保护页面并反复报权限错误。
- 建议：无效、过期或吊销身份凭据统一返回 401；已认证但无操作权限才返回 403。避免前端无差别清除所有 403 的登录态。

## 5. 中：模型配置更新后，缓存客户端继续使用旧端点和 key

- 位置：[factory.py](/workspace/QA/backend/app/infrastructure/llm/factory.py:48)、[openai_client.py](/workspace/QA/backend/app/infrastructure/llm/openai_client.py:76)、[model_config_service.py](/workspace/QA/backend/app/services/model_config_service.py:80)。
- 已复现：建立客户端后更新数据库中的端点，再调用工厂得到同一个客户端对象，其端点仍是旧值。缓存只按配置 id 判断；写入接口没有失效通知。
- 影响：切换代理或轮换密钥在当前进程中不生效，持续请求旧服务或因旧 key 被撤销而失败。
- 建议：更新连接参数后安全关闭并失效对应客户端；缓存键纳入配置版本。多 worker 部署还需跨进程更新机制。

## 6. 中：密码长度校验与 bcrypt 5 不兼容，合法请求返回 500

- 位置：[auth.py](/workspace/QA/backend/app/schemas/auth.py:17)、[auth_service.py](/workspace/QA/backend/app/services/auth_service.py:154)、[password_policy.py](/workspace/QA/backend/app/services/password_policy.py:24)。
- 已复现：登录 DTO 接受 73 字节密码，HTTP 登录返回 500。bcrypt 5 对超过 72 字节的输入抛 ValueError，而代码未处理；密码策略也接受该输入。UTF-8 多字节密码可能在字符数更少时触发。
- 影响：登录、改密、重置密码和用户创建等密码处理路径出现未捕获异常。
- 建议：统一按 UTF-8 字节数校验现有 bcrypt 输入并返回 422，或设计兼容迁移到适合长密码的算法；不能直接截断密码。

## 7. 中：按用户限流的配置没有接入真实身份

- 位置：[rate_limit.py](/workspace/QA/backend/app/infrastructure/rate_limit.py:98)。
- 代码证据与函数检查：取 key 时读取 `request.state.user`，仓库没有给该字段赋值的认证中间件；`getCurrentUser` 也不接收 Request 或写入 state。两个不同用户请求在 `user_id` 策略下均得到 `anonymous`。
- 影响：启用 user_id 策略后所有用户共享匿名桶；ip_user 实际按 IP 加匿名分桶，无法实现配置承诺的用户隔离。同一代理后的用户容易互相占用限额。
- 建议：在限流执行前建立经过验证的请求身份，或选择实际可用的限流维度。`memory://` 存储还意味着多 worker 不共享计数，若需要全局限额须使用共享存储。

## 8. 中：文件上传缺少读取过程中的大小限制

- 位置：[documents.py](/workspace/QA/backend/app/api/v1/documents.py:203)、[wiki_import.py](/workspace/QA/backend/app/api/v1/wiki_import.py:149)。
- 代码证据：文档上传使用无界 `await file.read()`；Wiki 上传虽然限制 10 MB，但在完整读取后才判断。
- 影响：较大文件会先被完整加载进应用内存；Wiki 的限制不能防止该阶段的内存放大。具体可上传大小还取决于外部代理设置，这里未验证压力行为。
- 建议：分块读取并在累计字节数达到上限时停止；同时配置入口请求体限制。不要仅信任 Content-Length。

## 9. 高（有机密数据时）：文档密级没有对应访问控制

- 位置：[documents.py](/workspace/QA/backend/app/api/v1/documents.py:234)、[rag_service.py](/workspace/QA/backend/app/services/rag_service.py:237)、[enums.py](/workspace/QA/backend/app/domain/enums.py:328)。
- 代码证据：枚举声明 L3 为机密；检索接口取得当前用户却不传给检索服务，密级仅为用户可选筛选参数。省略参数时，Milvus 不设置密级过滤。目录列表和详情也没有用户授权过滤。
- 影响：如果系统按这些标签存储有访问限制的资料，普通登录用户可以检索机密内容，或使内容进入问答上下文。尚未启动 Milvus 验证实际检索响应；具体用户密级授权政策也未在本次审查中确认。
- 建议：明确用户/角色/组织的文档授权政策，在查询端生成服务端权限过滤，并把用户筛选条件与权限条件取交集。

## 10. 中：登录页读取的异常结构与公共拦截器不一致

- 位置：[client.ts](/workspace/QA/frontend/src/api/client.ts:103)、[LoginPage.tsx](/workspace/QA/frontend/src/pages/LoginPage.tsx:33)。
- 已复现：公共拦截器把 AxiosError 转成普通 Error，仅保留 `.status` 和 `.detail`；登录页却仍读取 `.response.status` 和 `.response.data.error`。临时前端检查确认 429 的转换结果不存在 response。
- 影响：密码错误、账号问题和限流都进入登录页的“网络错误”提示。即使保留 response，后端的 error 也是中文文案，登录页比较的却是 `MSG_*` 名称，仍不匹配。
- 建议：统一错误对象结构和稳定的机器错误码，登录页消费统一字段；用户可读文案单独承载。

## 11. 低：创建模型时丢弃 temperature

- 位置：[schemas.py](/workspace/QA/backend/app/domain/schemas.py:339)、[model_config_service.py](/workspace/QA/backend/app/services/model_config_service.py:36)。
- 已复现：提交 `temperature=0.7` 创建模型返回 201，但数据库/响应中的值为 null。DTO 有该字段，创建 ORM 对象时未赋值；更新接口却可以保存。
- 建议：创建和更新采用一致字段映射，补充往返值检查。

## 测试与维护观察

- 已有模型配置、菜单及真实应用装配相关的 19 个后端集成测试全部通过，但没有覆盖以上无角色用户管理权限、强制改密、73 字节密码和缓存失效场景。
- 2 个临时前端检查确认了异常形状不一致和 403 保留 token 的当前行为；它们是复现检查，不是修复验证。
- 根测试 fixtures 仍保留 SQLite 路径，与 Harness 的“后端全面禁止 SQLite”规范冲突；一些测试使用独立维护的 `_testapp`，容易漏掉生产 app 的装配/生命周期问题。
- 部分安全文档仍描述 Stub MVP，并指向不存在的 SQL Guard 路径。建议同步文档和测试约束，防止开发者按过时说明实施变更。
- 本次未运行全量覆盖率、完整图谱/向量/对象存储集成、真实模型调用、Playwright 或负载测试，也不把这些列为已验证能力。

建议处理顺序：先统一管理权限和生产认证门禁，再落实文档访问与强制改密限制；随后修复认证状态码、密码边界和缓存失效，最后统一前端错误与上传/限流边界。
