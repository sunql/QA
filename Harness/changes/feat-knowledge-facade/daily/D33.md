| # | 事实 | 证据 | 对设计的影响 |

| C-1 | **manifest 里没有「类 ↔ 域」的直接字段** | `app/domain/semantic_manifest_schema.py` 的分区只有 `domains / classes / joins / metrics / kpis / businessObjects` | 域切片**不能**按类直切 ⇒ 必须绕道业务对象（`businessObjects[].primaryDomainCode` / `attachedDomainCodes`） |

## 三、方案与取舍

### 3.1 召回：**确定性词项匹配**，不调 LLM

| 选项 | 结论 |
|---|---|
| LLM 改写问题 → 向量召回 | ✗ 引入计量 / 预算 / 评测三张皮；G5 的三条验收（试点集、权限双向、引用回溯）**在证据层即可客观判定**，不需要语义改写的准确率 |
| **确定性词项匹配**（类名 / 类别名 / 属性名 / 属性别名 / 业务别名 / 指标名 / KPI 码 / 语义关键词） | ✅ 采纳：同一问题 ⇒ 同一批证据（顺序也一致）⇒ 试点通过率可复算、引用可回溯 |

匹配口径（`services/knowledge/matching.py`）：
- CJK 词项走**子串**命中；ASCII 词项走**词边界**命中（避免 `id` 命中 `vendor`）；
- 权重：别名 4 > 名称 3 > 分词命中 2；同分按 key 排序 ⇒ 顺序确定。

### 3.2 域切片（`services/knowledge/domain_slice.py`）：绕道业务对象 + fail-closed

| 规则 | 内容 |
|---|---|
| 域 → 类 | 业务对象（主域 / 附域）→ `headerClassName` → **父类闭包**（`parentClassName`） |
| 域 → JOIN | **两端都在域切片内**才留（跨域 JOIN 排除） |
| 域 → 指标 | `targetClassName` / `numeratorMeasure.className` / `denominatorMeasure.className` / `sources[].className` 任一命中域内类 |
| 域 → KPI | `metricName` ∈ 域内指标 **或** `kpiCode` ∈ 域内指标的 `kpiCodes`（**双向**，见 C-3） |
| 归不了属的 | **排除**（fail-closed）：宁可少给，不给跨域的东西 |
| 未知域 | 空切片（不是报错） |

### 3.3 权限源（`services/knowledge/permission.py`）：**本批提前落地**（原计划 D35）

提前的理由：**域可见性是「要不要跑这两路」的闸门**，不接权限源就等于对任何域都发数据 ⇒ D35 再回来补闸门等于把已发出的数据收回去。提前落地后，D35 退化为「四路**同一口径**的验收矩阵 + 引用回溯核对」，不再改接线。

推导口径：

1. `isAdmin` = `'admin' ∈ user.roles`（**与仓内 `getAdminOnlyActor` / `requireAdmin` 同口径**；生产 `AUTH_MODE=real` 时 roles 只来自 DB，stub 头被反向代理剥离 ⇒ 伪造不出 admin）。
2. 非 admin：可见域 = 域的主组织 code ∈ 用户组织 code；`primary_org_id IS NULL` 的域**一律不可见**（L-P4-1）。
3. `entityTypes` = 可见域下的业务对象（活表）。
4. `maxSecurityLevel`：admin ⇒ L3，其余 ⇒ L1（L-P4-8：用户级安全等级没有权威来源）。
5. **请求里的 scope 只能收窄**：组织收窄 = 请求组织 ∩ 用户组织（admin 直接采用请求组织）；实体 / 安全等级同理只取交集。

### 3.4 域不可见 ⇒ **200 + 空结果 + 警告**（裁决 4）

沿用 D32 的契约（`messages.MSG_DOMAIN_NOT_VISIBLE`），**不是 403**。本批新增一个路由状态 `DENIED`，
把「这个域我没权限」与「这个域里没这些东西（`EMPTY`）」**分开** ⇒ 调用方不必去猜 warnings 的文字。

### 3.5 状态枚举新增

`KNOWLEDGE_ROUTE_DENIED = "DENIED"`（域不可见）。其余沿用 D32：`OK / EMPTY / DEGRADED / PENDING`。

## 七、约定沉淀（避免下一批再踩）

1. **内部 dataclass = snake_case，DTO = camelCase**：`CamelModel` 只在**跨进程契约**上用；
   服务层内部结构体（`ResolvedRelease` / `KnowledgeScope` / `RouteOutcome`）一律 snake_case。
2. **`entity_types` 来自活表**（授权按当前态），**类 / 指标来自发布快照**（口径按发布时刻）⇒ 两者来源不同是**故意的**。
3. **路由状态五态**：`OK / EMPTY / DEGRADED / PENDING / DENIED`；每路**必须**落在其中之一，不许静默。
4. **共享测试样本放 `app/tests/` 根**（`_knowledge_manifest.py`），不放 `unit/` ⇒ unit 与 integration 共用一份口径。
