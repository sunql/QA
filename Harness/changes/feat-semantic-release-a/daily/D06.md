## Manifest 结构（v1 定稿）

```
{
  "schemaVersion": "v1",
  "domains":         [{code, name, description, enabled}],
  "classes":         [{className, classAlias, description, sourceTable, objectType,
                       objectOwner, parentClassName, properties[]}],
  "joins":           [{joinKey, sourceClassName, sourceColumns[], targetClassName,
                       targetColumns[], joinType, relationType, description}],
  "metrics":         [{metricName, metricAlias, formula, aggFunction, metricType,
                       targetClassName, dimensionDefaults, grainKeys[],
                       aggregationOrder, numeratorMeasure, denominatorMeasure,
                       filterExpression, status, owner, executionSource,
                       sources[{className, role}], kpiCodes[]}],
  "kpis":            [{kpiCode, kpiName, businessDefinition, formula, numerator,
                       denominator, grain, unit, grainKeys[], numeratorColumns[],
                       denominatorColumns[], owner, version, status,
                       semanticKeywords[], metricName, datasourceId,
                       datasourceName}],
  "businessObjects": [{code, name, headerClassName, primaryDomainCode,
                       attachedDomainCodes[], graphLabel, description}]

```

## 设计要点

1. **指标两层都入档（裁决三）**：`metrics` = 技术口径（结构化轨道：`metricType` /
   `numeratorMeasure` / `denominatorMeasure` / `aggregationOrder` / `grainKeys` /
   `filterExpression` 原样入档，不做二次解释）；`kpis` = 业务层。两侧用 `metricName`
   单向关联，`metrics[].kpiCodes` 是反向索引（排序后写入）。
2. **不按指标状态过滤**：实测 12 条指标全部是 `DRAFT`。若编译器按「只发布 PUBLISHED」
   过滤，真实库将编译出空 `metrics` —— 与 D5 的墓碑设计错误同型。**策略属于发布闸门
   （D9/D10），快照必须如实记录**，否则发布评审看不到被拦下的内容。
3. **KPI 弱引用可空**：`metric_id` / `datasource_id` 都允许为空（业务定义先行、技术实现
   后置）；非空但指向不存在的行 ⇒ 抛 `ValueError`（数据被写坏）。
4. **`match_threshold` 刻意不入档**：它是 `Numeric(3,2)` ⇒ `Decimal`，stdlib `json`
   无法序列化（历史事故：Decimal 直接炸 INSERT），且属检索调参而非语义定义。
   对应用例 `test_kpi_has_no_decimal_or_float_noise` 钉死。
5. **BO header 墓碑 ⇒ 抛错**：外键型引用（属性 `refClassName`）可以编译成 `null`，
   但 BO 的身份就是 header 类，不能为空 ⇒ 明确报错（实测当前库 0 条）。
6. **模块拆分**：D5 单文件已 511 行，超过 200–400 行惯例；按「本体核心 / 指标·BO·域 /
   共享原语」拆成 253 + 233 + 55 行。拆分前后真实库 sha256 完全一致（纯搬迁）。

### 2. golden（8,931 B）

策展行集覆盖：4 个域（含 1 个 disabled）、4 个类（含 1 个墓碑类 + 1 个父类）、
7 条属性（含 PK / FK / 单位 / 值域）、2 条 JOIN（1 条端点已删）、2 条指标
（RATIO + MEASURE，含分子分母度量与 1 条墓碑源被过滤）、3 条 KPI（1 条无指标引用）、
2 个 BO（含附域）、1 个数据源。**反向守卫**：每个分区的键集合在测试里显式列出 ——
「编译器删字段 + golden 同步重生」这种双双变绿的情况会被挡住。

不提交生产全量快照（约 1.0 MB）作 golden：一有本体改动 diff 无法评审；
真实库覆盖改由下方冒烟记录（分区计数 + sha256）承担。
