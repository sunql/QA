## 1. 这个模板解决什么问题

A6 的产出是「12 条 KPI 差在哪」。本文件把「差在哪」翻译成「**落到哪一列**」：

```
问卷答案（自然语言）  →  [本文件的映射表]  →  ontology_metric 的某个具体列  →  A9 才能发布
```

三条纪律：

1. **只做槽位，不写死口径**（并行轨硬纪律 ①）。本文件不产生任何 KPI 的口径结论，
   只声明「这个答案该进哪个字段、该字段的合法值域、以及它被哪道闸门要求」。
2. **空槽必须可见**。`●` 有业务值 / `◐` 有值但是占位 / `○` 空槽可填 / `⛔` 空槽且被阻塞 / `⊘` 不适用。
   不允许把「填了个默认值」当成「填好了」。
3. **装不下的必须登记**（§6）。13 个字段是 `ontology_metric` 的现有能力边界；
   问卷里有相当一部分答案是这 13 个字段表达不了的，硬塞会造成「看着配了、实际算错」。

## 2. 13 个槽位定义

这 13 个字段 = `ontology_metric` 中**构成一个可发布口径**的全部列
（`metric_name` 是主键式标识、`id` / `created_by` / `target_class_id` / `dimension_defaults`
不属于口径，不计入；源类绑定在 `ontology_metric_source`，属 **A8**）。

| # | 字段 | 类型 / 值域 | 必填条件 | 谁写 | 被哪道闸门要求 |
|---|---|---|---|---|---|
| 1 | `metric_type` | `MEASURE` / `RATIO` / `DIFFERENCE` / `DERIVED` | **恒必填** | 问卷 A（题型） | 发布闸门 `metric_type` |
| 2 | `numerator_measure` | JSON：`{agg, expr, filter?, class_id?, class_alias?}` | **恒必填**（`RATIO`/`DIFFERENCE` 为分子，`MEASURE` 为唯一度量） | 问卷 A（分子定义） | 发布闸门 `numerator` |
| 3 | `denominator_measure` | 同上 | `RATIO` / `DIFFERENCE` **必填**；`MEASURE` 必须为空 | 问卷 A（分母定义） | 发布闸门（比率型） |
| 4 | `agg_function` | 列级默认聚合，字符串；编译器白名单 `SUM` / `COUNT` / `AVG` / `COUNT_DISTINCT` | 恒必填（DB NOT NULL，默认 `SUM`） | 工程（由 ②③ 的 `agg` 派生） | 无闸门；`COMPILED` 轨道编译时校验 |
| 5 | `aggregation_order` | `WEIGHTED_RATIO` / `AVG_OF_RATIOS` / `NONE` | `RATIO` ⇒ **必须是前两者之一**；其余 ⇒ `NONE` | 问卷 A5.3 / A1.3 | 发布闸门（比率型）+ 对账 `ratio_aggregation_order_*` |
| 6 | `grain_keys` | 物理列名数组 | **恒必填**（≥1 个） | 问卷 A1.6 / B2.x | 发布闸门 `grain` |
| 7 | `filter_expression` | SQL 谓词片段（`COMPILED` 轨道拼进 `WHERE`） | 可空 | 问卷 A（全局过滤类答案） | 无闸门；编译期 `_assertSafeFragment` |
| 8 | `time_grain` | `day` / `week` / `month` / `quarter` / `year`（小写） | 需按时间切片时必填 | 问卷 B3.x | 无闸门；对账 `time_grain` 比对 |
| 9 | `time_column` | 源类日期列（**物理列名**） | 需时间切片 **或** `formula` 含 `{time_scope}` 时必填 | 问卷 A（判定日期）+ §3 候选 | 无闸门；`COMPILED_TIME_COLUMN_MISSING` / 写入校验（占位符 ⇔ 非空） |
| 10 | `execution_source` | `COMPILED` / `ESCAPE_HATCH` / `NONE` | **恒必填且 ≠ `NONE`** 才能过闸 | 工程 | 发布闸门 `execution_source` |
| 11 | `formula` | 可执行 SQL（`ESCAPE_HATCH`）/ 说明文字（其余） | `ESCAPE_HATCH` ⇒ 必须是**可解析 SQL**（`sqlglot` 解析结果须为 `exp.Query`） | 工程（A6 已证明 4 条是中文说明） | 无闸门；诊断与探针以它为准 |
| 12 | `status` | `DRAFT` / `PUBLISHED` | 发布前必须 `PUBLISHED` | 工程（发布动作） | 发布闸门 `metric_published` |
| 13 | `metric_alias` | 展示别名（≤100 字符） | 可空 | 问卷 A / 术语词典 | 无闸门；展示名 + resolver 阶段 3 |

> ⚠️ **两个 `status` 别混**：`ontology_metric.status` 是**技术形态成熟度**（DRAFT/PUBLISHED），
> `kpi_catalog.status` 是**治理状态**（指标是否在首期清单里）。
> 「NCR 摘除首期」改的是**治理侧**，`ontology_metric` 保持 `DRAFT` 即可 —— 不存在「把 metric 删掉」这个动作。

> ⚠️ **`measure.filter` ≠ `filter_expression`**：前者属于某个度量（分子或分母各自的过滤，
> 如「只统计逾期行」），后者是整条指标共用的 `WHERE`。答案说「只算 X」时**先判断它属于哪一层**，
> 判错了会一边算多一边算少。

**读表要点**：

- **12/12 的 `status` 都是 `DRAFT`、`metric_alias` 都等于 `kpi_code`** ——
  这是「列非空」而非「口径已定」，所以标 `◐`。别把 NOT NULL 默认值当完成度。

## 6. 13 个槽位的表达能力边界（A7 的第二个结论）

把 §5.2 归并，采购域目前有 **5 类口径要素在 `ontology_metric` 里没有落点**：

| # | 缺的能力 | 影响的口径 | 建议处置 | 归属 |
|---|---|---|---|---|
| 1 | **时间窗边界规则**（25 日自然月 / T-1 安全边界） | 全部 12 条 | 运行时参数，不建字段；改 `TimeScope` 计算 | M2′ |
| 2 | **指标间关系**（补集 / 拆分 / 派生） | OTD↔逾期、FPY↔不良率、成本节约↔超支 | `metric_type=DERIVED` 只能表达"派生"，表达不了"互补"；建议登记到 Wiki（口径关系图），不建字段 | M2′ / 知识层 |
| 3 | **加权平均的权重列** | 采购周期（A3.3） | `MEASURE` 的加权只能在 `formula`（`ESCAPE_HATCH`）里写；`COMPILED` 轨道无法表达 ⇒ 扩展 measure JSON 或保持 `ESCAPE_HATCH` | M2′ |
| 4 | **中位数等非白名单聚合** | 采购周期中位数（A3.4） | 新建指标 + `ESCAPE_HATCH`；若要 `COMPILED` 需扩 `_SUPPORTED_AGGS` | M2′ |
| 5 | **展示层规则**（负偏差单列、分档） | 价格偏差、不良率分档 | 前端/图表层，不入 `ontology_metric` | M4 |

> 结论：**13 个槽位足以表达 8 条 `ESCAPE_HATCH` 指标的全部修改动作**（那 8 条的真实缺口是
> `time_column` + JOIN 形状 + 过滤条件，全是已存在的字段）。
> 质量域 4 条（含 NCR）的阻塞是**源类不存在**，不是槽位不够。
> 真正需要扩展模型的只有上表 3 / 4（`COMPILED` 轨道的加权与中位数）—— **且当前 12 条全是 `ESCAPE_HATCH`，没有一条走 `COMPILED`**，
> 所以这两项不阻塞 M0.5 / A9。

## 7. 回收后的填槽顺序（G1 汇合用）

```
1. 建源类（A8/M1）           ← 只对 DEFECT / FPY / MAINTENANCE（NCR 摘除）
2. 填 measure 四件套         ← metric_type / numerator / denominator / aggregation_order
3. 填时间两件              ← time_grain / time_column（用 §3 的候选 + 答案的"判定日期"）
4. 填过滤                  ← 先判断 measure.filter 还是 filter_expression
5. 重写 formula            ← 仅 ESCAPE_HATCH；必须能用 sqlglot 解析成 exp.Query
6. 跑 A6 探针              ← 本体覆盖 0 缺口 + 对账 verdict 不再 unknown
7. 过发布闸门              ← status=PUBLISHED + execution_source ≠ NONE + 对账 pass + datasource
8. 与 alias `--apply` 同批 ← A9 采购域首次发布
```

**填槽的验收标准**（机器可判）：

- `execution_source ≠ NONE` 的 8 条：`numerator_measure` 与 `denominator_measure` 非空
  （`MEASURE` 除外分母）、`grain_keys` 非空、`aggregation_order` 合法；
- 需要时间切片的 11 条：`time_column` 非空且是该指标源类的真实列；
- `formula` 非空的 `ESCAPE_HATCH` 指标：`sqlglot.parse_one(formula)` 结果为 `exp.Query`；
- 上述四条任一不满足 ⇒ **仍算空槽**，不允许标"已填"。

### 9.3 结论变化（§6 / §7 需要改的地方）

- §6「质量域 4 条的阻塞是**源类不存在**」⇒ **只对 NCR 成立**。DEFECT / FPY 的源类已存在，
  阻塞从「源类不存在」降为「字段语义待确认 + 单位口径待回问」⇒ 两条 `execution_source` 可由 `NONE` 改为 `ESCAPE_HATCH`。
- §7 填槽顺序第 1 步「建源类（只对 DEFECT / FPY / MAINTENANCE）」⇒ DEFECT / FPY **不再需要建类**，
  只需为 `DWD_ARRIVAL_ORDER_DTL` 补 `ARR_QTY` / `QUALIFIED_QTY` / `INSPECT_DATE` / `DOC_STATUS_CODE` 属性。
- §6 第 5 类「展示层规则」新增一条：**基准价覆盖率**必须与节约额/偏差率同屏输出（R-09）。
- **新增展示层规则**：采购周期的**可精确匹配覆盖率**（13.8%）必须与周期值同屏输出（R-10）。
- 两条 `NONE` 保留：MAINTENANCE（品类准入表 0 行 + 码义未知 + 无停用列 ⇒ 降级为台账展示）与 NCR（质量数据未进系统）。
- **绑定范围修订**：本文件所有 `class_id` 引用（20 / 17 / 16 / 27 / 6 …）指向的是**墓碑族**的类，
  而 A8 的 34 候选是 `_DTL` 族 ⇒ **M1 绑定清单必须含 7 个复活墓碑类**（C-22 / A8 §5.3）。
