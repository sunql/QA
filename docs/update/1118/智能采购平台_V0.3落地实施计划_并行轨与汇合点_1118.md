## 0 · 一句话答案

**可以并行，而且必须并行**——但不是"一边等一边随便做点别的"。

理由只有一条，但很硬：**问卷回收是「外部等待」，不是「工程投入」。** 等它回来＝让机器和人同时空转。
⇒ 正确做法是：**把回收窗口用 M0 + M1 前半段的工程工作填满**，让两条线在窗口结束时**正好汇合**。

按当前数据算：**回收窗口 1 周（5 工作日）≈ M0 的全部工程量（8–12 人日，2.5–3 人并行）**。⇒ **M0 恰好能在回收回来之前做完**，这不是巧合，是排出来的。

## 2 · 三条并行的结构性理由

### 2.1 问卷是"外部等待"，不是"前置工作"

落地计划的准则 C 写的是「**外部依赖在 M0 发出**」——发出去之后，那 1 周**不属于任何人的工作量**。
⇒ 用它去填 M0 的工程缺口，是**零边际成本**的。

### 2.2 真正的"前置"不是问卷，是**判断**——而判断可以提前做

| 例子 | 看起来卡问卷 | 实际上不卡 |
|---|---|---|
| KPI 口径 | "12 条口径要业务给" | **归因**（治理层/技术层/一致，三选一）是纯工程分析，用现有数据就能做完；只有**改**要等答案 |
| 源绑定 | "要 ERP 管理员说哪个类在哪个库" | **绑定表结构 + 候选集**可以先建（候选来自现有 `source_table` 与库命名惯例），C 的回答只是**确认/修正** |
| 评测题集 | "要业务给真实问题" | 可以先用附录 B **Q01–Q07** 起步，D 回来再扩 |

### 2.3 口径类工作必须做成"**槽位**"而不是"**值**"

⇒ 回收后**只填值、不改结构** ⇒ 把"等答案"造成的串行依赖降到最短。
这是本并行计划**最关键的一条设计**（见 §6 纪律 1）。

### 5.1 ⚠️ 对准则 C 的一处**修正**

原准则 C 写的是：「回收率 < 3 份 ⇒ **M5/M6 不启动，整体计划要重排**」。
复核后认为**过于严厉**，修正为：

| 回收情况 | 修正后的处置 |
|---|---|
| **≥ 3 份** | 按原计划走 |
| **2 份** | **M5 / M6 不启动**（确实缺审批矩阵或写接口）；**M1 / M2 / M2′ / M3 / M4 照常推进**（它们只需要"部分答案 + 降级"）⇒ **不需要整体重排**，只把 M5/M6 顺延 |
| **≤ 1 份** | 触发**整体重排**（关键路径被打断） |

> **理由**：M5/M6 是**链尾**（15–25 人日），把它们顺延不影响 M0–M4 的 50–70 人日主线。
> 原表述会让"少回收 1 份"⇒"全部重排"，代价与收益不成比例。
> ⇒ **准则 C 修正版：回收不足只顺延链尾，不整体重排。**（已回写落地计划 §2 准则 C）

## 6 · 四条硬纪律（**并行计划最容易翻车的地方**）

### 纪律 1 · 口径**不写死**——一律做成"槽位"

轨 A 产出的一切与口径相关的东西，必须是**模板/参数/空表**，不是具体数值。

| 轨 A 产出 | ❌ 写死 | ✅ 槽位化 |
|---|---|---|
| KPI 技术口径 | 直接改 `ontology_metric.numerator_measure` | 建**空槽表** + 题号↔字段映射，回收后填值 |
| 源绑定 | 直接落库 | 落**候选** + 「待确认」标记 |
| 评测题集 | 拿 Q01–Q07 当全集 | Q01–Q07 是**版本 0**，D 回收后升 v1 |
| 规则 | 把阈值写进代码 | 阈值进**规则表**，答案只提供参数 |

**判据**：回收回来后，**能不能只做"填值"而不改结构**？不能 ⇒ 槽位化没做到位。

### 纪律 2 · **候选 ≠ 结论**——候选不得进生产

A8 的候选绑定、A9 的候选发布，**必须带显式标记**（`待确认` / `candidate`），且**不得被生产读路径消费**。
⇒ 守门：**在 M0.2 开关全开的状态下**，候选数据**不应**出现在任何业务答案里。

### 纪律 3 · **禁伪并行**——"等问卷"不算工作

轨 A 每个任务都必须有**可归档的验收包**（M0.3 §3）。没有验收包 ⇒ 不许标"进行中"。
> 判据：不看进度条，看 `docs/update/1118/M0/evidence/` 里有没有对应文件。

### 纪律 4 · **回收答案不直接改代码**

回收的答案先落到**数据/规则/配置**，**不改代码**。
⇒ 理由：口径变更是常态；代码里写死口径 = 下次变更又要发版。**答案进数据层，口径变更是数据变更**（可版本化、可回滚）。
