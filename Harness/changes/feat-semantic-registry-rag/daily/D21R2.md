## 〇、背景

D21R 合入评审意见后，**第二轮评审**（code-reviewer + security-reviewer，各自独立）
在**同一个核心洞**上再次收敛：**D21R 引入的 `isScopeBound` 标志位本身是新的风险源**。

D21R 的写法：

```python
RegistryFilter(domainCodes=())          # 忘了写 isScopeBound=True
RegistryFilter(domainCodes=(), isScopeBound=True)   # 写对了
```

⇒ 第一种（**默认写法**）会被判成「本轮无作用域」⇒ 闸门返回**全量可见**。
这恰好发生在「本该什么都看不到」的一轮 ⇒ **越权**。
标志位把「空作用域无法表达」变成「空作用域有两种写法，且默认那一种不安全」。

⇒ D21R2 裁决：**过滤器的「存在」本身就是声明** —— 删掉标志位。

## 一、评审意见 ⇒ 本轮处置

| # | 评审结论 | 根因 | 处置 |
|---|---|---|---|
| R2-① | **HIGH**：`RegistryFilter(domainCodes=())`（忘写标志位）被判「无作用域」⇒ **全量可见** | 「有作用域」需要**两个**信号（实例 + 标志位）⇒ 默认那一个不安全 | **删掉 `isScopeBound` 字段与 `hasScope()`**：任何实例 = 已声明作用域；各维度取值为空 ⇒ deny-all。`registryFilter=None` = 无作用域 |
| R2-② | **HIGH**（文档层）：模块文档写「开关关 ⇒ 与今天逐字节一致」，但 D21R 之后**开关关 + 作用域 = 空结果** | 文档口径没跟上 D21R 的 fail-closed 改动 | 文档改成「开关关 **且未声明作用域** ⇒ 与今天逐字节一致」；并补「⚠️ 反过来：开关关且声明了作用域 ⇒ fail-closed」 |
| R2-③ | MEDIUM：过滤侧与写侧**归一不对称** ⇒ 空字面量被「放大」 | 写侧 `_codeList` 会 strip / 丢空串 / 截断 64 字；过滤侧不 strip、不丢空 ⇒ `entity_type == ""`（存储层合法哨兵值）命中**所有非 BO 头类** | 过滤侧共用一套归一（`_normalizeFilterCodes`）：strip + 去重；**空 / 纯空白 / 超长 / 含控制字符 / 非字符串** ⇒ `ValueError`（闸门转成 `filter_invalid` ⇒ 空结果） |
| R2-④ | MEDIUM：写侧截断 64 字、过滤侧不截断 ⇒ 持**前缀**可跨域命中 | 两端口径差 | 过滤侧**拒绝超长**（域码/组织码 > 64 字、实体码 > 32 字）⇒ 不与写侧「静默截断」对齐，而是**拒绝**，避免前缀跨域 |
| R2-⑤ | MEDIUM：裸 LF/CR 等**控制字符**会让 Milvus 表达式解析失败 ⇒ 杀掉**整域**召回 | 只转义引号/反斜杠，不拦控制字符 | 归一里拒控制字符（`ord < 0x20` 或 `0x7F`）⇒ `ValueError` ⇒ 空结果（不是「整域挂掉」） |
| R2-⑥ | MEDIUM：就绪探针只判「集合有没有行」⇒ **行在、维度全空** 时误报「就绪」，而带过滤召回**恒空** | 物理行数 ≠ 可召回行数 | 探针增报「**带任一治理维度**的可见行数」（`registryV2DimensionedRowCount`）；启动期把「有行但维度全空」单列为第三种诊断 |
| R2-⑦ | MEDIUM：独立核对脚本**零行比对也判「一致」** ⇒ 假绿（v2 空 / 指错库） | 只看 `mismatched == 0` | 退出码分层：`0` 一致 / `1` 不一致 / `2` 环境故障 / **`3` 零行比对（假绿信号）**；另加「必须有显式 `DATABASE_URL`」「缺省目标库 = 应用配置」「集合不存在返回空而不是抛」「跨类型同号用复合键计不一致」「期望值镜像写侧截断口径」 |
| R2-⑧ | MEDIUM：`verify` 脚本默认目标库写死字面量 ⇒ 「PG 读应用库、Milvus 读另一个库」而脚本毫无察觉 | 硬编码 | 缺省取 `milvus_client.getDbName()`（应用配置）；报告里记录 `pgDatabase`（**不含口令**） |
| R2-⑨ | LOW：启动期探针**同步阻塞**事件循环；三种「未就绪」共用一条告警 | 探针在 async 启动里直接调用 | `asyncio.to_thread` + `wait_for(10s)` 超时预算；三种情形（Milvus 不可达 / 集合缺失或空 / 有行但维度全空）**分别**给可区分的诊断文案 |
| R2-⑩ | LOW：`degradedReason` 取值 `switch_off_with_filter` 与其它取值口径不一致；文档没给取值表 | 命名与文档漂移 | 改名 `switch_off_denied`；模块文档补**取值表**（五个取值全是「拒绝/降级」，没有「放行」） |
| R2-⑪ | LOW：影子脚本的「范围」是**自指**的，报告没提醒读者 | 真值来自 v2 行自己带的维度字段 | 影子报告加「⚠️ 本报告的范围判定是自指的」块引用，指明外部锚点是 `verify_registry_v2_dimensions.py` |
| R2-⑫ | LOW：`backfill --limit -1` 会变成「除最后一行外的全部」⇒ **静默丢行** | `rows[:-1]` 语义 | `--limit < 0` 直接 `parser.error`；`--limit` 生效时**明说**「读错库的行数上限护栏不生效」 |

> 两个评审**独立**指到了同一个洞（R2-①）⇒ 不是风格分歧，是**同一个可利用的口径失真**。

## 四、裁决

| # | 裁决 | 理由 |
|---|---|---|
| D21R2-① | **删掉 `isScopeBound`**，用「实例的存在」表达「已声明作用域」 | 标志位是**可忘记**的；「存在即声明」不可忘记 ⇒ 从根上消掉「默认写法不安全」 |
| D21R2-② | 过滤侧对**非法字面量 fail fast**（`ValueError`），而不是「尽力归一」 | 空字面量是**存储层合法哨兵值** ⇒ 放行 = 「放大」而非「收窄」；静默截断 = 前缀跨域 ⇒ 宁可拒绝 |
| D21R2-③ | 探针要报**可召回行数**（带维度），不只报物理行数 | 「行在、维度全空」与「集合空」在召回上的后果相同（恒空）⇒ 探针必须能分辨，否则告警是安慰剂 |
| D21R2-④ | 核对脚本的「一致」必须**真的比到行**才算 | 零行比对 = 假绿；这是「只断言状态码/只看计数器」的同类陷阱 |
| D21R2-⑤ | 两种口径变化（作用域语义反转 + 字面量收紧）**放在同一轮** | 二者同源（过滤边界），分开做会出现「一半新一半旧」的中间态 = 更难推理的组合 |
