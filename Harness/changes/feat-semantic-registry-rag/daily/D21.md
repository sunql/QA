| 症状 | 根因 | 处置 |
|---|---|---|
| `RuntimeError` 抛在 `app/tests/integration/conftest.py:50` 的 `installTestNeo4jEnv()` | 未设 `TEST_NEO4J_URI` ⇒ fail-fast（防连生产图谱，2026-10-03 事故后的守卫） | 设 `TEST_NEO4J_URI=bolt://localhost:7688`（容器 `qa-neo4j-test`）+ `NEO4J_USER` / `NEO4J_PASSWORD`（凭据由 `docker exec … printenv` 取，**不打印**） |
| 单测集体报错「需要 `TEST_DATABASE_URL`」 | `qa_metadata_test*` 未指定 | `TEST_DATABASE_URL` → `qa_metadata_test_p3arag`@**5434**（`qa-pg-a1` 容器；5432 是 OpenMetadata，5433 是 dev `qa_metadata`） |

> ⚠️ **教训**：这套集成环境**不是**「装好依赖就能跑」的 —— Neo4j 与 PG 两个测试实例的
> URI/凭据必须**显式**给，否则守卫直接 fail-fast（这是**故意的**，不是缺陷）。
> 环境缺配置时，任何「80 errors」都不构成回归结论，必须先补环境再取证。
