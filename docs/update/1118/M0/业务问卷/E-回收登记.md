## 使用说明

1. 收到任一份问卷后，把答案**回填到对应问卷文件**（原文件不改，只填 `▸ 回答：` 位），并在本表登记**状态**与**摘要**。
2. **状态三选一**：
   - `已答` —— 有明确答案，工程侧可直接落地；
   - `待确认` —— 答了"不确定 / 需 X 确认"，**不是阻塞**，走 §4 的降级方案；
   - `未答` —— 整题没回，**同样不是阻塞**，走 §4 的降级方案。
3. **一个关键纪律**：只有 `已答` 的题可以进入工程实现。`待确认` / `未答` 的题**不得凭工程侧猜测实现**——必须走降级，否则会做出"看起来对但业务是错的"逻辑（这正是当前 12/12 KPI mismatch 的成因）。
4. 每题标注它**卡住哪个工作包**。某工作包的**所有 P0 题**全部 `已答`，该工作包才可开工。

### 4.1 通用降级原则

| 情形 | 降级动作 |
|---|---|
| 指标口径未定 | 该 KPI **不进验收范围**；问答返回"口径待业务确认"，**禁止 LLM 估算数值**（判据：零条 LLM 估算数值） |
| 表/源未确认 | 该类**不发布**到语义面；问答只答已发布范围，并说明"该维度尚未接入" |
| 规则条件未确认 | 规则**只读展示**，不做判定；不下发任何"合规/不合规"结论 |
| 审批矩阵未确认 | 工作流**不实例化**，只保留定义草稿；**不发任何外部动作** |
| 写接口未知 | 全部写操作降级为 **DRAFT-only**（生成草稿 + 人工发送） |
| 权限级别未确认 | 默认按**最严**处理：仅 READ，DRAFT_WRITE 关闭 |
