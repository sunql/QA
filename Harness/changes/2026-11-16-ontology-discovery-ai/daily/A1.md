## 〇、需求（用户视角）

「本体发布出去之后，治理表又被改了，我**不知道改了什么、改了会不会打破下游**。」
A1 交付两件底座，让这句话能被机器回答：

1. **不可变元数据快照**：把「某个授权数据源在某一刻的 schema 结构」冻结成**只增不改**
   的一行，带内容哈希 ⇒ 以后任何时候都能引用「那一刻的结构」当作证据；
2. **语义差异引擎**：给定两份 Manifest（基线 = 已发布 ACTIVE；候选 = 当前治理表编译结果），
   产出**结构化差异 + 破坏性分类 + 风险分级** ⇒ 回答「发布后被改了什么、风险多大」。

**验收标准**

| # | 标准 | 证据位置 |
|---|---|---|
| A1-a | 快照**只增不改**：内容不变 ⇒ 复用既有行；内容变 ⇒ **新增**一行，旧行逐字不变 | 第四节真实数据（8/8 PASS） |
| A1-b | 快照**内容寻址**：落库哈希可由落库 JSON 独立重算复现 | 第四节「哈希可由落库 JSON 独立重算」 |
| A1-c | 差异引擎是**纯函数**：零 IO、不改入参、确定性排序 | 单测 + 真实数据「两次计算完全相同」 |
| A1-d | 差异带**破坏性分类 + 风险分级**（BREAKING→HIGH / ADDITIVE→LOW / COSMETIC→INFO） | 单测 + 真实数据 3 例断言 |
| A1-e | 写入口**只有 admin** 能碰，读入口所有登录用户可看，**生产装配**与测试装配一致 | `test_governance_write_route_auth.py` + 集成用例 |
| A1-f | 差异引擎覆盖 classes / properties / joins 三分区，**披露字段级覆盖范围** | `test_semantic_diff_service.py` + `/diff` 断言 |
| A1-g | 高成本端点（采集）**限流**，敏感信息不入库 | 限流**位置**断言 + 净化单测 + 审计 `REUSE` |

## 二、方案取舍（详见 `plan.md` D-1…D-21）

| 根因 | 漂移端点统计的是**库里全部有 `source_table` 的本体类**；集成测试的 autouse fixture `warmAgentCaches` → `seedHeaderOntologyClasses` 会补种 **4 个** header 类（`Supplier` / `ItemMaster` / `PurchaseOrder` / `Receipt`；`IncomingInspection` 无 `source_table` 不计）⇒ 4 + 3 = **7**。测试断言写死了绝对值 3 ⇒ 与 fixture 耦合 |
| 取证 | 在 **pristine baseline**（main `5ab1313c` 的独立 worktree `qa-main-check` + **独立基线库** `qa_metadata_test_base`，避免 0148 与基线迁移链互斥）上复现**同样 2 个失败** ⇒ 与本批无关 |
| 处置 | **不在 A1 范围内修**（扩大范围会污染本次 CI 判据）。已作为**既有缺陷线索**登记 ⇒ 建议后续单独立项：漂移用例改为按「本次种子类」过滤计数，或把 `checkedTables` 断言改成相对量 |
