## 0. 计划管理约定（先读）

### 0.1 日单位规则

1. **每天必须有一个可验证产出**：代码提交、测试输出、报告或决策记录，四者至少其一。
2. **日终证据落盘**：`Harness/changes/<feature>/daily/Dnn.md`（当日做了什么、证据、未完成项、明日依赖）。
3. **不允许静默跨日**：当天未完成必须显式写入「未完成 + 顺延原因」，后续日次整体顺延；**不压缩验收步骤**。
4. **每天收工前**：`git status` 净树或明确 WIP 提交；定向测试可复跑；任务板更新完成/阻塞状态。
5. **日任务不跨阶段**：P1 的最后一天不夹带 P2 的代码；跨阶段准备工作只能是文档/取证。

### 0.2 分支 / PR / 合并 / 部署规则（沿用仓库现行）

- 每子阶段一个 worktree + 分支：`feat/semantic-release-a`、`feat/semantic-release-b`、`feat/semantic-registry-nl2sql`……
- 每子阶段一个 PR；合并判据 = **CI 失败集合对差净新增 0**（不追求全绿），`cancelled` 的 job 必须整轮重跑。
- 开关一律默认关闭；P0–P4 **不部署生产**（随常规发版）；P5 默认关闭、模拟器先行；P6 只在测试环境演练。
- 迁移一律手写（禁 autogenerate）、只用加法 DDL；每个迁移必须做 downgrade 往返验证。
- 合并后不部署；需要生产 DDL 的时机单独评审并展示精确 SQL。

## 15. 变更控制

1. 任一日次实际耗时超出 **1 天**，当天触发范围评审：**削范围，不削验收**。
2. 新需求一律进 backlog，不插入当前阶段；插入必须重排整张日表并重新过门禁。
3. 阶段间不并行修改同一文件族（`models.py` / `main.py`）以避免跨 PR 语义冲突；有交集时由后一个分支 rebase 并重跑对差。
