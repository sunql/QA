## API 契约

| 端点 | 行为 |
|---|---|
| `GET /api/v1/semantic/releases` | `?status` / `?domainCode` / `?globalOnly` / `?limit(1~200，默认 50)` / `?offset(0~1e6)`；`rows` 只含汇总列（**不含 1MB `manifest`**），`total` 是全量不受 limit 影响 |
| `GET /api/v1/semantic/releases/active` | `?domainCode`；**未发布返回 200 + null**（正常状态，不是 404/500） |
| `GET /api/v1/semantic/releases/{releaseId}` | `1 ~ 2^63-1`；返回完整快照；不存在 404 |

域三态：不传 = 全部；`globalOnly=true` = 只筛 `domain_code IS NULL`；`domainCode=X` = 该域；
两者同时传 ⇒ 422 领域错误（`{"error": ...}`，不是 FastAPI 的 `{"detail": [...]}`）。

## 设计要点

1. **开关关闭 = 整组不注册**（不是 403）：未启用的子系统不该有可探测的端点。生产与测试 app 两处装配同构。
2. **admin 门禁**：只读的是数据，不是治理信息 —— 草稿/归档、`created_by`/`note` 属于治理元数据，非 admin 一律 403。
3. **装配漂移的结构性盲区**：API 集成测全走 `_testapp.py`；若从 `main.py` 删掉 `requireAdmin`，
   集成套件仍全绿。新增 `test_semantic_release_route_auth.py` 直接构建**生产 app**：
   路由集合恰好 3 条（集合相等，空集必然不等）+ 每条路由依赖链同时声明 `requireAdmin` 与 `getCurrentUser`。
4. **stub 鉴权下的启动期告警**：`ENABLE_SEMANTIC_RELEASE=true` 但 `AUTH_MODE=stub`（或放行 stub 头）时，
   `X-User-Roles: admin` 可被任意客户端伪造 ⇒ 启动日志 `logger.error` 醒目告警。
   不选择 fail-closed：测试夹具与本地开发都依赖 stub 鉴权，这是仓库级既有设计，不在本特性内翻。
5. **列表域编码与 `/active` 同一套校验**：曾漏校验，`?domainCode=`（空串）静默返回空集、超长值直接进 SQL 绑定，
   同一参数在两条路径上契约不一致 —— 已补 `_validateListDomainCode`。
6. **`_noStore`**：治理快照与 `created_by`/`note` 不进浏览器/代理缓存（三条路由统一 `Cache-Control: no-store`）。
7. **快照读取纵深防御**：`_toSnapshot` 对「无法规范化序列化」（孤立代理项/NaN）与体量超 `MAX_MANIFEST_BYTES`（4MB）
   都归类为 `SemanticReleaseIntegrityError`（fail-closed），不让坏数据漏成未分类 500。
8. **bigint 上界前置拦截**：`releaseId` 超过 `2^63-1` 时若交给 asyncpg 会抛整型越界（500），
   `Path(le=MAX_RELEASE_ID)` + 服务层双保险变成 422。
